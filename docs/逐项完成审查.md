表中带「网页实测」字样的步骤**可以照原样复现**：网页验收入口会把夹具的 36 条视频渲染进真实网格（2026-09-26 在 headless Chrome 里量得 1280×800 下挂载 20 张卡片、5 行，其余在滚动窗口外）。#23 记的「库查询一直停在 pending」当前不再出现，但**恢复原因没有追溯**，因此这个入口要当作会坏的东西用：打开后列表若是空的、停在「正在读取视频库…」，那就是老毛病回来了，此时它又不能作为验证手段。`docs/验收截图/` 中 2026-09-11 的截图早于此后几轮界面调整，`网页固定导航.png` 里的导航扫描状态已随导航简化移除，该截图只作为当时的证据。


## 最终验证与复现

- 前端 128 项测试全部通过（2026-09-26 重跑，23 个测试文件），源码约束、翻译检查、TypeScript 检查和生产构建通过。此前记录在案的 8 项失败（详情抽屉焦点、语言同步与设置保存，由 #25 跟踪）已随 #25 修复，对应用例仍在 `VideoDetails.test.tsx`、`languageSync.test.ts`、`LanguageSetting.test.tsx` 中。
- Rust 83 项测试中 82 项通过、1 项忽略（含真实 FFmpeg/FFprobe 集成用例与 macOS 专属的系统打开失败用例），Clippy 和格式检查通过；计数以 2026-09-26 在 Windows 上重跑为准。空间功能新增的用例在 `repository/migration_tests.rs`、`repository/space_management_tests.rs`、`repository/space_isolation_tests.rs`、`scan/control.rs`。
- `frontend/acceptance/web-acceptance.html` 为独立网页验收入口，使用 Tauri 官方模拟通信及 36 条测试数据，不接触用户数据库，不进入生产构建入口。该入口会把那 36 条视频渲染进真实网格（2026-09-26 量得 1280×800 下挂载 20 张卡片、5 行），因此既能做框架与文案走查，也能承载依赖真实数据的界面验收；它走桩通信、不接后端，验的仍不是 Rust 行为。启动方式见开发指南。
- 2026-09-11 网页截图：`网页筛选排序.png`、`网页固定导航.png`、`网页预览生成中.png`、`网页英文窄窗口.png`、`网页英文设置窄窗口.png`、`网页打开失败.png`、`网页详情预览状态.png`，均位于 `docs/验收截图/`。
- 网页打开失败来自注入的业务错误；实际系统错误映射由 `player::tests::system_open_failure_returns_localizable_error` 验证，失败不记次数由仓储回归测试验证。网页模拟不宣称验证了播放器、原生菜单或文件系统。

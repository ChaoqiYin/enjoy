# Enjoy 本地视频统一启动器：开发基线

项目名称：**Enjoy**

## 1. 产品定位

Enjoy 是一个类似游戏启动器的本地视频库客户端：扫描用户指定目录，统一展示视频，支持搜索、分类和快速启动播放，减少在不同目录间切换文件的操作。

首期定位为“视频启动器”，重点是快速发现和打开视频；后续可扩展为本地媒体中心。

## 2. 首期功能范围

- 添加一个或多个视频目录
- 扫描常见格式：MP4、MKV、AVI、MOV、WEBM 等
- 读取文件名、路径、时长、分辨率、编码等元数据
- 生成视频缩略图
- 卡片网格展示视频，所有页面均不提供列表视图及切换按钮
- 搜索、目录筛选、最近播放排序
- 单击卡片打开详情；播放由卡片与详情中的独立播放按钮触发，调用系统默认播放器打开文件
- 记录成功发起打开操作的历史、次数和时间，不记录播放进度
- 右键打开所在目录、移除索引
- 用户手动重新扫描，发现新增或删除的视频
- 手动刷新和重新生成缩略图
- 显示语言切换：跟随系统、简体中文、英文

## 3. 总体架构

```text
React 界面
  ↓ Tauri invoke / events
Tauri Rust 后端
  ├── 目录扫描器
  ├── 元数据提取器
  ├── 缩略图生成器
  ├── SQLite 数据库
  └── 系统默认播放器调用
```

不部署独立 HTTP server。Rust 后端直接嵌入 Tauri 客户端，通过 Command 和事件与 React 通信。

开发时 Tauri 通过 `devUrl` 加载 `http://127.0.0.1:5173`，启动脚本自动启动或复用本项目的 Vite 服务，浏览器与桌面窗口可同时访问。打包时通过 `frontendDist` 加载内置的 `frontend/dist` 页面，不依赖开发服务器。

### 工程目录

- `frontend/`：完整的网页界面目录，包含 `index.html`、`src/`、`public/`、前端构建与测试配置，以及 `acceptance/` 下的网页验收入口和夹具。生产构建输出到 `frontend/dist/`。
- `src-tauri/`：独立的桌面原生工程，包含 Rust 源码、窗口配置、权限、应用图标及打包配置；桌面窗口承载网页界面，Rust 提供本地系统能力。
- 根目录：保留共享的 npm 依赖与锁文件、统一开发命令、仓库检查脚本、文档和持续集成配置。所有 npm 开发与验证命令仍从根目录运行。

前端内部按职责组织：`src/app/` 负责应用框架、全局导航、路由配置及跨组件测试，`src/pages/` 存放独立路由页面，`src/features/library/` 集中视频库组件和状态逻辑，`src/i18n/` 管理语言初始化、同步和设置界面，`src/shared/` 放置通信接口、通用组件及格式化函数。入口与全局样式保留在 `src/`，单元测试紧邻所属模块。

Rust 将扫描归入 `src/scan/`，媒体处理归入 `src/media/`，数据库访问归入 `src/repository/`，语言及原生提示归入 `src/i18n/`。各模块测试放入所属目录，通用错误、数据模型和独立系统适配文件保留在源码根目录。

`shared/locales/` 存放双方使用的翻译资源，避免原生工程依赖前端源码目录。`assets/brand/` 存放品牌原图及图标制作源图；网页公开资源仅保留运行时需要的文件，制作素材不进入前端构建产物。根目录的 `scripts/` 只放开发服务、仓库检查及资源生成脚本。

前端通过 Tauri 命令和事件调用原生能力；Rust 原生提示在编译时读取 `shared/locales/` 中的共享翻译资源。

## 4. 技术选型

### 前端

- React + TypeScript
- Vite
- Tailwind CSS + daisyUI
- Zustand：客户端状态管理
- TanStack Query：异步任务和扫描状态
- React Router：视频库、收藏、最近播放、设置页面
- Lucide React：图标
- i18next + react-i18next：界面翻译和语言切换

### Rust 后端

- Tauri 2.x
- Tokio：异步任务
- Walkdir：递归遍历目录
- SQLx 或 rusqlite：SQLite 访问（优先 SQLx）
- Serde：数据序列化
- Tracing：日志
- Tauri 设置存储插件（`tauri-plugin-store`）：持久化语言偏好
- `std::process::Command`：调用 FFmpeg、FFprobe 和系统默认打开命令

### 外部媒体工具

- 随应用分发 LGPL 构建的 FFmpeg 和 FFprobe
- FFprobe 用于读取视频元数据
- FFmpeg 用于截取视频帧并生成缩略图

## 6. UI 约定

daisyUI 基于 Tailwind CSS，作为主要组件样式来源。主题使用 daisyUI 内置的 `light` 与 `dark` 两套；页面静态默认深色，启动时按保存的偏好或系统主题改写，设置页可切换亮色、暗色或跟随系统。

```html
<html data-theme="dark">
```

品牌资源使用 `assets/brand/enjoy-logo.png`（黑字版）与 `assets/brand/enjoy-logo-light.png`（亮字版）。页面导航在浅色主题使用黑字版、暗色主题使用亮字版；展示资源裁去透明留白及右下角生成标记，原图保留。桌面应用图标由黑字版配浅色圆角底生成，使用固定图标，不随页面主题切换。

主要页面结构：

```text
应用框架
├── 全局顶部：品牌标志、视频库、收藏、最近播放、设置导航
└── 页面内容：页面标题、当前页面操作、扫描进度、视频网格、空状态
```

窗口保留系统标题栏和窗口控制按钮，不显示应用原生菜单栏；启动时禁用框架默认菜单，读取或切换语言时不创建菜单。

`App` 只组合应用级数据提供者、全局顶部 `AppNavigation` 和 React Router 路由。`/`、`/favorites`、`/history`、`/settings` 分别渲染 `LibraryPage`、`FavoritesPage`、`HistoryPage`、`SettingsPage`；未知路径重定向至视频库。各页面拥有自己的内容组合，不在 `App` 中通过路径条件拼装页面。

视频库、收藏和最近播放分别在页面中使用 `LibraryHeader`，承载标题、操作插槽及搜索、目录筛选、排序控件。组件通过参数和回调接收状态，不直接依赖路由或调用后端。各页面明确提供标题、操作入口与空状态文案，复用 `useVideoPageView` 和 `VideoPageContent` 管理筛选、数量、虚拟网格及视频操作；视频数量保持在滚动区外。设置页独立组合语言、主题和目录管理。

`LibraryProvider` 在应用级仅调用一次 `useLibrary`，提供共享扫描、错误及查询状态，避免页面切换重复订阅。各页面通过 `PageFrame` 复用内容布局和扫描反馈。所有通知经公共 `Toast` 在右上角浮动展示，采用 daisyUI 原生 alert 的类型化配色并由通知宿主堆叠，不占用页面内容高度；设置及启动失败同样遵循此规则。宿主按位置注册，通知用右上角、短提示用顶部居中，同一位置共用一个容器。完成统计在 3 秒后自动关闭，悬停或键盘聚焦时暂停并显示随剩余时间收缩的通知底边细线，统计含失败项时转为常驻；统计含「目录当前不可访问」时不改变停留时长。非错误通知全局只保留最新一条，错误通知豁免于该互斥并继续堆叠。视频详情复制路径的结果与通知分处两地：成功是短提示——顶部水平居中、宽度随内容收缩、1 秒后自行消失、静默不向读屏播报、吞掉落在它矩形内的点击——它不是通知，不进入上述互斥，可与通知同时在屏；失败与其余错误一样是右上角常驻的错误通知。写入剪贴板的是详情里显示的那条路径，不是索引中保存的原样字符串。决策背景见[短提示决策](adr/0005-点击反馈改用短提示.md)。保留本地化错误说明、可用的排查编号、重试和关闭操作；对话框打开时通知仍须可见可操作。决策背景见[通知决策](adr/0002-通知的类型配色与停留共存策略.md)。搜索与目录筛选状态继续共享，排序按页面保存；页面卸载时释放选中项、右键菜单及弹窗状态。

按钮统一采用 daisyUI 语义颜色样式，默认使用 `btn btn-outline` 配合语义颜色，视频库与设置页的目录管理按钮统一使用 `btn btn-md btn-primary btn-soft`，主操作使用主色、危险操作使用错误色，顶部导航采用 daisyUI 的 `tabs tabs-border` 与 `tab`，当前路由使用 `tab-active text-primary`，保留链接及当前页语义；具体映射遵循开发指南。目录管理操作采用图标加文字按钮，中文按钮文案不超过 5 个字，仅在视频库和设置页出现。视频库标题区域提供“添加目录”和“重新扫描”；设置页在“视频目录”区域集中提供“添加目录”“重新扫描”和“重建缩略图”。视频库空状态的添加入口统一使用“添加目录”。收藏、最近播放及其空状态不提供目录管理入口，内容通过已有数据变更通知自动同步。“重新扫描”扫描全部视频目录，“重建缩略图”重新生成所有视频的缩略图，两处目录管理按钮均采用 `btn-md` 和 18 像素图标，不提供悬停提示，样式由 `DirectoryActions` 统一维护。窄屏下页面操作自动换行。

窗口使用固定视口高度，全局导航、页面标题、筛选工具栏和视频数量保持固定，仅下方视频内容区域滚动；设置页内容独立滚动。视频内容、空状态及设置页统一使用 `ScrollViewport`，在实际滚动容器设置 `scrollbar-gutter: stable`。该属性不为覆盖式滚动条占位，因此额外保留 20 像素的尾侧安全区域，并通过 `ResizeObserver` 测量原生槽宽后扣减补偿间距，避免重复占位。原生槽超过 20 像素时尊重系统槽宽，不压缩系统滚动条。旧引擎使用 `overflow-y: scroll` 回退。虚拟网格按扣除内边距后的内容宽度分列。原理与来源参见[滚动条占位资料核对](滚动条占位-资料核对.md)。视频库、收藏和最近播放通过公共 `VideoCard` 展示单个视频：保留缩略图，卡片文字仅显示文件名和时长，内容区采用紧凑内边距；文件名以单行半粗体显示，超长省略并通过公共 `Tooltip` 展示完整名称，时长以较小、较弱颜色与操作图标同排，窄卡片允许换行；播放使用主色描边，其余操作使用对应语义色的描边按钮。底部播放、收藏、打开目录、移除索引使用 `btn-xs btn-square` 纯图标按钮，图标为 14 像素，按钮间距为 `gap-1.5`，并通过公共 daisyUI `Tooltip` 提供本地化悬停提示，保留无障碍名称；收藏图标区分选中状态，播放按钮只在有媒体任务运行时禁用。其他元数据在详情中查看。视频详情抽屉的关闭按钮采用与通知关闭按钮同形态的中性色描边 `btn-square` 叉号图标按钮，不显示文字标签，靠无障碍名称保留本地化提示，悬停反馈沿用 daisyUI 按钮的填充与过渡。抽屉的开关动画完全由公共 `Drawer` 用的 daisyUI 自带过渡提供，调用方只传 `open`：面板自右侧滑入滑出、遮罩同步淡入淡出，时长即 daisyUI 自身的滑动 0.3 秒与淡入 0.2 秒，遵循 `prefers-reduced-motion` 时降为瞬时。`Drawer` 的外壳常驻挂载、关闭时不卸载，`open` 只负责翻转 daisyUI 的开关，因此关闭态退出 Tab 顺序与无障碍树由 `inert` 承担，焦点在关闭开始时即归还触发元素，面板内容由调用方保留到下次打开为止。窗口保留 macOS 原生标题栏，webview 铺满窗口而网页内容自标题栏下方开始，标题栏会透出其下方 contentInset 区的内容，而该区只有根背景可见，因此详情抽屉打开时须让抽屉不参与会把 `:root` 背景压暗 40% 的 daisyUI `rootscrolllock`（在 `style.css` 置空对应的 `--page-scroll-lock`），否则标题栏会由白转灰。抽屉遮罩沿用 daisyUI 默认的 40% 黑色并覆盖整个内容区，它自内容区顶部起、触及不到该区，弹窗沿用 `.modal[open]` 等选择器亦不受影响。面板顶部与标题栏之间以内侧阴影分隔，此处不能用外投影：面板顶边与 `.drawer-side` 顶边重合，而该容器裁剪溢出，向上投出的阴影在到达标题栏之前就会被裁掉。`VirtualVideos` 负责虚拟网格组合，网格内容通过公共 `VirtualGrid` 渲染。网格列数与 20 像素行列间距集中配置：可用内容宽度达到 800 像素时每行 4 个，600、400 像素分别显示 3、2 个，更窄显示 1 个。通用 `useVirtualCollection` Hook 封装 `@tanstack/react-virtual`，统一返回可见行数据、偏移、占位及测量接口，不依赖视频领域或路由；页面数据读取、筛选、排序和重置标识由共享数据层及 `useVideoPageView` 提供。网格仅挂载可见行及前后各 3 行缓冲。网格按内容区宽度响应式分列并测量实际行高。切换页面、筛选或排序时重置内容滚动位置；滚动时关闭右键菜单。视频索引仍一次读取用于本地筛选与排序，此方案减少界面节点及缩略图挂载，不包含后端分页。

## 7. SQLite 数据模型

```sql
CREATE TABLE videos (
    id INTEGER PRIMARY KEY,
    path TEXT NOT NULL UNIQUE,
    file_name TEXT NOT NULL,
    folder_path TEXT NOT NULL,
    duration_ms INTEGER,
    width INTEGER,
    height INTEGER,
    file_size INTEGER,
    modified_at INTEGER,
    thumbnail_path TEXT,
    play_count INTEGER DEFAULT 0,
    last_played_at INTEGER,
    created_at INTEGER NOT NULL,
    updated_at INTEGER NOT NULL
);
```

可在搜索需求明确后增加 SQLite FTS5 全文索引。

`play_count` 和 `last_played_at` 分别表示成功发起系统打开操作的次数和最近时间，不代表实际观看次数或播放完成时间。已有数据库中的 `last_position_ms` 可保留兼容，但不再读写或用于界面展示。

## 8. 扫描与处理流程

### 增量扫描规则

一次扫描以当前保存的全部视频目录为范围，合并发现的视频形成扫描合集。视频按绝对路径与文件大小、修改时间判断身份：身份不变且媒体处理完成则保留已有记录和媒体信息并跳过处理；新增、身份变化或上次未完成时进入处理，身份不变的未完成项复用已成功写入的部分。发现阶段只读文件元数据，不打开文件、不读文件内容，因此大小或修改时间都没变而内容被换掉的替换不会被发现，该记录沿用旧的媒体信息，直到该路径上的文件下次发生大小或修改时间变化。

数据库中不属于扫描合集的视频记录直接删除，包括已消失的文件以及已移除目录中不再属于当前扫描合集的文件。例如当前目录是甲、乙，旧目录丙的视频记录不因曾经入库而继续保留。清理按目录分别判定，一条既有记录是否存活看它的路径上有没有文件：路径上已没有文件，或路径不在任何配置目录下，记录清除；路径上仍有文件但本次取不到它的元数据、或它所在的子树遍历不出（权限、设备错误等），记录连同收藏与播放历史原样保留，等下一次能读到的那次扫描归位；整条配置目录存在但列不出来时，该目录整个跳过、其记录同样保留。整条配置目录已不存在时，其记录按该目录下的文件都已消失清除。此处清理仅指数据库视频记录，不删除磁盘视频文件。

数据库版本为 4。版本 1 及更旧的数据库首次打开时在事务中清空视频、目录及关联表，不做兼容迁移；版本 2 起就地升级，只删除已无读者的列，不清空数据，索引、收藏、播放历史与已配置目录列表都保留。发现阶段取消时保留原库；单条目录读不到不再中断整次扫描，而是跳过该目录并计入「不可访问目录」计数。索引同步在事务内进行，提交前检测到取消或写入失败则回滚；提交后媒体处理失败或取消不撤销已提交的索引及清理结果。决策背景见[增量扫描决策](adr/0001-增量扫描复用已有媒体处理结果.md)、[扫描合集与过期记录清理决策](adr/0003-扫描合集的来源与过期记录的清理判据.md)与[文件身份判据决策](adr/0004-文件身份改用大小与修改时间.md)。

### 处理流程

1. 用户添加目录只保存目录配置；仅用户主动点击“重新扫描”才启动扫描。
2. Rust 后台任务递归遍历文件。
3. 依据扩展名筛选视频。
4. 遍历时每个目录项检查一次暂停与取消；完成发现后以事务同步基础索引和清理差集。
5. 跳过身份不变（文件大小与修改时间都没变）且已完成的视频；其余视频后台调用 FFprobe 补充缺少的媒体元数据。
6. 后台调用 FFmpeg 补充缺少的缩略图；元数据与缩略图均成功后保存处理完成状态。
7. 通过 Tauri 事件通知 React 更新进度。
8. 失败或取消的视频保持未完成，下次主动扫描继续补齐；文件大小或修改时间任一变化即视为身份变化，已有的媒体信息作废并重新处理。

扫描任务不得阻塞 Tauri 主线程；缩略图存放在应用数据目录，不写入资源目录。

扫描进度分别报告基础索引、元数据就绪和缩略图就绪数量。媒体就绪数量只累计成功处理或复用有效缓存的结果；整体已处理数量包含已尝试但失败的文件，失败次数另行显示。「不可访问目录」指整条配置目录仍然存在、本次却列不出内容（权限、设备错误等）的情形，单独计数并显示，不计入失败次数；遍历中取不到元数据的子目录或文件属于单个条目，计入失败次数，不进这一项。

批量扫描和缩略图重建遇到单个文件的媒体处理失败时，记录错误和失败次数并继续其余文件；用户取消或数据库写入失败时结束任务。单个视频的缩略图重建失败直接返回错误，供界面重试。

目录添加、应用启动和文件变化均不得自动触发扫描；扫描取消后不调度后台扫描。后端不启动目录监听器。用户需要主动重新扫描以更新视频索引。

## 9. FFmpeg 打包和许可证

资源目录约定（Windows x86_64 已接入；其他平台为后续布局）：

```text
resources/ffmpeg/
├── windows-x86_64/ffmpeg.exe
├── windows-x86_64/ffprobe.exe
├── windows-x86_64/LICENSE.txt
├── macos-aarch64/ffmpeg
├── macos-aarch64/ffprobe
├── macos-x86_64/ffmpeg
├── macos-x86_64/ffprobe
└── linux-x86_64/...
```

Windows 使用 `src-tauri/tauri.windows.conf.json` 将仓库 `resources/ffmpeg/windows-x86_64/` 映射到安装资源目录的同名路径，包含 FFmpeg、FFprobe 和 LGPL 许可证正文 `LICENSE.txt`。发布构建缺少上述文件时失败，当前仅支持 Windows x86_64。目录准备方式见[媒体工具说明](../resources/ffmpeg/windows-x86_64/README.md)。

媒体处理器显式持有工具目录及缩略图缓存路径，由应用层创建并传给扫描和缩略图重建流程。Windows 发布版从 Tauri `resource_dir()` 解析绝对路径，缺少资源时报告工具错误，不回退到 PATH。Windows 开发版优先使用仓库内的完整工具对，缺少时回退到 PATH；其他平台当前使用 PATH。开发和发布均通过子进程执行，不把 FFmpeg 库链接到 Rust 程序。

发布前确认构建配置未引入 GPL 组件，并保留版本、来源、版权声明及对应源码获取方式。macOS 后续接入发布资源时，将内置二进制纳入签名和公证流程。

## 10. 国际化与语言设置

### 10.1 语言选择与持久化

- 首期支持 `zh-CN` 和 `en`。设置页提供“跟随系统 / 简体中文 / English”，语言名称使用各自语言显示。
- 首次启动默认跟随系统：系统语言为中文时使用简体中文，其他语言暂时回退到英文。
- 使用 Tauri 设置存储插件保存 `system`、`zh-CN` 或 `en`。选择跟随系统时保存 `system`，不保存当时解析出的语言。
- Rust 在启动时读取偏好并解析实际语言，前端在显示主界面前获取该结果，避免语言闪切。读取失败或值无效时按跟随系统处理。
- 用户切换语言时同步更新持久化偏好、Rust 运行时语言和前端翻译状态，无需重启。若保存失败，按统一错误协议提示，避免静默丢失偏好。
- 跟随系统模式在启动及应用重新获得焦点时重新解析系统语言；手动选择语言不受系统变化影响。
- 切换语言仅更新文案与本地化格式，不重新扫描视频，也不清空搜索、筛选或打开历史。

### 10.2 翻译资源与界面格式

前端使用 `i18next` 和 `react-i18next`，按通用、视频库、播放历史、设置、错误提示和原生界面组织翻译资源。建议统一存放在 `locales/zh-CN/` 和 `locales/en/`，由前端和 Rust 构建过程按需读取同一份资源，避免重复维护。

使用稳定的语义键及完整句子，通过命名参数插值，不拼接词语。标题、按钮、空状态、扫描进度、错误提示均须翻译；文件名、路径及用户输入的分类名称保留原文。切换时同步更新页面语言标识。

日期、数字和相对时间统一使用 `Intl` 接口并传入当前语言。翻译资源随应用打包，不依赖网络。普通文案缺失时回退到英文；未知错误或错误翻译缺失时，优先显示当前语言的通用错误提示及排查编号，不直接显示翻译键。

### 10.3 Rust 错误协议

Rust 使用统一错误类型，在 Tauri 命令返回值和后台任务事件的出口转换为相同的结构化错误。返回稳定业务错误码、必要参数和排查编号，不将已翻译字符串作为错误协议。

例如，扫描时遇到一个读不出的视频文件返回：

```json
{
  "code": "media.scan.permission_denied",
  "params": {
    "path": "/Volumes/Movies/影片.mp4"
  },
  "errorId": "err_123"
}
```

前端根据错误码和当前语言生成提示，例如上例渲染为：无法访问“/Volumes/Movies/影片.mp4”，请检查访问权限。该文案对文件与目录都成立，因为它的生产者既可能是单个文件，也可能是子目录或整条配置目录。界面状态保留错误码与参数，在渲染时翻译，使仍在显示的错误随语言切换更新；异步扫描事件中的错误遵循相同规则。

将文件系统、数据库、FFmpeg 和系统打开调用错误映射为明确的业务错误码。优先依据错误类型、系统错误码和工具退出状态分类，不依赖匹配原始报错文本；无法可靠分类时使用通用业务错误。

原始错误、调用上下文、工具输出和错误链通过 Tracing 记录为英文诊断日志，并用 `errorId` 关联。第三方原始输出按原样保留。界面不直接展示底层堆栈或工具输出，参数仅包含生成用户提示所需的信息。

### 10.4 Rust 原生提示与语言同步

Rust 直接显示的原生通知及启动失败对话框也必须国际化。Rust 提供统一翻译入口，读取共享资源，采用与前端一致的语言标识、回退规则和命名参数插值约定。共享的原生提示模板使用双方均支持的简单插值语法，并验证渲染结果。

用户切换语言后，后台任务在生成新通知时读取当前语言，不沿用任务启动时的语言。系统已投递的通知不保证能够修改；仍在应用内显示的错误提示应立即更新。

前端尚未启动时，Rust 依据持久化偏好或系统语言显示错误。通用启动错误文案须随 Rust 二进制嵌入，确保设置或外部资源读取失败时仍有本地化提示。

### 10.5 验证要求

- 验证两种语言的翻译键、错误码覆盖和插值参数一致性，检查缺失翻译及未知错误的回退行为。
- 验证即时切换、重启后偏好保留、跟随系统及不支持语言的回退，并覆盖偏好读取和保存失败。
- 验证文件系统、数据库和外部媒体工具错误到业务错误码的映射，以及命令与事件错误结构一致。
- 验证已有错误随切换更新、后续后台通知使用新语言、前端启动前的错误提示，以及启动和切换语言后均不出现原生菜单栏。
- 检查英文长文案溢出、日期与数字格式，并确认切换语言不会重置业务状态或触发重新扫描。


## 11. 播放职责边界

Enjoy 仅负责将视频文件交给操作系统默认播放器打开。播放过程及相关能力不纳入本系统设计；播放器由用户在操作系统中设置，应用不提供播放器选择或配置。

- 点击播放按钮时，校验索引和文件可用性，通过系统默认打开接口提交文件路径。
- 系统打开调用成功后，更新打开历史、次数和时间；调用失败时显示本地化错误，不增加次数。调用成功仅代表已提交打开请求，不保证播放器已加载文件或用户已开始观看。
- 视频解码、渲染、音频、字幕、暂停、快进、播放进度、续播和播放完成状态均由系统默认播放器负责，Enjoy 不控制、监听或同步这些状态。
- 不集成内置播放器，不提供 mpv 等特定播放器适配，不建立播放器进程通信，也不安装或打包播放器依赖。
- 界面不提供进度播放、继续播放或播放控制入口；历史和最近播放排序以成功发起系统打开操作的记录为准。
- FFprobe 元数据读取和 FFmpeg 缩略图生成仍属于视频库管理功能，继续按扫描与处理流程实现。

本节取代此前的可选 mpv 进度接口方案。现有实现中与该方案相关的入口、进度读写和适配模块应按本节收敛；验收只覆盖系统打开调用及历史记录，不要求播放器内部行为或进度回传。

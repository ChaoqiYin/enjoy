# 0046 - 刮削任务的调度与结果回流

## 背景（Context）

第一个真实插件是「影片刮削」插件。刮削是异步网络请求，需要任务队列管理。现有插件框架已基本就绪（六个挂载点、WASM 运行体、`video.fields` 链式合并、`video.actions`、`scan.completed`、`plugin.settings` 往返、封面「插件给地址→内核下载」路径）。

本次设计需要回答三个关键问题：

1. 调度：宿主还是运行体？超时/取消怎么协作？
2. 结果回流：是 action 直接返回字段还是经 `video.fields` 链式问？
3. 自动刮削资格：如何判定「尚未刮削」（以什么标记、绑定什么身份）？

## 决策（Decision）

### 1. 宿主调度、任务细节由运行体决定

- **宿主维护任务队列**：宿主为每个插件维持串行队列，插件间并行。宿主全局同时进行的动作调用上限首版为 2。
- **运行体实现刮削细节**：单任务的解析、重试策略、如何选择站点等由 WASM 运行体决定；宿主只负责入队、出队、超时、取消、去重、并发控制。
- **复用 `video.actions`**：手动触发走 `video.actions`。动作类调用使用**单独的较长预算**（首版 120 秒），而不是默认 5 秒。`VideoActionsResult` 改为携带 `outcome: "done"|"failed"|"cancelled"` 和可选 `error`。
- **超时与取消**：宿主负责超时计时与取消；取消走中断（epoch trap）而不强加取消检查点，符合 ADR 0044 中「epoch/fuel 对阻塞在宿主调用里的 wasm 管不到」的盲区预期。WASM 可在重试循环内自行控制，但宿主保留最终裁决权。

理由：既能利用宿主的网络/计时/调度，又能让插件决定刮削逻辑；串行队列与全局上限避免过载。

### 2. 结果回流走 `video.fields` 链

- **任务 `done` 后再问 `video.fields`**：宿主不要求 action 直接返回字段。任务成功后，宿主**再次调用**该插件的 `video.fields`（带完整上下文与链参数），其返回值按现有「依次问、取第一个非空」规则合并，由内核写入 `video_fields` 表。
- **封面复用既有路径**：若插件在 `video.fields` 返回 `cover` 为 http(s) 地址，内核沿用 `cover::settle` 逻辑下载到 `$APPDATA/covers/` 并写入路径。
- **写库路径唯一**：所有插件向库写入的字段都只经 `video.fields` 派发入口（repository 层只有这一条写入路径），不新增第二条写入路径。

理由：保持「插件只返回数据由内核写」的一致性、复用链式合并与封面处理、减少契约改动面（action 只报状态）。

### 3. 自动刮削资格与 `scraper.scrapedAt` 标记

- **应用级开关**：扫描后自动刮削由**宿主/应用级**开关控制（默认关闭），不放入 `plugin.settings`。因为入队是宿主行为。
- **判定「尚未刮削」**：宿主在 `scan.completed` 通知时，对「媒体处理完成」的视频检查 `video_fields` 是否存在保留键 `scraper.scrapedAt`。若不存在，或其值中记录的**文件身份摘要**（基于 `path`、`size`、`mtime` 计算）与当前文件身份不符，则自动入队。
- **成功时写入标记**：任务成功并经 `video.fields` 写入结果后，宿主顺带向该视频写入 `scraper.scrapedAt`，其值应包含身份摘要与时间戳。标记**不进入白名单**，前端**隐藏**显示。
- **手动触发不受约束**：`video.actions` 手动刮削**不检查**该标记，允许用户强制重刮。
- **失败/取消不写标记**：任务未成功时不写入或更新 `scraper.scrapedAt`，因此下次满足条件仍可自动入队。

理由：标记需能随文件身份变化失效（文件换了、改名/重建等场景），且宿主能在不问插件的前提下做资格判定。手动触发保留用户控制权。

## 状态与约束

- **状态机**：`pending → running → completed | failed | cancelled`，FIFO，无内部重试计数（重试策略由运行体决定）。
- **去重**：同一视频在 `pending` 或 `running` 时拒绝再次入队；其余状态（completed/failed/cancelled）允许再次入队。
- **串行与并发**：每插件串行；插件间并行；宿主全局同时进行的 `video.actions` 调用上限首版 2，该计数器仅统计进行中的 `video.actions` 调用，不计入其他挂载点调用。
- **持久化**：首版**仅内存**。重启后，`pending` 与 `running` 丢弃；已成功写入的字段与标记不丢。自动入队会在下次 `scan.completed` 时重新补足；手动任务需用户重新触发。
- **字段表达**：多值字段（如 `actors`、`genre`）以 **JSON 字符串数组** 格式存入 `video_fields`，前端尝试 `JSON.parse`，失败回退单值。白名单外键统一以 `<插件id>.<键名>` 前缀化存储。

## 后果（Consequences）

- **契约改动**：需调整 `VideoActionsResult` 形状并同步 `shared/plugins/mount-points.json` 及其生成物（`mount_points.rs`、`mountPoints.ts`、`docs/插件挂载点目录.md`）。运行 `npm run generate:plugins` 校验一致性。
- **宿主新增责任**：任务队列、超时/取消、去重、自动入队资格判定、成功后写入 `scraper.scrapedAt`。这些都属于宿主调度边界，不侵入业务逻辑。
- **运行体最小化**：只需实现任务执行与重试策略，结果通过 `video.fields` 返回即可。
- **性能与简洁**：首版内存化是可逆的取舍，避免跨重启对账复杂度。


- **`scraper.scrapedAt` 值格式**：宿主写入时使用结构化 JSON 对象：`{"vid": video.id, "path": normPath, "size": video.size, "mtime": video.modified_at, "ts": now_unix_seconds}`，其中 `ts` 为 UTC 秒级 Unix 时间戳。`normPath` 采用统一正斜杠格式。
- **文件身份摘要算法**：判定文件身份是否变化时，直接比较 `normPath`、`size`、`mtime` 三个字段（即使用 `${size}:${mtime}:${normPath}` 形式的身份键），不额外做 sha256。

## 验收要点（非实现细节）

- 手动触发（`video.actions`）可强制重刮；自动仅在「尚未刮削」时入队。
- 文件身份变化后，自动刮削会重新入队并覆盖/补充字段。
- 任务超时或取消时，不写入新字段且不更新标记。
- 封面路径最终由内核落入 `$APPDATA/covers/` 并写入 `video_fields`。

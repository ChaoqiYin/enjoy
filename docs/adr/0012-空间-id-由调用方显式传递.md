# 空间 id 由调用方显式传递，后端不持有当前空间

每条需要空间作用域的命令都自己接收一个空间 id，后端不保存「当前是哪个空间」。当前空间是前端持有的状态，数据库里只留一列记着启动时该进哪个空间，供应用启动时喂给前端；空间随调用走，不随连接走。

## 为何显式传递，而不是让后端持有当前空间

后端持有是一条更省事的路：`AppState` 里放一个当前空间，`list_videos`、`add_directory`、`set_favorite` 等十来个既有命令的签名一个字都不用改，前端只在切换时调一次命令。它被否决的理由是空间会变成一层**在调用点不可见**的上下文——读 `set_favorite(path, true)` 这行代码看不出它在改哪个空间，测试也必须先记得设置一次当前空间才能断言。空间是这条功能里最要紧的一个限定条件，把它藏进隐式状态，等于让每一次数据读写的实际作用域都得靠回溯才能确定。

显式传递还有一个直接收益：任务启动时携带的空间就是它写入时的空间，中途切换不可能写错地方。隐式上下文下这两者可以不一致——一个任务在空间甲启动，运行时用户切到乙，写入那一刻读到的当前空间是乙。

## 一条被高估的否决理由，记在这里以免被当成当时的主因

否决隐式上下文时给过一条更重的理由：漏传空间 id 会**静默**跨空间串数据，类型系统与测试都拦不住。这条不成立，应当作废。Tauri 对缺失的必填参数是报错而不是取默认值，漏传会响亮地失败；而在查询键按空间作用域的前提下，一个迟到的响应会落进它自己那个空间对应的缓存条目里，读侧本来就不会串。

残余的风险只剩一种，且必须用纪律封住：调用点传了一个**格式合法但已经过期**的空间 id。读取会被作用域键接住（结果进的是旧空间那个桶，界面不看它），写入则会真的写进旧空间。封法是两条——所有 invoke 只经 `shared/api.ts` 一个出口；空间 id 在**调用发生的那一刻**从空间上下文读取，任何组件都不许传自己早先捕获的那个值。

## 「扫描期间禁止切换空间」的真实原因不是防竞态

显式传递消除了上面那类竞态之后，这条封锁就只剩产品理由：扫描进度事件与扫描状态查询是应用级的，没有空间限定，切到另一个空间后仍然会看到前一个空间的进度模态框；而按显式传递的设计，正在跑的任务绑定的是发起它的那个空间，进度事件天然正确，问题出在「用户此刻不在那个空间里」。锁的边界因此定为：扫描期间，改变当前空间是谁或其内容的操作全部按同一把闸门拒绝——切换、新建、重命名、删除，后端权威、前端禁用只是解释。连带把单文件「刷新信息」也算进锁内，尽管它的技术理由在显式传递之后已经消失；留着它是因为一把闸门只描述一件事，代价只是用户点刷新时选择器闪一下禁用。

这条必须写明，否则后来者会以为锁是为了防竞态，进而在某次「简化」里把它删掉。

## 扫描作用域的既有性质保持不动

`scan/job.rs` 刻意从仓储读目录列表、而不是从调用方接收，写明了理由是「没有调用方能扫一个子集，从而误删它没包含的目录」。空间化之后仓储改为按空间 id 读目录，这条性质原样保持——变的只是空间 id 的来源是调用方，目录列表的权威仍在后端。

## 实施状态

已实施，分四步落地：空间维度入库（`07c959e`）、空间的新建/重命名/删除（`3e971ce`）、切换空间（`2395c16`）、扫描期间封锁空间操作（`8a9bd2d`）。

`spaces.current` 是活值，不止是升级时写入一次的初值：新建空间会把它指过去，切换空间会改写它，删除空间时在同一个事务里把它改到另一个空间，不留给用户一个没有空间的瞬间。它记的是「下次启动该进哪个空间」，运行期的当前空间只活在前端的空间上下文里，后端一次都没有读过它来做作用域判定。

前端新增一层空间上下文，`LibraryProvider` 的查询键从裸键改为带空间 id 的作用域键（`['videos', spaceId]` 等），因此一个迟到的响应会落进它自己那个空间对应的缓存条目里。空间 id 在调用发生的那一刻从上下文读取，组件不传自己早先捕获的值。三个查询键都带空间 id，但空间切换时列表的搜索与目录筛选要显式清掉——筛选是照着内容说的，内容换了还留着它只会让人以为库是空的。

扫描期封锁落在 `scan/control.rs` 的 `space_change_gate`：扫描槽被占（`is_running()`，含暂停中与单文件「刷新信息」持有槽位时）就拒绝，四个空间命令共用一个包装函数，闸门因此不可能被某一条命令漏掉。单文件「刷新信息」占着同一个槽，因此它跑的期间空间操作同样被拒——这是这条取舍的已知代价，它的技术理由在显式传递之后已经消失，留着它是因为一把闸门只描述一件事。理由见[空间的产品范围与界面约定](../本地视频统一启动器-开发基线.md#6-ui-约定)。

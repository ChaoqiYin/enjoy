# 整个应用的背景用一层静态点阵

窗口背景原本只有一层纯色（根元素的 `bg-background`）。现在它上面还有一层点阵：`16px` 见方的格子里一个 2px 的点，铺满整窗，跟着主题换色，不动。

整件事由一条 CSS 规则完成，没有组件、没有 canvas、没有依赖。走过的路比结果长，这篇记的是为什么。

## 先试过两条 react-bits 的路，都不合适

**DotField**（Canvas 2D，302 行）。点铺满整窗，指针扫过时被推开再弹回。改写了 9 处才装进来（颜色改由令牌给、去掉跟随指针的柔光斑、静止时停帧、缓动按帧时长归一……）。装完发现两点：一是在近白底上**看不出来** —— 初值 8% 要放大五倍才分辨得出有一层点，用户选了 18%；二是它把「canvas 读不到 CSS 变量」这件事带进来了：`ctx.fillStyle` 既不认 `var()` 也不认 `color-mix()`，所以颜色令牌必须是**带 alpha 的成品色**，主题切换还得自己用 `MutationObserver` 去发现。为了一个底纹，代价是 393 行和一个常驻画布。

**GhostFibers**（WebGL2 全屏着色器，456 行，依赖 `ogl`）。用户点名换过去。它比 DotField 完备得多 —— 页面隐藏时停、滚出视口停、`prefers-reduced-motion` 下停、卸载时丢上下文，都是上游自带的。问题出在两处：一是**停不下来**，`uTime` 永远推进，所以它是一个常驻 GPU 的全屏逐像素着色器，只能靠降帧率减负；二是强度，同一套配色在暗色主题下是加法叠加（`backdrop + color`），实测整窗 **53% 的像素被改变、最大差 232**（亮色是 11.85%、最大差 42），在近黑底上直接烧成一片紫色光束。

两条路的共同点是：**为了「会动的背景」付出的东西，比这个位置需要的多得多**。这个位置在 24 张缩略图后面，它的职责是当一层有质感的表面。指针推挤也好、漂移的纤维也好，都是要盯着看才成立的效果，而这里没人盯着看。

## 于是改用纯 CSS

```css
.dot-grid {
  background-image: radial-gradient(
    circle,
    var(--dot-color) 1px,
    transparent 1.5px
  );
  background-size: 16px 16px;
}
```

挂在 `app/App.tsx` 根 div 的类名里，和 `bg-background` 并列 —— 一个画底、一个画点，都在内容之下。

**一处定义，两套主题。** 令牌是 `color-mix(in oklab, var(--foreground) 4%, transparent)`，只写在 `:root` 里。CSS 自定义属性在**使用点**求值而不是定义点，所以 `[data-theme='dark']` 下这一行自己就取到亮色的 foreground。不需要第二份令牌，也就不需要任何东西去发现主题变了 —— 那套 `MutationObserver` 随 canvas 一起没了。

**零常驻开销。** 点了才画，不点不画：没有 `requestAnimationFrame`，没有合成层刷新，窗口常开数小时也只是浏览器的一层背景。这条是前面两条路都做不到的 —— DotField 要自己实现停帧，GhostFibers 根本停不下来。

**不可能启动失败。** 没有 WebGL 就没有「WebGL 起不来怎么办」。DotField 要处理 `getContext('2d')` 返回 null，GhostFibers 要在 `new Renderer` 外面包 `try`（不然那个 throw 会打到应用最外层的 ErrorBoundary，把整窗换成错误页）—— 这些分支现在都不存在。

**代价是没有交互。** 点不会动。这是清楚的交换：拿掉的是这个位置本来就不需要的东西。

## 它推翻了什么

- **「窗口背景就是一层纯色」** 不再成立。
- **推翻本仓上一版决定。** 0022 这个号先前写的是一篇 DotField 的 ADR，已经实施、门禁全绿、真机实测过。用户看过之后判定不合适，于是有 GhostFibers；GhostFibers 也不行，于是有这篇。前两版实现连同它们的令牌、测试与文件头一并删掉了。
- **ADR 0007 反而被重新确认。** 那条决定是「不为了装饰请回 gsap」，理由是非 OSI 许可的盘点负担与第二个位移来源。中途 GhostFibers 换了个名目把依赖请了回来（`ogl`，MIT），效果上重蹈了同一类问题：为一个底纹引入一个引擎。最终方案**没有引入任何依赖**，`ogl` 已从 `package.json` 卸载。

## 后果

- **间距与浓度是一对，浓度被用户压着走了四档。** 第一次在 `20px` 的格子上定浓度：8% 在近白底上放大五倍才看得出来；18%（DotField 那一版选的值）在同一张截图里仍然几乎没有；40% 已经读得出是「花纹」而不是「表面」；32% 是明确在那儿、又不再多的一档。此后三次反馈，每次都是「还要更淡」：

  | 版本 | 亮色（底 `#faf8ff`） | 暗色（底 `#111317`） |
  |---|---|---|
  | `20px` / 32% | −76 | +71 |
  | `16px` / 20%（「密一点、淡一些」） | −47 | +45 |
  | `16px` / 12%（「还需要更淡」） | −29 | +27 |
  | **`16px` / 4%（「几乎看不见，但又隐隐约约」）** | **−10** | **+9** |

  表里是通道差：各取 60px 见方的空底，取极值像素与底色的差。**两个数咬得一直很紧**（末档 10 与 9），因为这是同一个令牌在两种底上取同一份 alpha —— 一个数就够，不用分主题标定。

  **第二档为什么必须连颜色一起降**：格子由 `20px` 收到 `16px`，覆盖率涨了 56%，只加密不降浓度只会更重。那一档单点比第一档轻得多，单位面积的墨量却几乎没动（估算 0.60 → 0.59）—— 同样的重量摊在更多、更轻的点上，这是一层「质地」和一地「斑点」的区别。

  **后两档只动浓度不动间距**：反馈都落在「点本身太实」而不是「排得太开」上，而这一层是「表面」，被看的是它上面的缩略图。

  **4% 是个目标值，不是偏好值。** 用户要的是「几乎看不见、但还隐隐约约」，在近白底上那就是一个离底色约 10/255 的点 —— 去看就在，不看就没有。再往下就不成其为一片「场」了：实测 3% 只剩一点点可疑的痕迹。
- **卡片必须自己遮住底下的东西。** 实测发现视频卡片的**信息区每张透着约 150 个点**（缩略图区 0 个，因为图片不透明）。原因不在点阵，在 `border-glow.tsx`：它把卡片的底色和边框渐变画在同一层、共享一个 `opacity`，而那个 opacity 是**给边框用**的 —— 边框越淡，底色越透。加一个不透明的 `bg-card` 打底（`VideoCard` 的根）同色叠加、颜色不变，实测 6 张卡片内部**变化 0 个像素**。
- **控件也必须自己遮住底下的东西。** 卡片之后轮到按钮与表单控件：`outline` 变体填的是 `bg-transparent`，`ghost` 连底色都没有，四处表单原语（`Input` / `Select` / `Checkbox` / `RadioGroup`）也都是 `bg-transparent`，而它们里有相当一部分直接站在点阵上（工具栏操作行、分页、表格视图的行、共享页），点就从它们中间透出来。改法是**只动变体定义，不动任何调用点**。取的是 `--background` 而不是 `--card`：点阵画在根元素自己的 `bg-background` 上，所以需要遮点的控件全都在页面上（卡片上本来就没有点），填 `--background` 的控件在页面上与四周**逐像素同色**——点消失，别的什么都不变；反过来填 `--card` 会把同样大小的差挪到页面上，而页面正是看得见问题的地方。代价是控件落在卡片上时它与 `--card` 差 2~6 级，也就是这两个令牌在全仓其它地方本来就有的那点差。

  逐像素实测（分页里那颗站在裸页面上的 `outline` 按钮，亮暗各一遍）：页面空带极差 **10 / 9**，把按钮底色强制改回 `transparent` 后同一块**变化 10 / 9**（各 38 个像素）—— 也就是说这层底色遮住的正是整幅点阵。

  **仍有四处透。** 三处半透明水洗：`VideoRow` 的 `hover:bg-muted/40`、`table.tsx` 的 `hover:bg-muted/50`、`ShareStatusPill` 的 `bg-muted/50` —— 前两处在悬停时**替换**掉自己那层不透明底色，所以悬停的瞬间反而透点；改法要先把今天的观感在 `color-mix` 里配成不透明色，没跟这一批走。第四处是**禁用态**：`disabled:opacity-50` 是整元素的透明度，会把刚加上的底色一起打薄，实测禁用按钮的变化是 **5（亮）/ 4（暗）**，恰好是页面点阵的一半。要彻底遮住，禁用态就不能用整元素透明度表达，得改成一组不透明的禁用色——那是一次看得见的观感改动，本轮没做。
- **页头仍然透。** `AppHeader` 是 `bg-background/90` + 背景模糊，点会透上来一点，被糊开。这是位置决定的，不是缺陷，但读数时要知道整窗只有 0.38% 的像素被这层影响 —— 点阵的可见范围就是卡片缝、空白带和页头。
- **`.dot-grid` 与 `--dot-color` 都不触发 `check-tokens.mjs`。** 那份脚本扫的是 `className` 属性值和 daisyUI 的类名，不管自定义类与自定义属性。
- **`NOTICE` 里 react-bits 的条目只剩一条。** 两个 vendored 背景组件都删了，现在只有 `border-glow.tsx` 还来自 react-bits。

## 实施状态

**已实施。**

- `frontend/src/style.css` —— 新增 `--dot-color`（只有 `:root` 一份）与 `.dot-grid` 规则。
- `frontend/src/app/App.tsx` —— 根 div 加 `dot-grid`。上一版为负 z 的图层加的 `relative isolate` 一并去掉：点阵是它自己的背景，没有东西要压。
- `frontend/src/features/library/VideoCard.tsx` —— 根加 `bg-card`（见上）。
- `frontend/src/shared/ui/button.tsx` —— `outline` / `ghost` 各加 `bg-background`（`link` 仍不填，它不画形状）。
- `frontend/src/shared/ui/input.tsx`、`select.tsx`、`checkbox.tsx`、`radio-group.tsx` —— `bg-transparent` → `bg-background`。
- `package.json` / `package-lock.json` —— `ogl` 已卸载。

门禁：`npm run check` 通过，`npm test` 82 文件 457 用例全绿，`npm run build` 通过。真实浏览器里量过：两套主题的令牌解析、点阵渲染、卡片遮挡（前后逐像素做差）、第一次标定的四档浓度对比，第二次标定的「间距 × 浓度」六格矩阵，以及此后三轮「两套主题 × 多档浓度」的阶梯（各格另做逐带极值像素测量，即上文那张表）。最后一轮还比过一个「软点」变体（渐变的峰值在圆心、向外散开到 2px），同样对比度下它摊在 4.5% 的面积上而不是 1.5%，读起来更像一层雾而不是一排点；没有采用，因为它要动的是渐变而不只是数字，而这一层要的只是「淡」。

**尚缺**：视频卡片 BorderGlow 那一篇（`0021`）仍未撰写，`border-glow.tsx` 的文件头已经引用了它，而这篇恰好动过它的一个后果。本篇不代它。

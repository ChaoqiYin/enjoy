# 悬停只改背景，选中优先

亮色模式下报了两个缺陷，实测证明是**同一个根因**：

> 我发现几个问题，亮色模式时，1。鼠标悬浮时会导致比如网格视图的图标颜色被修改为黑色，鼠标悬浮应该只影响背景色 2。设置页菜单已选菜单在鼠标悬浮时会被覆盖颜色，已选的背景色应该是优先级最高的才对 能不能从架构上设计统一这些规范

问了他三个问题，答：反馈方式＝**给只有文字的控件补一道背景水洗**（而不是把文字色提起来）、令牌＝**收口成 `--hover`**（`--accent` 退场）、防回归＝**加检查脚本 + ADR**。

## 一、为什么

### 根因是一条自定义变体，不是两处写错

`style.css` 顶部那条 `@custom-variant hover` 为了排除禁用控件，内联了三个 `:not()`：

```css
&:hover:not(:disabled):not([aria-disabled='true']):not([data-disabled])
```

`:not()` 的特异度取它参数里最高的那个，一个 `:disabled` 或 `[aria-disabled]` 就是一分。三个连写，于是**每一个** `hover:` utility 从 (0,2,0) 编译成 **(0,5,0)**，压过全站所有状态变体——`data-[…]` 通常只有 (0,2,0)。从构建产物里直接读到：

```
.hover\:bg-sidebar-accent:hover:not(:disabled):not([aria-disabled=true]):not([data-disabled])   ← (0,5,0)
.data-\[active\=true\]\:bg-selection[data-active=true]                                          ← (0,2,0)
```

两个症状是同一条规则的两张脸：悬停的**前景**压过了「选中」的语义（图标被涂黑），悬停的**背景**也压过了它（红底被灰底顶掉）。

值得注意的是这条变体**不是错在「排除了禁用控件」**——[ADR 0033](0033-禁用态取禁止符.md) 拆掉 `pointer-events-none` 之后，禁用控件确实需要在悬停里排除，否则高亮会一起复活。错在排除的写法顺手把特异度抬了上去。

### 为什么只在亮色显形

暗色主题下这些 token 恰好两两同值：`--hover` = `--secondary` = `--selection` = `#2a2d33`，`--foreground` = `--accent-foreground` = `--selection-foreground` = `#edeef2`。覆盖发生了，但覆盖上去的是同一个颜色。

亮色（[ADR 0029](0029-亮色改用用户指定的中性灰底与字段色.md) / [0032](0032-亮色下被选中的一块改用主色.md) / [0034](0034-亮色下悬停水洗改用中性灰.md) 之后）它们分道扬镳：`--hover` 中性灰 `#e5e5e5`、`--selection` 品牌红 `#e11d48`、`--selection-foreground` 白、`--foreground` 近黑 `#0f172a`。缺陷这才露出来。

**这条要记住**：那两个症状不是「亮色的问题」，是「亮色把它显出来了」。同样的类名在暗色下一直错着，只是错得看不见。

## 二、规范（四条）

- **R1 落点只改背景。** `hover:` 与 `focus:` / `focus-visible:` 只允许改 `background-color`；禁止 `text-` / `fill-` / `stroke-` / `caret-` / `decoration-` / `placeholder-`。指针说「这个够得着」，不该顺手复议一遍字色。
- **R2 选中优先是结构性的。** 带「当前/选中」底的元素，其悬停水洗只在**未选中**时生效，用反向状态门控（`data-[state=off]:hover:` / `data-[active=false]:hover:`）。**不靠特异度，也不靠产物顺序**——那两样都会在下一次 Tailwind 改排序或下一次谁"优化"选择器时翻掉。
- **R3 白名单（悬停可以改的非颜色）**：`outline-*`（卡片悬停描边）、`opacity-*`、`animate-*` / `transform` / `underline`。都不是「改颜色」，不在这条规则的射程里。
- **R4 一种水洗，而且只给没有别的答复的控件。** 控件与菜单项取 `--hover`，整行取 `--hover-soft`。**已经有悬停语言的控件不补**——页头导航项答指针的方式是逐字抬起落下（[ADR 0027](0027-页头导航项悬停时的逐字抬起落下.md)），本轮给它加的水洗量出来是 49 像素的直角块、站满页头高度，读起来像第二个选中态，**因此撤掉**（见 §三、§四）。

实现口径：**门控一律用元素已有的状态属性**（Radix 的 `data-state`、本仓 `Sidebar` 的 `data-active`），不新造 `@custom-variant`。一个变体没法知道「选中」在各控件上是哪个属性，只会静默漏掉第四种控件。

## 三、改了什么

### 根因：排除逻辑进 `:where()`

```diff
-    &:hover:not(:disabled):not([aria-disabled='true']):not([data-disabled]) {
+    &:hover:where(:not(:disabled):not([aria-disabled='true']):not([data-disabled])) {
```

`:where()` 是零特异度的容器：排除逻辑照旧，特异度回到 (0,2,0)，与 `data-[…]` 同级。编译产物：

```
.data-\[active\=false\]\:hover\:bg-sidebar-accent[data-active=false]:hover:where(:not(:disabled):not([aria-disabled=true]):not([data-disabled]))
.data-\[state\=off\]\:hover\:bg-hover[data-state=off]:hover:where(…)
```

同级之后 **hover 仍是 (0,2,0) > 基础 utility (0,1,0)**，所以 `ghost` / `outline` 的悬停不受影响；而状态与悬停同级时，Tailwind 把 `data-[…]` 规则排在 `hover:` 之后，状态赢。

`:where()` 是这一轮唯一**非局部**的改动：它一次修好两个症状，也是唯一不能靠改类名替代的一处。`:where()` 里那句注释就是为下一轮写的——它是最像"冗余"、最容易被顺手删掉的一行。

### 悬停/聚焦改前景的类名，全仓 11 处

`--accent-foreground` 与 `--sidebar-accent-foreground` 在明暗两套主题下**恰好等于各落点自己的静息色或继承色**，所以其中 8 处改前改后同色，是空操作：

| 落点 | 类名 | 为什么是空操作 |
|---|---|---|
| `button.tsx` outline / ghost | `hover:text-accent-foreground` | 两处静息色本就是 `--foreground`，而 `--accent-foreground` = `--foreground` |
| `select.tsx` 选项 | `focus:text-accent-foreground` | 同上 |
| `dropdown-menu.tsx` 菜单项 ×2 | `focus:text-foreground` | 静息继承的就是 `--popover-foreground`，两者同值 |
| `sidebar.tsx` 行 ×2 | `hover:text-sidebar-accent-foreground` | `--sidebar-accent-foreground` = `--accent-foreground` = `--sidebar-foreground` |
| `sidebar.tsx` 徽标 | `peer-hover/menu-button:text-sidebar-accent-foreground` | 徽标静息就是 `--sidebar-foreground`；且 `peer-hover` 直用 `:hover`，既不享受 `:where()` 修复也不享受禁用排除 |

这 8 处**直接删**。

真正肉眼可见的 3 处，静息是 `--muted-foreground`、悬停被提到 `--foreground`：

| 落点 | 原来 | 现在 |
|---|---|---|
| `shared/ui/toggle-group.tsx` 未选中段 | `hover:text-foreground` | `data-[state=off]:hover:bg-hover`（选中段另有 `data-[state=on]:bg-selection`，两者互斥） |
| `shared/ui/dialog.tsx` 关闭按钮 | `hover:bg-hover hover:text-foreground` | `hover:bg-hover`（水洗本来就有，只去掉提字色） |
| `shared/ui/tabs.tsx` | `hover:text-foreground` | **什么都不加**（R4：这一条的唯一调用方是页头导航，它有逐字抬起落下的动效） |

### 症状 2 的落点：`sidebar.tsx`

`:93`（`sidebarMenuButtonVariants`）与 `:200`（`SidebarMenuSubButton`）是同一串类名：

```diff
- hover:bg-sidebar-accent hover:text-sidebar-accent-foreground focus-visible:ring-2
- active:bg-sidebar-accent active:text-sidebar-accent-foreground
+ data-[active=false]:hover:bg-sidebar-accent focus-visible:ring-2
+ data-[active=false]:active:bg-sidebar-accent
```

`active:`（按下态）与 `data-[active=true]:bg-selection` 同特异度，今天也只靠顺序，一并门控。`:144`（`SidebarMenuBadge`）删掉 `peer-hover/menu-button:text-sidebar-accent-foreground`，保留 `peer-data-[active=true]/menu-button:text-selection-foreground`——徽标跟着当前行走是对的，跟着指针走是错的。

### 令牌收口：`--accent` 退场

悬停背景统一走 `--hover`，5 处 `bg-accent` 改名：`button.tsx` 的 outline / ghost、`select.tsx` 的 `focus:bg-hover`、`SpaceSwitcher.tsx`、`VideoMetaTable.tsx`（`hover:bg-hover/40`，斜杠照旧）。

`--accent` 的消费者到这一步一个不剩，于是把槽删掉：`style.css` 的 `@theme inline` 两条映射、`:root` 与 `[data-theme='dark']` 各两条声明、`check-tokens.mjs` 名单里的 `accent`。`--sidebar-accent-foreground` 改指 `var(--foreground)`（它原先指向刚被删的 `--accent-foreground`）。`rubber-segment.tsx` 的默认 props 由 `--accent` / `--accent-foreground` 改为 `--selection` / `--selection-foreground`——那是「被选中」的语义，也是唯一调用方 `ThemeSetting` 显式传的那一对，所以渲染不变。

## 四、实测

真 Chrome（`--headless=new`，155）、真鼠标（CDP `Input.dispatchMouseEvent`）、1440×900、验收夹具。**先确认前提**：`matchMedia('(hover: hover)').matches` 为 `true`，否则这条 hover 变体根本不参与命中，量出来的「没变化」会是假的。

**亮色**（页面 `rgb(245,245,245)`）：

| 落点 | 挂的类 | 静止 | 悬停 |
|---|---|---|---|
| 视图模式 选中段 | `data-[state=on]:bg-selection` | 底 `rgb(225,29,72)`／字 `rgb(255,255,255)` | **同前，一个字没变** |
| 视图模式 未选中段 | `data-[state=off]:hover:bg-hover` | 透明／字 `rgb(100,116,139)` | 底 `rgb(229,229,229)`，**字仍 `rgb(100,116,139)`** |
| 设置页左列 当前行 | `data-[active=true]:bg-selection` | 底 `rgb(225,29,72)`／字 `rgb(255,255,255)` | **同前** |
| 设置页左列 其余行 | `data-[active=false]:hover:bg-sidebar-accent` | 透明／字 `rgb(15,23,42)` | 底 `rgb(229,229,229)`，字仍 `rgb(15,23,42)` |
| 行上的计数徽标 | 无悬停类 | `rgb(15,23,42)` | `rgb(15,23,42)`（行被指针压住时） |
| 页头导航项 | 无（R4） | 透明／字 `rgb(100,116,139)` | 透明／字 `rgb(100,116,139)` |

**暗色**（页面 `rgb(17,19,23)`）同构，且每一处与改动前的渲染值逐字相同：

| 落点 | 静止 | 悬停 |
|---|---|---|
| 视图模式 选中段 | 底 `rgb(42,45,51)`／字 `rgb(237,238,242)` | **同前** |
| 视图模式 未选中段 | 透明／字 `rgb(154,160,170)` | 底 `rgb(42,45,51)`，字不变 |
| 设置页左列 当前行 | 底 `rgb(42,45,51)`／字 `rgb(237,238,242)` | **同前** |
| 设置页左列 其余行 | 透明／字 `rgb(237,238,242)` | 底 `rgb(42,45,51)`，字不变 |

**页头那块水洗的读数**（决定撤掉它的依据）：`95×49` 像素，`border-radius` 为 `0px`，悬停底色 `rgb(229,229,229)`。页头本身 `h-14`（49 像素），所以它是一块**直角、站满高度、顶到页头上下边**的灰矩形——与全站 `rounded-md` / `rounded-lg` 的语言不符，与它旁边 Library 那条 2 像素红底条并排时还把红条切断。撤掉之后复量：静止与悬停同为透明／`rgb(100,116,139)`。

## 五、代价

1. **暗色那 5 处水洗会变。** `bg-accent → bg-hover` 之后，暗色下它们从 `#1a1e26`（文档的 `surface-elevated`）变成 `#2a2d33`（`--hover`）。亮色**无变化**（亮色 `--accent` 本就是 `var(--hover)`，ADR 0034 定的）。这是把「暗色原本两档悬停灰」合成一档的必然结果，方向与 ADR 0034 对亮色做的事一致，但它确实动了暗色的手感，需要一次暗色的逐点视觉确认。
2. **偏离 shadcn 上游。** 删掉的 `hover:text-accent-foreground`、`focus:text-foreground` 上游都有，下一次手工 vendor 会把它们带回来。**靠门禁拦**，不靠记性。
3. **三处「次要色在悬停时升为主色」的提示消失了。** toggle-group 未选中段与对话框关闭按钮由水洗补上；页头导航项**什么都没有补**，它的悬停从此只有逐字抬起落下。
4. **页头导航项成了 R4 的例外。** 一个"不补水洗"的落点，与「统一规范」的直觉相反，所以写进 ADR 与开发指南，免得下一轮被"统一"掉。
5. **`--accent` 与 `--accent-foreground` 从此没有引用者**（`rubber-segment` 的默认 props 已改指 `--selection`）。
6. **`style.css` 的 500 行硬上限。** 删掉四条 token 声明与两条映射，加了三行注释（`:where()` 那条），净减，交出 499 行。
7. **门禁只认字面量。** `check-tokens.mjs` 的新扫描读的是 `className` 里的字符串；由变量拼出来的类名它跟不到。今天没有这样的落点，这是门禁的边界，不是它的承诺。

## 它推翻了什么

- **「页头导航项悬停时只有颜色变化（`hover:text-foreground`）……颜色变化照旧」**（[ADR 0027](0027-页头导航项悬停时的逐字抬起落下.md)、[界面通用组件清单](../界面通用组件清单.md) §7 那一行、[开发指南](../开发指南.md) 按钮样式一节的顶部导航一条）——「颜色变化照旧」这半句被推翻。页头项的悬停从此只有逐字抬起落下：既不改字色，也不填底。**逐字抬起落下那半句没有被推翻**，它照旧是那个入口答指针的方式，这也是它不需要水洗的理由。
- **shadcn 上游「悬停把次要色提为主色」的惯例**（`hover:text-accent-foreground` 一族）——全仓 11 处一并清掉。上游这样写是因为它的 `--accent-foreground` 与静息色**不同值**；本仓的恰好相同，8 处是空操作，另外 3 处的水洗比提字色更贴 R1。
- **`--accent` 槽本身**（ADR 0034：「`--accent` 是例外：亮色下它只服务水洗，值已改为 `var(--hover)`」）——收口之后它是多余的，整个删掉，`bg-accent` 这个名字在全仓消失。

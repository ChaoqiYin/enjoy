# 关窗的决定在后端，界面只回答「确认」

开着共享时点窗口关闭按钮，要先问一句「正在共享，确定关闭吗」——这个行为本身没变。这一篇记的是**谁来决定**它，以及由此删掉的那些东西。它取代 [ADR 0014](0014-关窗由销毁承担而侦听只在服务运行时挂着.md)：那一篇记的两条平台陷阱（挂着侦听器就关不掉、确认之后必须用销毁）都是真的，但它们是「把决定放在界面层」的产物——决定挪走之后，那两条陷阱连同绕开它们的办法一起从代码里消失了。

## 起因：一个行为的知识散在六处

0.2.0 点关闭没反应，0.2.1 修了一半（共享退了、窗口留着），0.2.2 才真的关得掉。连着两次栽在同一件事上，原因是这个行为要**六个地方同时正确**：界面什么时候订阅窗口的关闭事件、要不要拦下、确认之后谁来关窗、能力文件授了什么、检查表里写的是哪一项、以及为什么必须用「销毁」而不是「关闭」。六处里只有权限那一处有检查；其余靠注释和一条测试守。用户看到的现象前后两次都是「点了没反应」，底下的原因却是六处里的两处不同的地方。

## 决定挪到后端

判断只有一句话：**有没有在共享**。这句话的答案在后端（`ShareControl`），界面要靠一次往返才知道，而它却要为这句话的正确性负责——订阅时机、拦截、销毁、权限，四样都是它的。

现在是：

```rust
// main.rs
.on_window_event(|window, event| {
    if let tauri::WindowEvent::CloseRequested { api, .. } = event {
        let Some(state) = window.try_state::<app::AppState>() else { return };
        let events = events::AppEvents(window.app_handle().clone());
        closing::handle(&state.share, &events, || api.prevent_close());
    }
})
```

`closing::handle` 就是那一句话：

```rust
pub(crate) fn handle(share: &ShareControl, events: &impl Events, hold: impl FnOnce()) -> Answer {
    if !share.running() {
        return Answer::Proceed;
    }
    hold();
    events.close_requested();
    Answer::Ask
}
```

- **没有服务在跑**：放行，什么都不说。窗口走它自己的原生路径，不过 JS、不需要权限、不打扰用户。
- **有服务在跑**：拦下这一次关闭，并**用和其它后端消息一样的方式**告诉界面「有人要关窗」。界面弹出确认框，用户回答之后调一条命令。

`commands::window::close_window` 是那条命令：先结束共享服务，再销毁窗口。**一条命令而不是两条**（先 `close_share` 再关窗），因为用户答的是一个问题，而两次调用会把「窗口关不关得掉」押在「服务结不结束」上；服务结束之后进程本来也会释放端口，但让正在看片的设备拿到一个干净的结束而不是连接不再应答，是这条命令先做那一步的理由。销毁失败会作为 `app.close.failed` 回到界面（原来的写法是 `void`，失败无人知晓）。

`closing::handle` 的两个参数都是传进来的而不是就地伸手去拿：`hold` 只有拿到窗口的调用方（`main.rs`）能给，`events` 是后端对界面的那条既有接缝。这正是它可测的原因——规则一行，而它要作用的两样东西恰好是测试造不出来的那两样。

## 界面这侧少了什么

- 不再订阅窗口的关闭事件（原来 `ShareProvider` 挂载时订阅、按 `asking` 决定挂不挂）。现在是订阅后端的 `close-requested`，一条普通消息，挂多久都无所谓——它不拦任何东西。
- 不再调 `destroy()`，`shared/api.ts` 的 `windowApi` 只剩一个 `close()`（发 `close_window`）。**`core:window:allow-destroy` 从能力文件里删掉**：界面不再碰自己的窗口，也就不需要任何关于窗口的授权。`check-permissions.mjs` 的 `@tauri-apps/api/window` 表项保留，作为「将来有人伸手去碰时该要什么」的事实，而不是作为现在的用途。
- 「登录未订阅/订阅了关不掉」这条不变量消失，`ShareProvider.test.tsx` 里守它的两条用例随之消失，换成「后端问了才问用户」「答是的走 `close_window`」「答否窗口留着、下次再问」「关不掉要说出来」。

## 代价与不变量

- **只有真窗口能验**：`closing::handle` 的规则、事件、命令、权限都在本机验完了（Rust 197 项、前端 204 项、`npm run check`），但「点一下确实关掉了」这一句仍然只能由人在真窗口里点一次——本机不能注入合成点击（鼠标被远程会话夺走）。0.2.2 的验证也是这么做的。
- 窗口被拦下之后的下一次关闭会重新问 （没有「已问过」的态）；用户取消之后服务继续跑，要关就再点一次。
- 以后再有关窗相关的规则，加在 `closing` 里：它现在是一个文件，而不是六处。

# 亮色改用用户指定的中性灰底与字段色

用户给了一张别的应用（Orca）的浅色界面截图，要求：

> 亮色的效果参考这个截图里的搜索输入框配色，另外亮色的背景色也改为这个截图里的背景色

两句话指两个 token：**背景**（`--background`）与**搜索框配色**（`--field`，上一轮 ADR 0028 刚加的）。这一轮的分量不在改动量——两个十六进制值——而在于它是**设计文档的亮色底第一次被推翻**。此前 `--background`、`--card`、`--primary`、`--destructive`、`--ring` 五个槽由 `check-tokens.mjs` 逐字对着 `prototype-drawing/vermilion_studio/DESIGN.md` 断言，谁都不许动。现在其中一个动了，那条断言的期望值也跟着改了，并在这里记下为什么。

## 一、从截图里量到的值

截图是 279×898 的 PNG，直接在像素上量的（不是目测）：

| 取处 | 值 |
|---|---|
| 整幅背景（八处取样，含 x=20 / x=150 / x=260 三列） | `#f5f5f5` |
| 搜索框填充（y=44 到 y=76、避开图标与 ⌘J 徽标的干净区） | `#ebebeb` |
| 搜索框描边 | **没有**——从 `#f5f5f5` 直接跳到 `#ebebeb`，一个像素的过渡带都没有 |

两个值的间距是 **10 级**（245 → 235）。

## 二、改了什么

| token | 改前 | 改后 |
|---|---|---|
| 亮色 `--background` | `#faf8ff`（`vermilion_studio` 的 `background`） | **`#f5f5f5`** |
| 亮色 `--field` | `#f1f5f9`（`surface-dim`） | **`#ebebeb`** |

**只改这两个。** 亮色的其余槽一个没动：`--card` 仍是 `#fcfcfd`、`--muted` 仍是 `#fff1f2`、`--accent` 仍是 `#ffe4e6`、`--secondary` 仍是 `#fecdd3`、`--border` / `--input` 仍是那对蓝灰。也就是说，这一轮换掉的是**页面底与字段**，不是整套亮色调色板。

**搜索框保留描边。** 截图里那个框没有描边，但用户这一句说的是「配色」——上一轮 ADR 0028 里「浅填充 + 保留细边」是用户在三个选项里点着选的，本轮没有推翻它的理由。`border-input` 照旧；真要连描边一起去掉，是把 `--field` 那五处调用点上的 `border-input` 也覆盖掉，一行的事。

**`check-tokens.mjs` 的期望值跟着改**，并加了注释说明这一条偏离的来源。断言本身没有被删掉：这个检查是拿来抓 token 悄悄漂移的，不是拿来保证文档永远赢的——值仍是这个文件的，就该仍有人钉着它。

## 三、连带关系实测（无头 Chrome + CDP，1280 视口，亮色）

底色一换，所有「站在页面画布上」的表面都要重新看一遍。逐条量过：

| 关系 | 读数 | 差 | 结论 |
|---|---|---|---|
| 后端没有数据，页面为空 | 页底 `rgb(245,245,245)` | — | 就是 `#f5f5f5` |
| 工具栏控件对页面 | `rgb(235,235,235)` | **10** | 与截图的 10 级一致 |
| 设置卡 / 左栏面板对页面 | `rgb(252,252,253)`（`--card`） | **+7（更亮）** | 卡片仍从页面上浮起 |
| 设置页栏内控件对卡片 | `rgb(245,245,245)`（`--background`） | **−7（更暗）** | 「卡片上凹下去的控件」这层关系保住 |
| 页头（`bg-background/90` + blur）对主区 | `oklab(0.970 …)` | ≈ 0 | 与改前一样，靠 `border-b` 分隔 |

**点阵不用动，而且是量过才敢这么说。** `--dot-color` 是 `color-mix(in oklab, var(--foreground) 4%, transparent)`，底色换掉之后落点必须重测：取 200×200 的空底统计极值像素，实测跨度 **10 级**（`#f5f5f5` → `#ebebec`），与 ADR 0022 里那一档记的 **−10** 逐级相同。4% 这个 alpha 是用户压着走了四档才定下来的值，本轮**不动它**，也不必分主题重新标定——理由和 0022 里写的一样：一个数在两个底上给出同一个距离。

## 四、代价

**亮色的粉色调不再有底色替它铺路。** 亮色调色板是带粉的——`--muted` `#fff1f2`、`--accent` `#ffe4e6`、`--secondary` `#fecdd3`——它们原先压在一层微紫白的底（`#faf8ff`）上，彼此是一路的；现在底变成中性灰，这几个粉与新底之间**没有色相关系**，粉会更跳。设置页那条主题分段条的滑块（`--secondary`）是立刻能看出来的一处。这不一定是坏事（红是主色，粉是它的淡档），但它是一个**本轮没有处理的变化**，如实记在这里。

**`--background` 的语义从此与设计文档脱钩。** `check-tokens.mjs` 里五槽对文档的断言变成四槽加一个例外，`界面通用组件清单.md` §2.1 的映射表里那一行也加了注。将来谁再对着 `vermilion_studio/DESIGN.md` 核亮色，都要先读到这条。

**工具栏那一处的 10 级差是照抄截图的，不是为这个界面算的。** 截图里那两个面是另一个应用的排版，它的字号、行高、留白都与这里不同；同一个色差在别处不一定给出同样的分离度。本轮选择照抄而不是重算，因为用户点的就是这个观感。

## 它推翻了什么

- **亮色 `background` = `#faf8ff`**（`prototype-drawing/vermilion_studio/DESIGN.md` 的 `background` 槽）——推翻，记进 `界面通用组件清单.md` §7。**原型不回溯改稿。**
- **亮色 `--field` = `#f1f5f9`**（ADR 0028 刚定的 `surface-dim`）——同一个 ADR 里的值，随本轮一起更新。

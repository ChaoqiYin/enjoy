# 页头导航项悬停时的流光

> **已被 [ADR 0027](0027-页头导航项悬停时的逐字抬起落下.md) 取代。** 这道光带被用户否掉，页头导航项的悬停改为「逐字抬起落下」。本篇正文一字不改，保留它当时的依据与读数。

用户要求：

> 给tabs上的菜单文字在鼠标聚焦时添加上reactbits的Shiny Text效果

指针停在页头某个入口上时，一道光带扫过它的两个字。三个岔口问过之后照答复执行：**取 react-bits 重写之前的经典纯 CSS 版**（不移植上游现在那个 412 行的 rAF 引擎）、**悬停期间循环流光**（移开即停，不是「进入时只扫一次」）、**不开 Issue 直接改并用本篇记录**。

那三个选择各自都留了后果，下面逐条记：不抄文件意味着**不进 `NOTICE`、不写许可头**（本仓的界限是许可而不是「抄了多少」，ADR 0023 §二末）；「悬停期间循环」意味着它是一条 `infinite` 动画而不是一次性的进入动效；「直接改」意味着没有工单可指，决定只在这份文件里。

## 一、为什么取经典 CSS 版而不是上游引擎

react-bits 在 2026 年把 `ShinyText` 重写成了一台 rAF 引擎：canvas 逐个像素读颜色、指针位置参与、glow 层、`IntersectionObserver` 开关，412 行。它解决的是「底色未知、要按实际画出来的像素取色」这类问题——**页头这条导航没有这个问题**，它的底色是 `currentColor`，也就是入口自己已经声明过的文字色。

重写前那条做法只剩一句：一条渐变、`background-clip: text` 把渐变裁进字形、`@keyframes` 推着 `background-position` 走。零 JavaScript，也正是这次落地的形状。

因此**没有 vendored 文件**：`style.css` 里一条规则加一个 `@theme` 块，`NOTICE` 一行没动，文件里也没有许可头。上游那条实现本身只是 `background-clip: text` 加一条渐变，且已不在上游仓库里；这里点名致意而不搬运。

## 二、改了什么

**`frontend/src/style.css`** —— 三处：

| 位置 | 内容 |
|---|---|
| `@theme` | `--animate-nav-shine: nav-shine 1.6s linear infinite`，同一块里的 `@keyframes nav-shine` 两端为 `100%` 与 `0%` |
| `:root` | `--nav-shine-color: var(--primary)` |
| 文件末尾 | `@media (hover: hover) { .group:hover .nav-shine { … } }`，含渐变、`background-size: 250% 100%`、`background-clip: text`、透明填充 |

**`frontend/src/app/MainNav.tsx`** —— `NavLink` 的 `className` 加 `group`，`{label}` 包进一层 `<span>`，类名由组件里本来就有的 `useReducedMotion()` 门控。

**`frontend/src/app/AppHeader.test.tsx`** —— 一条新断言：五个入口各有一层 `.nav-shine`，其 `textContent` 等于入口名字，且悬停变体挂上了。jsdom 不跑动画，这里钉的是**工具类挂没挂上**，光带在不在走是真实浏览器那一半。

**整条规则挂在悬停里面，而不是「挂上但把光带停在盒外」。** 这是三次实测逼出来的一条：`background-clip: text` 加透明填充是**另一种文字绘制路径**（字形当遮罩、填充透明），与纯色填充不同——实测同样的字，静息态墨量比不带这层时**少 12%**，每条笔画边缘都更细。光带停在盒外并不改变这一点。所以不悬停时规则整个不生效，而不是「效果没在动」；这条不变性由 `@media (hover: hover)` 与 Tailwind 给 `group-hover:` 的那层守卫一起保证，两半同时开关，也不响应「来了就离不开」的触屏。

**颜色必须是 token。** 它要随主题变——浅色底上文字悬停近黑、深色底上近白，没有一种颜色能两边都显眼——而主题是 `[data-theme]` 切的、React 看不到（ADR 0018），所以「按主题不同」只能落在 CSS。取名对着 `--primary`，暗色块自己重声明它，于是光带跟着主题走而这里只写一行，同 `--dot-color` 的办法。

**基色取 `currentColor`。** 入口已经说过自己的字是什么颜色（`text-muted-foreground`、`hover:text-foreground`、原语的 `transition-colors`），从元素上取色的渐变把这些全部继承下来，一条规则就够了。

## 三、那条渐变的方向——这次真正的坑

**规则里写的是 `linear-gradient(currentColor 40%, var(--nav-shine-color) 50%, currentColor 60%)`，没有方向。** 缺省是 `to bottom`，也就是一条**竖**渐变；而竖渐变在**每一列都相同**。动画推的是 `background-position-x`，横着挪一张横向均匀的图——**一个像素都不会变**。

实测把它抓得很干净：光带占 **3 行、29 列**，一条横贯文字的红条，六帧截图逐字节相同；而 `getAnimations()` 说动画在跑（`currentTime` 500→1100 ms，计算值 68.76%→31.26%）。一个在动、一个没变，两者都是真的。

这一步曾经把排查带偏很远：所有行内探针里我都手打了 `90deg`，所以**探针会动、规则不会**，于是读数被解释成「这些无头环境里百分比位置不生效」。直到把规则原样写成行内仍然不动、而独立页面同一套声明会动，才回头去读 `getComputedStyle().backgroundImage` 里那串没有方向的值。

补上 `90deg` 之后入口自己的标签立刻扫起来（帧间峰值 209、变动像素 460、光带峰值列 12→9→18→30→38→47，左进右出）。**这条方向不是装饰性的默认值，它是这个效果能不能被看见的开关。** 前三次「看不见」的尝试都栽在同一个地方：光带本身没画错，只是它一直没有横着走过。

## 四、实测（无头 Chrome + CDP 驱动真实页面，1280 视口，dpr 1，真实鼠标事件）

文字盒 49 × 17.5 CSS 像素（14 像素字号的两个字），截图为该盒加 3 像素余量。

| | 浅色主题 | 深色主题 |
|---|---|---|
| 光带取 `--primary`（两套主题各是 `#e11d48` / `#ff334b`） | 帧间峰值 **209**、变动像素 460 | 帧间峰值 **186**、变动像素 452 |
| 光带取 `#ffffff` | 峰值 239，但方向是**把字抹掉**（白带扫过近黑的字，白底上等于擦除） | 峰值 **18**、变动像素 271——近白的字配白带，等于没画 |

- **静息态逐像素恒定**：不悬停的字与「根本没有这一层」比较，浅色与深色都是**最大差 0**（>2 的像素 0）。
- **引擎自己在走**：`getAnimations()` 报 `nav-shine`、`state: running`，`currentTime` 500→1100 ms，计算值 68.76%→31.26%，无需外部推动。
- **光带确实在走**：把关键帧走到的八个相位逐个拍照，光带峰值列 12→9→18→30→38→47（左进右出），首末同相（第八相位与第零相位）之差 **0**。
- **减动效**：`prefers-reduced-motion: reduce` 下**五个入口里 0 个带 `nav-shine`**，悬停着的那个 `animationName=none`、`backgroundClip=border-box`、`backgroundImage=none`；撤掉偏好即恢复 5/5。
- 门禁：`npm run check` 全过（`style.css` 489 行，500 行上限内），`npm test` **82 文件 472 用例**全绿，`npm run build` 通过。

相位取样有个装置上的前提值得记下：`Page.captureScreenshot` 返回的是**最后呈现的那一帧**，只有动画在跑的页面按需截不到新帧（十六张连拍可以逐字节相同），所以相位是「停掉动画、直接把关键帧那条属性写到该相位」取的，动没动则另由 `getAnimations()` 的时钟单独证明。

## 五、三个取值与它们的代价

| 岔口 | 选项 | 用户选择 | 依据 |
|---|---|---|---|
| 光带颜色 | 主色红 / 白 / 同色系更亮一档 | **主色红** | 白在两套主题上都不成立（上表），而主色在两处都清楚；再亮一档只是浓淡之差 |
| 一趟多久 | 1.2s / 1.6s / 2.4s | **1.6s** | 指针停住期间约每 1.6 秒一趟，扫过时才看得出是一条光带 |
| 往哪边走 | 左→右 / 右→左 | **左→右** | 顺阅读方向；关键帧两端随之对调（`from 100%` → `to 0%`），规则里的起始位置也跟着改成 `100% 0`，与扫掠的起点一致 |

**代价如实记：打开系统「减少动态效果」的用户永远看不到这道光带，一次也看不到。** 组件在减动效时不加任何类，入口退回今天的纯色文字——连 `background-clip` 都不挂。这是 ADR 0008 给装饰定下的规矩（装饰在减动效下**不出现**，而不是「静止地出现」），这里照办；换来的是那条 12% 的墨量差只在有人真的在看的时候才存在。

**第二处代价**：光带每 1.6 秒重来一次，只要指针停在上面就一直烧；`infinite` 动画在窗口不可见时由浏览器自己节流，本仓没有额外处理。

## 它推翻了什么

一条成文的约定，已记进 `界面通用组件清单.md` §7：

**页头导航项悬停时只有颜色变化**（`开发指南.md` 按钮样式一节的顶部导航一条）——改为悬停时另有一道光带扫过文字，颜色变化照旧。`界面原型.md` 与 `开发基线.md` **不回溯改稿**，偏离只记在这里（同 ADR 0024 的既例）。

`NOTICE` 与 `shared/ui/tabs.tsx` 都没动：没有抄 react-bits 的文件，而流光属于调用点——原语不为一处调用长出一条规则。**若出现第二个调用点**再提升为 `shared/ui/shiny-text.tsx`，这是它现在的去处。

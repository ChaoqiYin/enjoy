# 按完整目录合集增量同步视频库

现有扫描会清空视频记录再重新索引，导致已有视频重复探测和生成缩略图。已确认改为以当前保存的全部目录形成扫描合集，按绝对路径与 MD5 比较文件身份；身份不变且处理完成时保留记录及媒体信息并跳过处理，新增、身份变化或处理未完成时进入处理。

数据库中不属于扫描合集的视频记录直接删除，不保留不可用占位。例如当前保存目录为甲、乙，则同时扫描两者；旧目录丙中且不属于甲、乙扫描结果的视频记录应清理。这里的删除对象是数据库中的视频记录，不是磁盘上的视频文件，也不以旧视频记录反向恢复已移除的目录配置。

## 取舍与影响

- 采用“路径与 MD5”的组合身份，不对不同路径下内容相同的视频进行内容去重。
- 直接删除过期记录会同时丢失其收藏和播放历史；这符合清理扫描结果之外记录的要求。
- MD5 判定需要读取文件内容。仅比较大小和修改时间并不能保证内容未变化，不能默认为等价规则。
- 处理完成状态按文件身份持久化，只有元数据与缩略图均成功才标记完成。取消、失败或退出后，下次用户主动扫描补齐未完成部分，并复用已成功写入的结果。
- MD5 采用固定大小缓冲区逐块计算，每块之间检查暂停和取消。
- 完整发现文件后，以事务同步索引与删除差集；提交前检测到取消或写入失败则回滚。提交后取消不撤销已同步索引和删除结果，保留媒体阶段的已完成工作。

## 实施状态

规则已确认并实现。数据库版本为 4：版本 1 及更旧按约定清空视频、目录和关联表，不做兼容迁移；版本 2 就地升级，不再清空任何数据，索引、收藏、播放历史与已配置目录列表都保留（迁移与落地情况见 [ADR 0003](0003-扫描合集的来源与过期记录的清理判据.md) 的实施状态，版本 3 之后的升级见 [ADR 0004](0004-文件身份改用大小与修改时间.md) 的实施状态）。设计基线见[扫描与处理流程](../本地视频统一启动器-开发基线.md#8-扫描与处理流程)。

其中「目录无法完整读取时保留原库，不执行差集清理」一条已由 [ADR 0003](0003-扫描合集的来源与过期记录的清理判据.md) 修订为只跳过出问题的目录，其余目录照常清理；整条配置目录不存在时，其记录按「其中的视频都已消失」清理。

其中「MD5 判定需要读取文件内容。仅比较大小和修改时间并不能保证内容未变化，不能默认为等价规则」一条已由 [ADR 0004](0004-文件身份改用大小与修改时间.md) 修订为改由文件大小与修改时间判定身份，判据不再读取文件内容。

# 抽屉的开关动画，与抽出的通用 `Drawer`

视频详情抽屉原本没有开关动画，且关闭时组件立即卸载。本 ADR 记录为什么动画需要一个库而不是几条 CSS 过渡、为什么抽屉的挂载模型必须改成受控、以及为什么这些逻辑抽成了一个通用组件而不是留在详情组件里。

## 为何退场动画改动了挂载模型

原实现是 `{detailVideo && <VideoDetails … />}`：点关闭即 `setDetailsId(null)`，组件随即卸载。**卸载之后没有任何一刻可以播动画**——元素已经不在文档里了。所以退场动画的前提不是「加一段 CSS」，而是让面板比「请求关闭」活得更久。

选定的模型是把开关拆成两件事：`open` 表示用户的意图（驱动动画），`detailVideo` 表示面板还有内容可画（驱动挂载）。关闭时先 `open=false` 播动画，动画跑完才由 `onClosed` 释放 `detailVideo`。代价是调用方多持有一个状态、组件多一个回调，换来的是退场有时间可用。

被否决的是「保留条件渲染 + 用 `setTimeout(300)` 猜时长再卸载」：它把动画时长抄成第二份真值，改一处忘一处就会出现裁掉尾巴或白等一帧；而且它无法知道动画是否被中断。也否决了只做入场动画——用户要的是开关两侧。

## 为何用 GSAP，而不是 CSS 过渡或 `@keyframes`

仓库此前的立场是「声明给引擎画，不要每帧从 React 写样式」（见 `Toast` 的倒计时细线，开发指南亦有记录）。引入一个命令式动画库看似与它冲突，但两者解决的并不是同一个问题：那条立场的反面是**每个计时器 tick 触发一次 React 渲染**，而 GSAP 在自己的 rAF 里批量写 `transform`，同样交给合成器，不经过 React 的渲染循环。抽屉的动画只有开关两帧状态，不存在逐帧重渲染的问题。

真正需要库的地方是**编排**：连续快速开关时，新的补间要接管旧的补间（`overwrite: 'auto'`），让面板从当前位置继续走而不是跳回去；退场要在完成回调里通知调用方卸载；还要按 `prefers-reduced-motion` 决定时长。这些都能用 CSS 的 `transitionend` 加状态机硬写，但那是在应用层重新实现一个补间引擎的调度部分。

## 为何抽成 `Drawer`，而不是写在详情组件里

抽屉的外壳不是视频详情的业务内容：daisyUI 的 `drawer` 结构、遮罩、滑动与淡入、Esc、焦点进入与归还、关闭期间的 `inert`、`role="dialog"` 语义——这些对任何「从右侧拉出的面板」都成立，与里面放的是视频元数据还是别的东西无关。

第一版曾把这些直接写在 `VideoDetails` 里。那样第二个抽屉出现时，要么复制一遍动画与无障碍处理，要么把详情组件当成模板改。因此抽出 `frontend/src/shared/Drawer.tsx`，接 `open`/`title`/`closeLabel`/`onClose`/`onClosed` 与 `children`；`VideoDetails` 退回成只提供标题和内容。

`gsap.registerPlugin(useGSAP)` 是**全局注册**，只做一次，因此放在 `frontend/src/main.tsx`（验收页面的入口 `web-acceptance.ts` 复用同一个 `main`），不放组件里——放在组件里会让人以为注册是那个组件的要求，也容易在第二个组件里再写一遍。

## 无障碍上的取舍

- **`prefers-reduced-motion` 首次真正实现。** 仓库此前只在一处注释里提到它，且结论是**不要**用它关掉通知的倒计时细线——那条线表达剩余时间，不是入场装饰。抽屉的滑动与淡入属于装饰，信息不依赖它，因此按该偏好把时长降为 0。这与既有立场一致而非冲突。
- **关闭期间用 `inert`。** 面板在动画期间仍在文档里，`inert` 让它同时退出 Tab 顺序与无障碍树，直到真正卸载。`inert` 也意味着此后按 `role` 查询不到该抽屉——这是有意的，测试据此改用 DOM 查询验证卸载。
- **焦点在关闭开始时就归还**，不等动画结束。原实现依赖卸载时的 cleanup 归还焦点，现在卸载被推迟了 300ms，若沿用原路径键盘会在一个正在淡出的对话框上停留整整一个动画的时长。

## 取舍与影响

- **GSAP 不是 OSI 认可的开源许可。** 它在 Webflow 收购后对所有用途免费（含商用），但走的是 GreenSock 自己的 "No Charge" 许可，与仓库的 MIT 不同，也与 `docs/FFmpeg-LGPL下载-资料核对.md` 所关注的 LGPL 类别不同。记录在此以便日后做许可证盘点时有据可查。
- **jsdom 不绘制动画。** 测试能验证「入场动画结束时不会误报关闭」「关闭动画结束后才回调 `onClosed`」，但**看不到**滑动本身。真实观感仍须在桌面端人工确认——与通知倒计时细线同一分工。
- **关闭后到卸载前，面板仍在 DOM 中。** 依赖「关闭即消失」的断言需要改为等待卸载。生产代码里这段时间由 `inert` 兜住。
- **`Drawer` 目前只有一个调用点。** 与 `Hint` 同理，抽出的依据是「这类面板的职责边界」而不是调用点数量；第二个抽屉出现时应当直接复用它。

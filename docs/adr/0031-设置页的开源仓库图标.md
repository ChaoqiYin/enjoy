# 设置页的开源仓库图标

用户要求：

> 设置页里在常规的合适区域加入github的图标，并附上这个仓库的github链接，使点击图标能跳转到仓库首页

看过三种候选形态（地址明文加图标、整行即链接、带文字的「打开仓库」按钮）之后，用户给了一张参考图——Clash Verge 的设置页，红框圈住右上角那枚 GitHub 图标——并明确：

> 只显示github图标，像这样

也就是：**一枚纯图标按钮，不带任何文字标签**，位置照图里那样在标题行右端。仓库地址是 `https://github.com/ChaoqiYin/enjoy`（来自 `git remote -v`）。

**第二轮**，用户看过第一版的实际效果之后：

> 改成圆形图标按钮，并且图标背景色要优化。如果是亮色主题，这个图标背景色是黑色，图标白色。如果是暗色主题，一般是怎么样的？

答案在第五节。

## 一、这是界面第一次打开外部网页

在此之前，界面里所有「离开应用」的动作都止步于系统文件管理器（`revealItemInDir`）或剪贴板。这一次是第一次让 webview 之外的、属于用户自己的那个程序——浏览器——去拿一个地址。落这个能力的地方因此不是某个组件，而是 `shared/api.ts`。

## 二、为什么不能写 `<a target="_blank">`

放着锚点不写、绕到插件，是因为三条路里两条是坏的：

| 写法 | 结果 |
|---|---|
| `<a target="_blank" href="…">` | **静默丢弃**。Tauri v2 只在**有东西接管**时才把 `_blank` 交给 opener 插件；没有注册处理器时它什么都不做，也不报错。用户看到的是「一枚像链接的按钮，按下去没反应」。 |
| `<a href="…">`（窗内导航） | 整个应用被换成那个网页。**这个应用是一个窗口，窗内导航没有回头路**——没有地址栏，没有后退按钮。 |
| `openUrl(url)`（opener 插件） | 交给系统浏览器。**选这条。** |

## 三、两条权限缺一不可

ACL 里新增的是两条**分开的**授权，不是一条：

- `opener:allow-open-url` —— 授权 `open_url` 这个**命令**，但它**不带预置 scope**（见插件 `permissions/autogenerated/commands/open_url.toml`）。
- `opener:allow-default-urls` —— 提供 scope，也就是 `http://*` / `https://*` / `mailto:*` / `tel:*`。

只有前一条时，调用会被 `ForbiddenUrl` 拒掉：命令在，地址不在允许之列。这一对是**两条都要**的最小集合。逐条列出而没有改授 `opener:default`，是为了与这份 capability 现有的窄授权风格一致（它此前只授了 `opener:allow-reveal-item-in-dir` 一条）。

`scripts/check-permissions.mjs` 的 `needs` 表加了 `openUrl: 'opener:allow-open-url'` 一行，并在旁边写了为什么单看这一行会以为授全了。这个脚本把「界面调的每一个 Tauri 命令」与「capability 授的每一条」做双向比对，`needs` 表里没有的调用是**失败而不是跳过**——所以新能力绕不过它。

## 四、无后端时的答案

`openExternal` 与 `readCurrentSpace` / `readLanguage` 走同一套 `hosted()` 判据：

```ts
export function openExternal(url: string): Promise<void> {
  if (!hosted()) {
    window.open(url, '_blank', 'noopener');
    return Promise.resolve();
  }
  return openUrl(url);
}
```

浏览器开发构建里，「打开外部网页」这个问题浏览器自己就能答，而且它正是被问的那个东西。这是同一个决定落在第三处，不是权宜之计。

## 五、形状：圆形、反色，随主题自己翻过来

第一版取的是 `outline` + `icon-sm`，与卡片里其它纯图标按钮同规格。用户看过之后要求改成圆形并把底色做对——也就是照这枚 mark **自己的样子**画：一个实心圆，亮色下深底浅标，暗色下浅底深标。

**暗色下为什么反了过来。** 这是单色品牌标记在深色界面上的通行做法，也正是 GitHub 自己在暗色主题下画这枚 mark 的方式：它是一枚**有自身身份的标记**，不是一枚跟随本应用强调色的控件。若两套主题都用深底浅标，暗色下这个圆会成为页面上最黑的一块，比它所在的那一行还重，看着像块补丁；反过来之后，它在两套主题下与页面的对比量相当。

实现落在 `Button` 的一个新变体 `inverse` 上，一行读两套主题：

```
inverse: 'bg-foreground text-background hover:bg-foreground/90'
```

| | 圆的底（`--foreground`） | 猫（`--background`） |
|---|---|---|
| 亮色 | `#0f172a` | `#f5f5f5` |
| 暗色 | `#edeef2` | `#111317` |

颜色一处在两套主题下互换，因此**没有把颜色写两遍**，也不需要 `dark:` 分支。圆形由调用点的 `rounded-full` 给：变体管颜色，形状归尺寸与调用方（`cn` 是 `tailwind-merge`，调用点覆盖原语的 `rounded-md` 是它保证的行为）。

**为什么扩展原语而不是在调用点硬改颜色。** `开发指南.md` 说变体名是契约、要钉住「用了哪一个」就断言 `data-variant` 而不是 class。在调用点用 `className` 把 `ghost` 或 `outline` 涂成反色，`data-variant` 就在说谎——它会写着一个它并不是的东西。ADR 0028 那次调用点覆盖是另一回事：那是**同一个变体落在特殊表面上**（工具栏不是卡片），改的是底色，不是造一个新外观。

常驻的纯图标控件必须给 `Tooltip`，提示文案与无障碍名同值：`打开 GitHub 仓库` / `Open the GitHub repository`。按钮上**不写任何字**——名字是用来被念出来的，不是用来看的。

**`action` 为什么在 `h2` 外面**：按钮放进 `h2` 里会被读成一个标题的一部分，而那是调用方没给过的名字。所以标题行由 `h2` 改成 `div.flex.items-center.gap-2` 包住 `h2` 与 `{action && <span className="ml-auto">{action}</span>}`。**代价**：不加 `action` 时结构也多了一层 `div`，三张设置卡片的标题行都受影响（不是只有「常规」）；`SettingsSection.test.tsx` 那条按 `heading.parentElement.textContent` 取标题的断言因此仍然成立——那层 `div` 的 `textContent` 在没有 `action` 时仍是纯标题。

## 七、实测（无头 Chrome 开远程调试、CDP 驱动真实页面，做法同 ADR 0023 / 0024 / 0025）

在验收页 `acceptance/web-acceptance.html`（挂 `mockIPC` 夹具）里量按钮本体：

| 项 | 亮色 | 暗色 |
|---|---|---|
| 尺寸 | 28×28 | 28×28 |
| 圆角 | `rounded-full`（算成半边长，正圆） | 同左 |
| 圆的底色 | `rgb(15, 23, 42)` `#0f172a` | `rgb(237, 238, 242)` `#edeef2` |
| 猫的颜色 | `rgb(245, 245, 245)` `#f5f5f5` | `rgb(17, 19, 23)` `#111317` |
| 猫的尺寸 | 14×14 | 14×14 |
| 标题行高 | 28 | 28 |
| 卡片头（含说明） | 57 | 57 |
| 按钮右缘距卡片右缘 | 15（= 卡片内边距 14 + 边框 1） | 同左 |
| 无障碍名 | `Open the GitHub repository`（中文界面为「打开 GitHub 仓库」） | 同左 |
| 按钮上的文字 | 空（`textContent === ''`） | 同左 |
| 同一行藏起图标后 | 18 | 18 |

点击那一跳在两条分支上各验一次：

- **有后端**（验收页夹具，`isTauri()` 为真）：发出 `plugin:opener|open_url` + `{"url":"https://github.com/ChaoqiYin/enjoy"}`。
- **无后端**（纯 web 构建 `/settings`，`__TAURI_INTERNALS__` 不存在）：`window.open` 收到 `("https://github.com/ChaoqiYin/enjoy", "_blank", "noopener")`，而 `open_url` 不被发出。

## 八、代价

**「常规」卡片的标题行从 18 撑到 28，整张卡片高 +10 像素。** 这一行的原高由 `h2` 的 18 决定（18 像素图标），`icon-sm` 那枚 28 像素的按钮比它高，撑高的是它。这是这枚图标唯一影响到的几何；另两张设置卡片（「视频目录」「更新」）没有标题行动作，`action` 不传时那个 `span` 根本不渲染。

**它是全站唯一一枚反色控件，重量比周围的图标按钮重得多。** 卡片里其余纯图标按钮都是 `outline`（白底细边），这枚是实心圆。用户要的正是它跳出来，但代价要写清楚：它在视觉上比它所在的那一行更响。

**可发现性靠悬停。** 一枚 28 像素的纯图标按钮，屏上没有任何字说它是干什么的，用户要停上去才知道。这是用户点名要的形态（「只显示github图标」），不是省事的结果。

**界面里多了一条离开应用的出口，而它不被任何测试覆盖到「真的打开了浏览器」这一层。** 见下条。

## 九、本机无法自动验证的一条

`openUrl` 是否真的拉起系统浏览器，自动化跑不出来——命令是发给后端的，后端再交给系统，这一跳没有可观察点。已验证的是**命令被正确发出**（`plugin:opener|open_url` 带正确 URL，见上表）以及 ACL 两条齐备。最后一跳要 `npm run desktop` 起来点一次。

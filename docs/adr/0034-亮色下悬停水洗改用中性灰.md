# 亮色下悬停水洗改用中性灰

禁用态光标刚落地，用户回来看设置页，改了上一轮的一个决定：

> 修改刚才的一些决定，在亮色主题时，鼠标悬浮部分的背景色效果应该是[截图]这种

附的是一张别的应用的截图：白底列表，指针所在的那一行是一块浅灰圆角。

问了他两个问题，答：范围＝**所有悬浮水洗**（侧栏行、下拉菜单项、Select 选项、outline / ghost 按钮的悬停、对话框关闭按钮、表格行、视频行、元信息行；实心按钮的填充与各处的**静息**底色不动），色值＝**按图另取一值**。「暗色一律不动」写在选项里，他接受了。

## 一、为什么

这不是新账。[ADR 0029](0029-亮色改用用户指定的中性灰底与字段色.md) 把亮色页面换成中性灰 `#f5f5f5` 时，收尾里记下过一笔：

> 亮色那套粉调（`--muted` / `--accent` / `--secondary`）原先压在微紫白底上、彼此一路，如今与中性灰底没有色相关系，粉会更跳——本轮没有处理。

[ADR 0032](0032-亮色下被选中的一块改用主色.md) 处理了其中一半：「被选中的一块」换成主色红。它留在原地的那一半是这一轮的起点，那里写着：

> **左列的悬停行仍是粉的（`--secondary`，`#fecdd3`）。** 用户明确选了「悬停保持浅色」：只有当前行是红的，指针扫过的行不该跟着泛红。代价是亮色下这一列现在同时有红块与粉块。

「悬停保持浅色」是上一轮的选择，当时的容器里只有红与粉两个候选。这一轮用户看见了第三种：中性灰。于是设置页左列那两块从「红 / 粉」变成「红 / 灰」——**「指针扫过的行不该跟着泛红」这条理由没有被推翻**，换掉的只是它顺带定下的「浅」是哪一种浅。

## 二、改了什么

### 水洗不再借用那三个填充用的槽

亮色下承担水洗的是 `--accent`（`#ffe4e6`）、`--secondary`（`#fecdd3`）、`--muted`（`#fff1f2`，后两个的半透明）。三个都是设计文档的槽，且**都另有填充用途**：

| 槽 | 水洗之外的用途 |
|---|---|
| `--secondary` | `secondary` 按钮的填充、`Badge` 的 secondary 变体、进度条轨道 |
| `--muted` | 缩略图底、骨架屏、空状态的圆底与胶囊、对话框关闭按钮的**静息**底、`ShareStatusPill` |
| `--accent` | 只有水洗 |

所以三个里只有 `--accent` 能直接改值。其余两个照 `--selection` 的先例新增一对只服务水洗的槽：

| 槽 | 亮色 | 暗色 |
|---|---|---|
| `--hover` | `#e5e5e5` | `var(--secondary)` = `#2a2d33` |
| `--hover-soft` | `var(--hover)` | `var(--muted)` = `#1a1c20` |

`--accent` 亮色改为 `var(--hover)`；暗色仍是文档的 `#1a1e26`，一个字没动。

**为什么是两个槽而不是一个。** 暗色下「指针所在的一条菜单/侧栏行」与「指针所在的一整张表格行」从来不是同一级灰（`#2a2d33` 对 `#1a1c20`），这个区别是设计，不该被亮色这一轮抹平。亮色下两槽同值，强弱由落点自己的 `/50`、`/40` 造。

**`--sidebar-accent: var(--secondary)` 改为 `var(--hover)`。** 它一直是个派生槽，改指向之后侧栏的悬停自动跟着水洗走——`sidebar.tsx` 那两处类名一个字没动。

### 灰取哪个值

截图里那一行坐在**白底**上，本应用的亮色页面是 `#f5f5f5`。把贴着截图读到的 `#f0f0f0` 直接搬过来，在页面上只差 5 级——outline / ghost 按钮的悬停会几乎看不见（它们的底是 `--background`，不是卡片）。

取 `#e5e5e5`：本应用亮色的页面色 `#f5f5f5` 正是 neutral-100，而它是 neutral-200，一档之差；暗色的做法同构（页面 `#111317` → 悬停 `#2a2d33`，也是高一档）。在卡片 `#fcfcfd` 上差 23 级，在页面 `#f5f5f5` 上差 16 级，两处都读得出来。

### 落点

| 落点 | 原来 | 现在 |
|---|---|---|
| 侧栏行（`shared/ui/sidebar.tsx:93,200`） | `hover:bg-sidebar-accent`（= `--secondary` 粉） | 类名不动，槽改指 `--hover` |
| 下拉菜单项（`shared/ui/dropdown-menu.tsx:71,93`） | `focus:bg-secondary` | `focus:bg-hover` |
| 对话框关闭按钮（`shared/ui/dialog.tsx:110`） | `hover:bg-secondary` | `hover:bg-hover` |
| 表格行（`shared/ui/table.tsx:50`） | `hover:bg-muted/50` | `hover:bg-hover-soft/50` |
| 视频行（`features/library/VideoRow.tsx:78`） | `hover:bg-muted/40` | `hover:bg-hover-soft/40` |
| outline / ghost 按钮（`shared/ui/button.tsx:41,42`） | `hover:bg-accent` | 类名不动，`--accent` 已改值 |
| Select 项（`shared/ui/select.tsx:101`） | `focus:bg-accent` | 同上 |

九行、十二处。**没有动的**：`sidebar.tsx` / `toggle-group.tsx` 的 `data-[active=true]`（选中态走 `--selection`）、`table.tsx` 的 `data-[state=selected]:bg-muted`、动效里那些 `transition-colors`。

## 三、实测

真 Chrome（`--headless=new`）、真鼠标、1440 视口、验收夹具。每处都量了两遍——坐在页面上与坐在卡片上——半透明的水洗在这两块底上读出来不同。

**亮色**（页面 `rgb(245,245,245)`、卡片 `rgb(252,252,253)`）：

| 落点 | 挂的类 | 静止 | 悬停 |
|---|---|---|---|
| outline / ghost 按钮、Select 项、空间切换行、元信息行 | `hover:bg-accent` | 透明 | `rgb(229,229,229)` |
| 下拉菜单项、对话框关闭按钮 | `hover:bg-hover` | 透明 | `rgb(229,229,229)` |
| 侧栏行 | `hover:bg-sidebar-accent` | 透明 | `rgb(229,229,229)` |
| 表格行 | `hover:bg-hover-soft/50` | 透明 | `#e5e5e5`，α 0.5 |
| 视频行 | `hover:bg-hover-soft/40` | 透明 | `#e5e5e5`，α 0.4 |

**暗色**（页面 `rgb(17,19,23)`、卡片 `rgb(20,23,29)`）——每一处都与改动前的渲染值逐字相同：

| 落点 | 悬停 | 改动前 |
|---|---|---|
| `hover:bg-accent` 那四处 | `rgb(26,30,38)` | `rgb(26,30,38)` |
| 下拉菜单项、对话框关闭按钮 | `rgb(42,45,51)` | `rgb(42,45,51)` |
| 侧栏行 | `rgb(42,45,51)` | `rgb(42,45,51)` |
| 表格行 / 视频行 | `#1a1c20` 半透明 | 同 |

## 四、代价

**亮色 `--accent` 不再是设计文档的 `surface-container`。** [界面通用组件清单](../界面通用组件清单.md) §7 里 ADR 0029 那行写的「亮色其余槽一律不动（卡、muted、accent、secondary、border 全是文档原值）」从此少一条。`--accent` 仍是 shadcn 的槽名（`bg-accent` 与 `text-accent-foreground` 在多个组件里），但它的值现在是「悬停水洗」而不再是一张表面——亮色下两者恰好都是浅灰，读起来不出错，语义上却已经变了。`check-tokens.mjs` 不管这三个槽的值（只要求它们亮暗不同），门禁不受影响。

**暗色多了一层间接。** `--hover` 在暗色下解析到 `--secondary`、`--hover-soft` 解析到 `--muted`，也就是这两处原本就在用的值（实测逐字核对过）。代价是要改暗色的水洗，改的仍是 `--secondary` 或 `--muted`，而那两个槽同时是填充——与亮色这一轮想摆脱的处境一样。真正要还这笔账，得把暗色的填充也拆开，那是另一轮。

**表格行与视频行的悬停比原来明显。** 原来 `--muted`（`#fff1f2`）的半透明压在卡片上几乎看不见，现在是 `#e5e5e5` 的半透明。这是这一轮唯一一处「从看不见变成看得见」的变化，方向是对的（悬停本就该看得见），但它确实改了这两处的手感。

**粉没有从亮色消失。** `--secondary` 与 `--muted` 的填充用途一个没动（用户明确说按钮填充不动）：实心 `secondary` 按钮、`Badge`、进度条轨道、缩略图底、骨架屏、对话框关闭按钮的静息底仍是粉。这一轮只把「指针所在的那一块」从粉里拿了出来。

**`style.css` 仍是 500 行，余量 0。** 这一轮加了两个槽（`@theme inline` 两行、`:root` 两行、暗色两行）与三段注释，同时把 ADR 0032 留下的 `--selection` 注释与 `--sidebar-accent` 那段注释压缩，压完正好 500 行——与 ADR 0033 交出来的行数相同，一行余量都没多。

## 它推翻了什么

- **「亮色下悬停保持浅色（`--secondary` 粉）」**（ADR 0032 §四 代价条、§三 落点表里那句「**悬停仍是 `--sidebar-accent`**」、§三 实测表的「左列悬停行（亮色，另测）| `rgb(254,205,211)` 底（**没动**）」）——改为中性灰。**那条论证没有被推翻**：「只有当前行是红的，指针扫过的行不该跟着泛红」仍然成立，被换掉的只是它顺带定下的取值——那轮的容器里只有红与粉，没有灰。ADR 0032 §四 末段按同一理由留在粉里的下拉菜单项，一并改掉。记进 [界面通用组件清单](../界面通用组件清单.md) §7。
- **`--sidebar-accent: var(--secondary)`**（`style.css` 那段注释：「That fill is `--secondary`（`surface-container-high`）rather than `--accent`……」）——侧栏的悬停行不再与「被选中的一块」同色。

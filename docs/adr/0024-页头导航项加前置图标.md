# 页头导航项加前置图标

用户给了一张真实应用的页头截图，要求「给上方每个tab加上合适icon」。页头那五个入口从此各带一枚 14 像素的图标。

这件事本身很小，值得记的是三件周边的事：**图标是从哪来的**（两枚是复用的，理由是「同一个意思不该有两枚图标」）、**为什么加了图标而入口的名字没变**（装饰与可访问名），以及**代价**（页头的最小可用宽度被抬高了约 97 像素）。

## 一、五个图标，以及它们各自的来历

| 导航项 | 图标 | 来历 |
|---|---|---|
| 视频库 | `Clapperboard`（场记板） | **新引入**。仓库里没有「视频库」的图标 |
| 收藏 | `Heart` | **复用** `features/library/VideoActions.tsx` —— 视频卡片上那个收藏控件 |
| 最近播放 | `History`（时钟 + 逆时针回退箭头） | **新引入** |
| 共享 | `Share2` | **复用** `features/library/VideoBadges.tsx` 的「已共享」角标与 `features/share/SharePage.tsx` |
| 设置 | `Settings`（齿轮） | **新引入**，不与设置页左列冲突——那几个是分区图标（`Palette` / `Layers` / `RefreshCw` / `FolderOpen`） |

**「收藏」与「共享」为什么要复用而不是另挑一枚。** 视频卡片上已经画了这两件事：心形是收藏控件，分享是「已共享」角标。页头再用一枚别的图标说同一件事，就是让用户学两遍同一个意思。这也意味着页头的心形**不填色**——卡片上那枚在已收藏时是填满的，而页头说的是「去收藏页」，不是「已收藏」。

**被排除的三组，因为它们在仓库里已经各有一个意思。** `LayoutGrid` / `List` / `Table` 是工具栏的视图模式（`features/library/ViewModeSwitch.tsx`），`Clock` 在视频详情里是「时长」，`Play` 是卡片上的播放浮层。页头把它们借过来，等于让同一个图标在两处说两件不同的事。这也是选 `History` 而不选 `Clock` 的原因——「最近播放」要的是「时间 + 回到过去」，而 `Clock` 那一半已经被占用了。

五个名字都已在 `lucide-react@0.468.0` 的 1748 个图标里核对存在。图标库本身不用挑：本清单 §2.4 与 ADR 0018 早已定下继续用 `lucide-react`，不引入原型的 Material Symbols。

**页头「共享」项上仍然没有角标。** 加图标不是把那枚曾经挂在这里的 7px 圆点加回来——共享状态仍然只在头部右簇的文字胶囊里说（`ShareStatusPill`，见本清单 §7 那一行）。图标是装饰，不是一个指示器。

## 二、图标是装饰，入口的名字还是那两个字

图标上写着 `aria-hidden="true"` 与 `pointer-events-none`，这是 `开发指南.md`「带前置图标时」那条成文规则的要求。它在本处还多担一件事：**把入口的可访问名钉死在标签上**。

页头那五个入口是按可访问名被找到的——`AppHeader.test.tsx` 与 `routes.test.tsx` 都用 `getByRole('tab', { name })` 取它们，读屏也一样。图标一旦带上自己的名字（`aria-label`、`<title>`、或带名字的 `role="img"`），可访问名就会变成「Library Library」那样，两处测试一起打红，读屏也会把每个入口念两遍。实测五个入口的可访问名仍是 `["视频库", "收藏", "最近播放", "共享", "设置"]`。

（口径：lucide 默认并不给自己加 `aria-hidden`，而纯 `<svg>` 没有文本子节点时对可访问名的贡献本来就是空串，所以**不加也不会破**。加，是把这条不变性写下来，而不是碰巧成立。）

`shrink-0` 是因为 `TabsTrigger` 没有 `Button` 与 `Badge` 携带的 `[&_svg]:shrink-0` —— 页头是这两条链之外自己拼的，窄窗下图标会被压扁。

尺寸取 `size={14}`（绝对像素，与 `theme/ThemeSetting.tsx` 同款写法），规格出自 `开发指南.md` 的「图标 14 像素」。图标与文字之间**不需要新的间距**：`TabsTrigger` 本来就是 `inline-flex items-center gap-1.5`，那个 `gap-1.5` 一直空着，等的就是这个。实测图标 14×14、图标右边缘到文字左边缘 5.25px。

## 三、代价：页头的最小可用宽度从 589px 抬到 686px

每个入口多出 14px 图标 + 5.25px 间距 = 19.25px，五项共 **+96.25px**。中文界面下的实测：

| | 改前 | 改后 |
|---|---|---|
| 导航内容宽 | 292px | **389px** |
| 五个入口宽 | 58 / 46 / 70 / 46 / 46 | 77 / 65 / 89 / 65 / 65 |
| 末项右边缘（1280 视口） | 572 | 669 |
| **页头不被裁切的最小视口宽** | **589px** | **686px** |
| 标签开始折行的视口宽 | 约 700px | 约 780px |

默认 1200px 窗口下余量仍然充足（内容到右簇之间空 482px，改前是 579px），挤不到品牌区（`w-28` + `w-40` + `gap-5` = 255.5px 固定），也压不到右簇。

**窄窗才是代价所在。** `MainNav` 是页头里唯一的 `flex-1`，左右两簇都是 `shrink-0`，而它没有 `min-w-0`：窗口收窄时先让标签在盒内折行，折到 min-content 平台（中文 291px）之后就不再退让，于是右簇被推出视口——根列是 `overflow-hidden`（`app/App.tsx`），溢出被**裁掉**而不是出现滚动条。实测中文视口 620px 时右簇右边缘在 686，超出 66px；改前要收到 520px 才到这个地步。

英文标签更长（`Recently played`），门槛更高：DOM 模拟下改后约 883px、折行从约 920px 开始（模拟只改了标签文字的长度，字体与其余一切没动）。

**本轮不处理它**，因为处理要动的是别的东西：给 `tauri.conf.json` 加一个 `minWidth`（窗口能拖到多窄，是全局决定，ADR 0019 已记过它现在没有这个字段），或者给窄窗换一套导航形态（原型里那个 `hidden md:flex` 的替补至今不存在，`MainNav.tsx` 的文件头注释记着这件事）。这两件都不是加图标引出来的，也不该由这次改动顺手决定。**如实记在这里，供以后要动时查。**

**一处观感代价。** 原型 `_5` / `_6` 的页头 `<a>` 里只有文字，没有任何图标节点——九稿都是如此。所以这不是「把原型画过的东西补上」，是**原型之外的一处增强**，由用户点名要求。它让页头多了五个视觉锚点，比原型那版纯文字更重。

## 四、这一轮没有动的东西

- **`shared/ui/tabs.tsx` 一个字符不改。** `tabs.test.tsx` 的三组断言用的都是测试内联标签，与 `MainNav` 无关；只要不动 `TabsList` / `TabsTrigger` 的基础类，原语那边就不受牵动。
- **没有新增 `<nav>`。** `routes.test.tsx` 断言 `getByRole('navigation')` 唯一，`SettingsSidebar.test.tsx` 明写它从远处依赖这一条。图标直接放进既有的锚点里，没有包一层容器。
- **没有加 `whitespace-nowrap`。** 窄窗下标签现在会在空格处折行，加图标不改变这个行为；加 `nowrap` 是把折行换成裁切，那是另一件事。

## 它推翻了什么

**没有推翻任何成文决定。** `开发指南.md` 那条顶部导航的约定是被**扩写**的（加了图标这一句），不是被改写的；`界面通用组件清单.md` 的链接语义、`aria-current`、选中横线全部照旧。

**但它是对原型的一处有意偏离**，九稿的页头都是纯文字。按本仓规矩记在这里：这是用户要的，不是实现时的自作主张。

## 实施状态

**已实施。**

- `frontend/src/app/MainNav.tsx` —— `entries` 每项加一个 `icon` 字段，`MainNavItem` 的 props 加 `icon`，在标签之前渲染一枚 `size={14}`、`aria-hidden`、`pointer-events-none`、`shrink-0` 的图标。文件头的注释记了「五枚图标的来历」，细节指向本文。
- `frontend/src/app/AppHeader.test.tsx` —— 新增一条：每个入口里恰有一枚 `aria-hidden` 的装饰 `svg`，且入口的 `textContent` 仍等于它的标签（照该文件里 LAN 胶囊那条断言的写法）。
- `docs/开发指南.md` 顶部导航那条 —— 补图标这一句。
- `docs/界面通用组件清单.md` —— §2.4 图标条补一句；§5.1 的 `MainNav` 行参数列加 `icon`。

门禁：`npm run check` 通过（500 行上限：`MainNav.tsx` 131 行），`npm test` 81 文件 **458** 用例全绿（新增的正是上面那条），`npm run build` 通过。

真实浏览器（无头 Chrome 开远程调试、用 CDP 驱动真实页面，做法同 ADR 0023）里量过两套主题：五枚图标都是 14×14、`aria-hidden="true"`、class 为 `lucide lucide-<名称> pointer-events-none shrink-0`；图标右边缘到文字左边缘 5.25px；五个入口的可访问名仍是纯标签；导航内容宽 389px、末项右边缘 669（改前 292 / 572）。窄窗按 20px 一档从 1280 扫到 620，改前那一遍是把 `header nav svg` 用一条临时样式 `display: none` 藏掉得到的——`gap-1.5` 只在可见项之间生效，所以那样得到的正是改前的几何。两套主题各出了页头截图与放大图。

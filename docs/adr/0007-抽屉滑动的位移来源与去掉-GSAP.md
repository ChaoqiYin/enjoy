# 抽屉滑动的唯一位移来源，与去掉 GSAP

[ADR 0006](0006-抽屉开关动画与通用-Drawer.md) 把抽屉的开关动画交给 GSAP，理由是动画需要「编排」——连续快速开关时新补间要接管旧补间，退场要在完成回调里通知调用方释放内容。本条推翻这个结论：动画交回 daisyUI 自带的 CSS 过渡，`gsap` 与 `@gsap/react` 两个依赖移除，`Drawer` 的 `onClosed` 回调取消。

0006 的另一半结论不受影响，仍然有效：外壳抽成通用 `Drawer`、面板宽度上限 440 像素、关闭期间用 `inert`、焦点在关闭开始时即归还、关闭按钮用中性色描边 `btn-square`。

推翻的直接原因是一个可复现的缺陷：抽屉打开时约九成概率向左滑过头、露出抽屉外的背景，动画结束后又闪回最右侧。

## 缺陷的根因：两套位移叠加

daisyUI 5.7.32 的抽屉滑动用的是 CSS `translate` **属性**，不是 `transform`：

```css
.drawer-end > .drawer-toggle ~ .drawer-side > :not(.drawer-overlay) {
  translate: 100%;
  transition: translate 0.3s ease-out, width 0.2s ease-out;
}
.drawer-end > .drawer-toggle:checked ~ .drawer-side > :not(.drawer-overlay) {
  translate: 0%;
}
```

而 `Drawer` 原来的 GSAP 时间线动画用的是 `transform`（`xPercent: 100` → `0`）。`translate` 与 `transform` 在 CSS 里是**两个互相独立的属性**，各自的位移量**相加**，不是二选一。

原实现把 daisyUI 的开关写死成 `checked`、无条件为真，于是 `translate` 一直停在 `0%`、从不产生过渡，只有 GSAP 在动——这是那约一成的正常情况。当 `:checked` 的匹配与 GSAP 的首次写入发生竞态时，`translate` 会**在过渡中**从 `100%` 走向 `0%`，与另一个时钟上运行的 `transform` 叠加；合位移把面板推过终点，两者各自收敛到 0 之后再弹回右侧。现象与「滑过头、再闪回」完全对应。

这不是调参能解决的问题：只要位移有两个来源，叠加就成立，只看两边是否恰好同时归零。

## 为什么不需要一个库

daisyUI 自带的过渡已经提供了完整的开关动画，而且不止是滑动：

- **面板滑动**：上面的 `translate` 过渡。
- **遮罩淡入淡出**：`.drawer-side` 自身的 `transition: opacity .2s ease-out .1s allow-discrete, visibility .3s ease-out .1s allow-discrete`。
- **可交互性的自动管理**：`.drawer-side` 关闭时 `pointer-events: none; visibility: hidden; opacity: 0`，`:checked` 时由 `:where(.drawer-toggle:checked ~ .drawer-side)` 改回 `auto / visible / 1`。

也就是说，原先由 GSAP 完成的每一件事——面板位移、遮罩淡入、关闭后不拦截点击——vendor CSS 都已经在做，GSAP 那层是重复的，而且正是它引入了第二个位移来源。

0006 认为需要库的地方是**编排**：连续快速开关时，新补间要接管旧补间而不是跳回起点。这一点 CSS 过渡同样原生支持——过渡被打断时浏览器会就地重定向，从**当前计算值**继续走向新目标，不需要 `overwrite: 'auto'` 那样的调度器。0006 说的「这些都能用 `transitionend` 加状态机硬写」是对的，但正确答案比这更简单：连状态机都不需要。

## 常驻挂载是 CSS 过渡的前提

CSS 过渡在元素**首次挂载**的那一帧不会运行——没有「旧值」可以过渡。所以外壳必须从「打开时才挂载」改成**常驻挂载**，由 `checked` 从 `false` 翻到 `true` 触发过渡。这是 `Drawer` 契约里唯一真正的变化，也意味着 `checked` 从写死的 `checked readOnly` 变成受控的 `checked={open} readOnly`（`readOnly` 必须保留，否则 React 会对受控 checkbox 报警告）。

常驻带来三处必须一并处理的后果：

- **外壳变成全视口覆盖层，要自己关掉命中测试。** daisyUI 只给 `.drawer-side` 设了 `pointer-events: none`，`.drawer` 自身没有；面板外壳一旦常驻，这块 `fixed inset-0` 会吃掉整页点击。因此根节点补 `pointer-events-none`，由 daisyUI 在打开时还给 `.drawer-side`。
- **隐形开关成了 Tab 停靠点。** `.drawer-toggle` 是 `position: fixed; width: 0; height: 0; opacity: 0`——看不见，但仍可聚焦。补 `tabIndex={-1}`。
- **`inert` 的含义变了。** 以前它遮住的是「正在滑走的动画窗口」，现在它遮住的是「常驻的关闭态」，是这个面板退出 Tab 顺序与无障碍树的唯一手段。

`style.css` 里那条 `:root:has(.drawer-toggle:checked) { --page-scroll-lock: initial }`（防止 daisyUI 的 `rootscrolllock` 把根背景压暗、进而让 macOS 标题栏由白转灰）**不需要改**：它与 daisyUI 触发同一条件，改成受控之后只在抽屉打开期间生效，条件与规则依然一致。

## 为什么不再需要 `onClosed`

0006 用 `onClosed` 表达「关闭动画已经跑完，调用方可以卸载了」，调用方据此把两个状态拆成 `detailsOpen`（驱动动画）与 `detailVideo`（驱动挂载）。常驻之后这层拆分失去意义：外壳关闭时**本来就不卸载**，面板内容自然留到下次打开，退场动画期间不会变空。于是「动画时长」不再需要被应用层知道——0006 否决过的 `setTimeout(300)` 依然被否决，只是现在连绕过它的必要都没有了。

代价是面板在关闭后仍持有上一次的视频内容。它被 `inert` 与 daisyUI 的 `visibility: hidden` 双重遮住，不可见也不可达；换来的是调用方少一个回调、少一个状态。

调用方 `VideoPageContent` 有一处必须跟着改：那段「详情中的视频在重扫描后消失」的 effect 原先靠面板内容被清空来停止重触发——按 id 查库时是 id 置空，抽出内容状态后是 `onClosed` 清空 `detailVideo`。`detailVideo` 既然不再清空，就必须改成在关闭态提前返回，否则每次 `videos.data` 变化都会重发一条「文件已移除」通知。这个短路同时覆盖 `remove` 路径：它是先关抽屉再移除视频，因此不会为一次用户主动的操作补发通知。

焦点基准的捕获时机也必须挪位：`previousFocus` 原先在首次渲染时求值，而常驻之后首次渲染发生在页面加载时，那时 `document.activeElement` 是 `body`。改为在 `open` 翻真的那次 effect 里捕获。

## 无障碍上的取舍

- **`prefers-reduced-motion` 从 JS 移进 CSS。** daisyUI 的 `drawer.css` 里没有任何该偏好的处理（出现 0 次），原来这个判断在 `Drawer.tsx` 里。改为在 `style.css` 顶层加一条 `@media (prefers-reduced-motion: reduce)` 把 `.drawer-side` 与其面板的 `transition` 置为 `none`；写在顶层即可压过 daisyUI 的层叠层。抽屉的滑动与淡入是装饰，信息不依赖它，与仓库对通知倒计时细线的立场（那条线**不**降级）并不冲突。
- **焦点陷阱目前没有实现，这是一个已知缺口。** 抽屉抽出成 `Drawer` 之前，`VideoDetails` 曾实现并测试过 Tab 在对话框内循环；抽出时这段逻辑与其用例一起丢失了，`aria-modal="true"` 因此声明的模态性没有对应的键盘约束。本条不顺手补——它不属于「去掉 GSAP」的范围——但记录在此，以免日后被当成新缺陷重新发现。同样丢失的还有「触发元素已被卸载时焦点回退到页面」这条行为及其用例。
- **`inert` 让关闭态无法按 role 查询。** 与 0006 同一后果，只是现在长期成立：依赖「关闭即消失」的断言必须改为断言关闭态（`inert` / `checked`），不能再等元素离开 DOM。

## 取舍与影响

- **GSAP 的许可证负担一并消失。** 0006 记录过它不是 OSI 认可的开源许可（GreenSock 自己的 "No Charge" 许可，与仓库的 MIT 不同）。移除依赖后这条不再需要盘点。
- **单测只能钉住 `checked`，看不到动画。** jsdom 不加载样式表，也不绘制过渡，因此测试能验证「开关由 `open` 驱动」「关闭态带 `inert`」「外壳不卸载」「重渲染不抢焦点」，但**看不到**滑动本身。真实观感仍须在桌面端人工确认——与通知倒计时细线同一分工。
- **面板内容的生命周期由调用方决定。** `Drawer` 不再提供任何「内容可以释放了」的信号；持有内容的调用方需要自己决定何时替换它。本仓库只有一个调用点，`VideoPageContent` 选择保留到下次打开。
- **`Drawer` 目前仍只有一个调用点。** 与 `Hint` 同理，抽出的依据是这类面板的职责边界而非调用点数量。

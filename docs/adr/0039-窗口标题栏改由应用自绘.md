# 窗口标题栏改由应用自绘

用户的原话：

> 需要对 app 进行窗口标题栏定制，使其能在亮色/暗色下对主题颜色的切换能应用到标题栏，并且使标题栏的按钮和默认情况下拥有的按钮一致

参考的是 Tauri v2 的 Window Customization 文档（`learn/window-customization/#creating-a-custom-titlebar`）。

问题本身很短：标题栏由系统画，于是它跟随的是**系统**的亮暗外观，而不是应用自己的主题设置。设置页把主题切成亮色、系统却是暗色时，窗口顶上就压着一条深色带子，与下面 `--background` 的浅灰不是一个东西——「主题颜色的切换没能应用到标题栏」说的就是这件事。文档给的做法是把窗口装饰关掉（`decorations: false`），标题栏由网页自己画；那么它就是一层普通的应用表面，切主题时跟着走。

用户拍板的三件事：

| 项 | 取值 | 代价（见 §四） |
|---|---|---|
| 位置 | 页头**上方**独立的 32px 一条 | 垂直空间少 32px；「Enjoy」在屏幕上出现两次 |
| 观感 | 复刻 Windows 原生：46×32 命中区、1px 细线字形、悬停中性水洗、关闭悬停红底白字 | 按钮颜色不随主题 token 走，要单独定两个槽 |
| 范围 | 全平台自绘（`decorations: false` 对所有平台生效） | macOS 失去原生红绿灯 |

## 一、为什么不能只把系统标题栏染成主题色

`decorations: false` 不是唯一的路。Windows 的标题栏颜色跟随**系统**的应用亮暗设置，而 Tauri 的 `window.setTheme()` 正是去改那一个——在设置页切主题时跟着调一次，原生标题栏就会跟着翻。这条路几行代码，不丢任何系统能力。

它没有被选，因为用户的第二句话把它排除了：「使标题栏的按钮和默认情况下拥有的按钮一致」——若标题栏还是系统的，这句就不必说。要自绘的按钮，就得有自绘的标题栏；而既然标题栏是自绘的，它用什么颜色就由应用决定，`setTheme()` 那条路也就不需要了。

## 二、改了什么

### `src-tauri/tauri.conf.json`

主窗口加 `"decorations": false`。`shadow` 保持默认 `true`（`tauri-utils` 的 `config.rs:2337`），于是 Windows 上仍拿到系统的投影与圆角——这一点在 §三 里量过。

### `src-tauri/src/commands/window.rs` —— 三条新命令

`minimize_window`、`toggle_maximize_window`、`request_close_window`，与既有的 `show_window` / `close_window` 并列。

用**应用自己的命令**而不是 `@tauri-apps/api/window` 的 `minimize()` / `toggleMaximize()` / `close()`，是 ADR 0037 立过的规（那张权限表的存在正是为了抓「又去够那个包」），照做也就不用给能力文件增授权。

`request_close_window` 与 `close_window` 是**一对，且分工是整件事的要点**：前者是「用户按了关闭按钮」，只**请求**关窗；`Window::close()` 在 Tauri 里被明确记为先发 `WindowEvent::CloseRequested`（`tauri-2.11.5/src/window/mod.rs:1793`：*"It emits `WindowEvent::CloseRequested` first like a user-initiated close request so you can intercept it"*），所以共享中时仍会被 `crate::closing::handle` 拦下、提问——与点原生 X 是同一条路。后者才是「用户已经答了是」：结束服务再 `destroy()`。

### `src-tauri/src/titlebar.rs`（新）

自绘标题栏要知道窗口当前是不是最大化，才能决定画方框还是画两个错位方框。这个事实只有系统有，界面拿不到（`getCurrentWindow().isMaximized()` 又是「去够那个包」），所以由后端推。

`Titlebar::report(maximized, events)` 一条规则：**只在答案变了的时候说**。`WindowEvent::Resized` 在拖拽缩放时每帧都来，不说这条规则，界面会在一次拖拽里收到六十次同一个 `false`。

读的是**窗口自己的事件**，不是「哪个命令被调了」：窗口被双击标题（Tauri 注入的拖动脚本自己会最大化）、被 Win+Up、被拖到屏幕顶端，都是它，而这些都不是我们的某一次调用。读窗口一个事实就全覆盖。

`main.rs` 的 `.on_window_event` 因此从「一臂」变成 `match` 两臂：`CloseRequested` 照旧，`Resized` 把 `window.is_maximized()` 交给 `Titlebar::report`。规则与上报合成一次调用，形状与 `closing::handle` 一致——测试造不出窗口，但造得出那个接收端，所以能留给测试的空白就只有这么多。

### `src-tauri/src/events.rs`

`Events` trait 加 `window_maximized(bool)`（`AppEvents` 发 `"window-maximized"`，`Recorded` 记下**顺序**而不只是次数——界面正被免掉的是重复，次数说不出最后那句是不是真的）。

### `src-tauri/capabilities/main.json`

加 **`core:window:allow-start-dragging`**，且这是唯一一条新增的窗口权限。拖动区是 Tauri 自己的注入脚本在响应 `data-tauri-drag-region` 上的 mousedown，它调的 `plugin:window|start_dragging` 不在 `core:window:default` 里——我逐条读过 `src-tauri/gen/schemas/` 里展开后的那个集合，它只有读取类命令。双击拖动区最大化要的 `internal-toggle-maximize` 已经在默认集里，不必加，那个行为也就白拿。

### 前端

- `frontend/src/app/TitleBar.tsx`（新）——32px 的一条，左「Enjoy」右三个按钮，整条带 `data-tauri-drag-region="deep"` 与 `select-none`，底色 `bg-background`（不透明、无边框：分隔线仍由页头自己的 `border-b` 承担，两条读作一整个顶栏）。
- `frontend/src/app/WindowControls.tsx`（新）——三个 `<button>`，46×32、右端齐平、彼此无间距、方形无阴影。**没有复用 `shared/ui/button`**：它每一档都是圆角方块、且至少比这条栏高出一半，变体还各带一层不透明表面，而那层表面正是标题栏本身。
- `frontend/src/app/App.tsx` —— `<TitleBar />` 插在 `<AppHeader />` 之上。
- `frontend/src/shared/api.ts` —— `windowApi` 加 `minimize` / `toggleMaximize` / `requestClose`，`backendEvents` 加 `onWindowMaximized`。
- `shared/locales/{en,zh-CN}/common.json` —— `minimizeWindow` / `maximizeWindow` / `restoreWindow` 三键（`close` 复用）。
- `frontend/acceptance/web-fixture.ts` —— 三条命令的应答。夹具**不做**模拟：三个按钮要动的是页面画在其中的那个真窗口，页面够不着；中间那个字形又是推来的、不是问来的，所以在验收页里它一直是方框。这一点写在夹具的注释里。

### 字形为什么是掩膜，不是 SVG 的墨色

平台自己的关闭按钮在指针下面把字形刷白，而本仓库的检查是**指针状态只许重画背景**（`scripts/check-tokens.mjs:337-396`，来自 ADR 0038）。把字形画成掩膜、用 `background-color` 上墨，墨色与它坐着的那层水洗就是**同一个属性**，规则照字面成立——这不是绕检查，是它本来要说的事；顺带 1px 方头字形也只有这样才有（lucide 是 2px 圆头，做不出 Windows 那三笔）。

四个形状放在 `frontend/src/components.css`，各自只声明一条 `--window-glyph`，掩膜声明在 `.window-glyph` 上写一次（`-webkit-` 前缀与标准属性各一条；`mask-*` 不加前缀要 macOS 10.15 之后的引擎才有）。

### `frontend/src/components.css`（新）—— style.css 从 499 行到 425

`style.css` 在改动前是 **499 行**，而它的模块上限是 500（`scripts/check-source.mjs`）。这一轮要加的是两个 token 与四条字形，于是按职责拆了一次：`style.css` 留下**声明 token 的那部分**（两个变体、`@theme`、`:root`、暗色块、`@layer base`），`components.css` 收走**某一块界面自己穿的规则**（滚动视口、卡片的辉光、点阵、通知倒计时细线、以及这四条字形），由 `main.tsx` 紧随 `style.css` 之后载入。

拆的边界是职责而不是行数：`style.css` 里唯一还点着组件名的只有导航那条 `--animate-nav-turn`，而它在那边是因为 Tailwind 要从 `--animate-*` 建出 `animate-nav-turn`，关键帧必须写在声明这个 token 的块里。

### `scripts/check-permissions.mjs` —— 一条检查读不到的「伸手」

拖动区的授权**不是 `api.ts` 里的一次调用**：它是 Tauri 的注入脚本对着一个属性做的响应。那份脚本自己的原则是「读不懂的写法是失败，不是沉默」，所以给它加了一段：扫 `frontend/src` 里的 `data-tauri-drag-region`，出现了就必须有 `core:window:allow-start-dragging` 被授予，两个方向都报。加完做了**红绿两向实测**：把那条授权从能力文件里拿掉，检查立刻红并点名（`the interface reaches for core:window:allow-start-dragging, and no capability grants it`），放回去立刻绿。

## 三、实测

### 无头 Chrome 量几何与两套主题（验收页，DPR 1，视口 762×484）

| 量 | 读数 |
|---|---|
| 标题栏本身 | `0, 0` 起，**762×32**，右端与视口右缘齐平 |
| 三个按钮 | 各 **46×32**，x = 624 / 670 / 716（首尾相接、无间距），最右一只的右缘 = **762** |
| 三个字形 | 各 **10×10**，y = 11（32 里的正中） |
| 页头 | y = 32，高 **50**（`h-14` 的 49 加它自己那条 1px 下边框，几何未动） |
| 标题文字左内边距 | 14px，与页头 `px-4` 的 14px 对齐 |

配色（两套都读，`data-theme` 属性翻转后取 `getComputedStyle`）：

| | 亮色 | 暗色 |
|---|---|---|
| 标题栏底 | `#f5f5f5`（`--background`） | `#111317`（`--background`） |
| 「Enjoy」 | `#64748b`（`--muted-foreground`） | `#9aa0aa` |
| 字形 | `#0f172a`（`--foreground`） | `#edeef2` |
| 最小化悬停（强制 `:hover`） | `#e5e5e5`（`--hover`） | `#2a2d33` |
| 关闭悬停（强制 `:hover`） | `#c42b1c`，字形 **`#ffffff`** | 同左 |

`:hover` 是用 DevTools 协议的 `CSS.forcePseudoState` 逼出来的——截图上做不出悬停态。

四个字形另外按 10 倍放大截了一张：最小化是 10×1 的横杠、最大化是 1px 方框、还原是两个错位 8×8 方框（后面那个只画没被前面压住的上边与右边）、关闭是从角到角的叉。**Windows 原生观感成立**。

### 真窗口（本机 125% 缩放，客户端 1500×1000）

`decorations: false` 与默认 `shadow: true` 合起来，窗口外框 1518×1010、客户端 1500×1000，四周那 18×10 物理像素是非客户区。**它没有变成一条看得见的边**：PrintWindow 抓下来的窗口内容满幅，标题栏贴在顶边。

四条边与四角**都能拖拽缩放**。这一条没有靠合成输入验，而是直接问窗口：`SendMessage(WM_NCHITTEST)` 打在边与角上的应答是 `HTLEFT` / `HTRIGHT` / `HTBOTTOM` / `HTTOP` / `HTTOPLEFT` / `HTBOTTOMRIGHT`，标题栏中部与最大化按钮的位置都是 `HTCLIENT`。窗口样式里 `WS_THICKFRAME` 在。

**最大化与还原这一条端到端验过**：用 `ShowWindow(SW_MAXIMIZE)`（系统调用，不是合成点击——本机鼠标被远程会话夺走，见 §四）把窗口最大化，PrintWindow 抓下右上角，中间那只按钮的字形**从方框变成了两个错位方框**；`ShowWindow(SW_RESTORE)` 之后回到方框。这条链是 `WindowEvent::Resized` → `Titlebar::report` → `"-window-maximized"` → `WindowControls` → 字形，一次外部改尺寸走通了全部。

### 测试

`cargo test` **210 项**全绿（`titlebar` 新增 3 条：第一次测量一律上报、站着不动的 61 帧只说一次、最大化与还原各说一次且顺序为 `[false, true, false]`）。`cargo fmt --check`、`clippy -D warnings` 干净。前端 `npm test` **86 文件 494 用例**（新增 `TitleBar.test.tsx` 5 条：是拖动区且写着窗口名、三个按钮就是系统那三个且顺序一致、各自打到哪条命令、中间那只按后端的说法画、按钮没做成的事要说出来）。

**本机默认超时下有假红。** 用 5 秒的默认 `testTimeout` 跑全量时，若干与本次改动无关的文件（`AppHeader`、`ScanProgress`、`ThumbnailProgress`、`VideoBadges`、`VideoTable`、`ViewModeSwitch`）会超时失败，且每次失败的文件集合都不同。**在改动前的干净树上跑同样的命令，也一样红**（4 文件 6 用例），因此这不是本轮引入的。把超时放到 60 秒后，86 文件 494 用例全绿。

## 四、代价

**最大化按钮悬停不再弹贴靠布局。** Windows 11 的那个飞出菜单挂在 `WM_NCHITTEST` 返回 `HTMAXBUTTON` 上，而 tao 的命中测试只处理缩放边与顶边（§三 的读数：那个位置回 `HTCLIENT`）。`Win+Z`、拖到屏幕边缘、`Win+方向键` 都还在，少的是鼠标悬停那一个入口。补它要在 Rust 侧再挂一层窗口子类、并把按钮的矩形同步过去，本轮不做。

**系统菜单没有了。** 右键标题栏与 `Alt+Space` 都随 `WS_CAPTION` 的不可见一起失效。

**macOS 失去红绿灯。** 全平台自绘是用户选的，macOS 上就是右上角三个按钮而不是左上角三个圆点；无边框窗口也没有系统的圆角。自动更新本就只发 Windows，这一条的实际影响在开发机上。

**横向多占了 138 像素。** 46×3。页头本来就够窄就会裁掉右簇（ADR 0024），现在这个门槛更高一点。三条栏自身也有一条地板：应用名先让位（`min-w-0 truncate`，实测视口 150px 时它的宽度是 **0**），再窄就轮到按钮，**约 155px 起**关闭按钮开始超出右缘——比同一版本的页头门槛（686px）低得多，所以只在窗口被拉到远不可用的那一刻才可能出现，本轮不设 `minWidth`。

**垂直少 32 像素。**

**三个按钮进了 Tab 顺序**，且在最前。原生标题栏不在 Tab 顺序里。保留可聚焦是有意的——键盘够不到一个真实按钮比多三个停靠点更糟——但按下 Tab 的第一站从此是「最小化」。

**「界面不碰自己的窗口，因此不需要任何关于窗口的授权」不再逐字成立。** 能力文件里出现了一条窗口权限，两条指南里写着这句话的地方都得改（见下）。准确的说法是：界面仍不调 `@tauri-apps/api/window`，那一条授权是 Tauri 自己的脚本要的。

**验收页看不到中间那只按钮的另一半。** 夹具不模拟最大化的推送（它会去够一个页面碰不到的窗口），所以在浏览器里走查只能看到方框那一态；两个错位方框要靠真窗口，本轮是靠 `ShowWindow` 验的。

**本机不能验点击。** 鼠标位置被同一台机器上的远程控制会话持续夺走（这是本仓库早就记下的那条），所以「按一下最小化真的最小化」「拖标题栏真的拖得动」「双击标题栏最大化」「开着共享点关闭仍会问」这几条**没有在本机点过**，交付后请点一次。

## 它推翻了什么

**`本地视频统一启动器-开发基线.md:158`**：

> 窗口保留系统标题栏和窗口控制按钮，不显示应用原生菜单栏；启动时禁用框架默认菜单，读取或切换语言时不创建菜单。

前两句被推翻：系统标题栏与它的控制按钮都不保留了。菜单那两句照旧。

**`本地视频统一启动器-开发基线.md:174` 中段**：

> 窗口保留 macOS 原生标题栏，webview 铺满窗口而网页内容自标题栏下方开始。

整句作废：没有原生标题栏了，webview 铺满窗口，网页内容自**自绘标题栏**下方开始。

**`本地视频统一启动器-界面原型.md:35`** 的那一句与基线 158 同文，一并改。

**`docs/guides/开发与启动.md`** 的「界面不碰自己的窗口……因此不需要任何关于窗口的授权」，与 **`docs/guides/测试与检查.md`** 里「这张表现在一项也不被用到」——都被 §四 那条取代。

**`scripts/check-permissions.mjs` 文件头**那句「reading it reads every reach」：现在读 `api.ts` 读的是每一次**由调用构成的**伸手，拖动区那一条是属性，改由后加的 `DRAG_REGION` 一段去读。

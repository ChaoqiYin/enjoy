# 禁用态取禁止符

用户看着按钮，问：

> 按钮如果是禁止状态，需要变更鼠标hover的cursor效果，现在没有更改,先说方案，是全局修改还是怎么做

问的是方案，所以先把两条路摆出来（改全站还是只改 `Button` 组件），并问了他两个问题。用户选了「全局，连 Radix 项一起拆」与「`not-allowed` 禁止符」。

## 一、为什么「现在没有更改」

不是没写规则，是规则写了也到不了。三件事叠在一起：

1. `style.css` 的 `@layer base` 里那条是全站唯一的 cursor 契约，它只写了**能点**的：`button:not(:disabled)` 等给 `cursor: pointer`。禁用态**故意没有规则**，注释里的理由是「a disabled control keeps the arrow… a hand over it promises an action that will not happen」（[开发指南](../开发指南.md)「按钮样式」里禁用态那条同样写着「禁用态保持箭头」）。
2. 光看第 1 条，禁用按钮该显示默认箭头。但 `Button` 的基础类带着 `disabled:pointer-events-none`——指针事件被关掉，鼠标**落不到按钮上**，命中测试穿透到下面那一层。光标于是由下层决定：下层是普通容器就是箭头，下层是文本框就变成 I-beam。**禁用按钮的 hover 光标是碰运气的，不是设计出来的。**
3. 反观 `Input` / `Checkbox` / `Select`，它们用的是 `disabled:cursor-not-allowed` 且**没有** `pointer-events-none`，禁用时确实显示禁止符。全站本来就不一致：**输入类给禁止符，按钮类给穿透。**

两个事实不能靠记忆判断，先在真 Chrome 里量了：

| 探针 | 命中测试命中谁 | 光标 |
|---|---|---|
| `<button disabled>` | 它自己 | `not-allowed`（作者声明生效） |
| `<button disabled style="pointer-events:none">` | 下层 `div` | 下层的 `text` |
| `<div role="button" aria-disabled="true">` | 它自己 | `not-allowed` |

**禁用按钮参与命中测试**——所以光标能生效；是 `pointer-events-none` 把它挡开的。

还有一个事实决定了改法：`button:hover` 的样式**在禁用按钮上照样匹配**（把 hover 背景设成纯红，禁用按钮渲染出来就是红的；`matches(':hover')` 报 `false` 是 API 的假象，渲染结果说了算）。这意味着拆掉 `pointer-events-none` 之后，变体里的 `hover:bg-primary/90` 会一起复活——**光拆不够，还得把悬停压住。**

## 二、改了什么

**基样式一处，两条互为镜像的规则。** `style.css` 那条原本只写「能点」的规则改成两半，角色列表用 `:is()` 写在外面：

```css
:is(button, [role='button'], [role='menuitem'], [role='option'], [role='radio']) {
  &:not(:disabled, [aria-disabled='true'], [data-disabled]) { cursor: pointer; }
  &:is(:disabled, [aria-disabled='true'], [data-disabled]) { cursor: not-allowed !important; }
}
```

**`hover` 变体重定义为排除禁用控件。** Tailwind v4 自己的是 `&:hover` 包在 `@media (hover: hover)` 里；重定义时那条 media query 保留，只加排除：

```css
@custom-variant hover {
  @media (hover: hover) {
    &:hover:not(:disabled):not([aria-disabled='true']):not([data-disabled]) { @slot; }
  }
}
```

一处声明，全仓所有 `hover:` 类自动跳过禁用控件，不必逐个变体去补 `disabled:hover:`。**这是拆掉 `pointer-events-none` 的前提**，不是顺带的清理。

**七处 `pointer-events-none` 拆掉**，保留各自的 `opacity-50`：

| 文件 | 拆掉的类 |
|---|---|
| `shared/ui/button.tsx` | `disabled:pointer-events-none` |
| `shared/ui/sidebar.tsx`（两处） | `disabled:pointer-events-none`、`aria-disabled:pointer-events-none` |
| `shared/ui/toggle-group.tsx` | `data-[disabled]:pointer-events-none` |
| `shared/ui/tabs.tsx` | `data-[disabled]:pointer-events-none` |
| `shared/ui/dropdown-menu.tsx`（两处） | `data-[disabled]:pointer-events-none` |
| `shared/ui/select.tsx` | `data-[disabled]:pointer-events-none` |

`[&_svg]:pointer-events-none`（图标不挡指针）与装饰层的那些不动——它们与禁用无关。

**`!important` 是必须的，不是偷懒。** 拿到 dev server 编译出的 CSS 之后量到：`dropdown-menu` 与 `select` 的项带着 `cursor-default`，而它是 **utilities 层**的工具类；`style.css` 的规则在 `base` 层，层顺序是 `theme, base, components, utilities`——**后声明的层赢，任何特异性都翻不过来**。实测：

| 元素 | 只写普通声明时 | 带 `!important` 后 |
|---|---|---|
| `<button disabled>` | `not-allowed` | `not-allowed` |
| `[role=menuitem][data-disabled].cursor-default` | `default` ✗ | `not-allowed` ✓ |
| `[role=option][data-disabled].cursor-default` | `default` ✗ | `not-allowed` ✓ |
| `[role=radio][data-disabled]` | `not-allowed` | `not-allowed` |
| `[role=menuitem].cursor-default`（未禁用） | `default` | `default`（**没动**） |

CSS 层叠对 `!important` 声明的层顺序是**反的**（先声明的层赢），所以 `base` 的 important 压得过 `utilities` 的普通声明。这样那两处不必各自加一个类，未来任何带 `cursor-default` 的组件也自动正确。

## 三、实测（无头 Chrome 新版模式，1440 视口，验收夹具 `acceptance/web-acceptance.html`）

真组件、真悬停，禁用态由脚本把 `disabled` 置上：

| 控件 | 未悬停 | 悬停 | 底色 |
|---|---|---|---|
| 按钮（启用） | `pointer` | `pointer` | `rgb(245,245,245)` → `rgb(255,228,230)`（悬停水洗**在**） |
| 按钮（禁用） | `not-allowed` | `not-allowed` | `rgb(245,245,245)` → `rgb(245,245,245)`（**不复活**），`opacity 0.5` |
| 侧栏行（禁用） | `not-allowed` | `not-allowed` | 透明（**无高亮**） |

第二行是这一轮最容易出错的地方：拆掉 `pointer-events-none` 之后悬停高亮没有跟着回来，说明 `hover` 变体的排除生效了。

## 四、代价

**`aria-disabled` 从此只是视觉标记，不再拦点击。** `pointer-events-none` 一并拆掉了，所以一个用 `aria-disabled="true"` 标成禁用的控件，光标是禁止符，但点下去仍会触发。原生 `<button disabled>` 不受影响（浏览器本来就不派发鼠标事件），Radix 的软禁用项也不受影响（`menuitem` / `option` / `radio` 的禁用由 Radix 自己在事件里守卫）。**受影响的是自己写 `aria-disabled` 的调用方**——本仓目前只有 `SidebarMenuButton` 带这个变体，且没有调用方用它，所以现在没有实际暴露。

**`rubber-segment` 的禁用态没有一起改。** 它的 `aria-disabled:pointer-events-none` 留在原处：`aria-disabled` 写在**容器**上，而 `cursor` 要写在**项**上才看得见，光加基样式规则会让内部的 `role="radio"` 项重新变成手型——比现在更糟。它的主题条也确实没有禁用态调用方。要对齐得单独给容器写一条 `aria-disabled:[&_[role=radio]]:cursor-not-allowed`。

**`style.css` 到 500 行上限只剩 0 行余量。** 这一轮加完正好 500 行（`check-source.mjs` 判的是「超过 500」）。注释已经压过两轮，下一轮往这个文件里加东西之前得先腾地方。

**「检查更新」这类按钮悬停时会重新接收指针。** 拆掉 `pointer-events-none` 后，禁用按钮不再让指针穿透到下层——压在它下面的元素从此收不到悬停。本仓没有禁用按钮压在另一个可点元素上的布局，所以没有实际影响，但这是一条新的约束。

## 它推翻了什么

- **「禁用态保持箭头」**（开发指南「按钮样式」里禁用态那条的末句、`style.css` 那条规则的注释）——改为禁止符。**那句话的论证没有被推翻**：「手型是在承诺一个不会发生的动作」仍然成立，被换掉的只是它顺带定下的取值——禁止符说的是同一件事，且不承诺任何动作，还与输入类控件（`Input` / `Checkbox` / `Select` 的 `disabled:cursor-not-allowed`）合流。记进 [界面通用组件清单](../界面通用组件清单.md) §7。
- **各组件用 `pointer-events-none` 表达禁用**——七处拆掉。这不是一条成文的决定，是 shadcn 上游带进来的写法；但 `开发指南.md` 新加的那条把它写成了规则：**控件不要用 `pointer-events-none` 表达禁用。**

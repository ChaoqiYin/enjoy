# 页头导航项悬停时的逐字抬起落下

用户要求：

> 给tabs上的菜单文字在鼠标聚焦时添加上reactbits的Shiny Text效果

这条要求最后落成的**不是**流光，而是每个字从自己的位置上抬起来、再落回原处，一个接一个地走一趟。中间换过三次形状，前两次都是用户看过之后否掉的：

- **一道光带扫过**——react-bits 那个 `ShinyText` 的形状，也就是 [ADR 0026](0026-页头导航项悬停时的流光.md) 落下来的那一版。用户看过之后说：

  > 效果不太好，改成split-text这样的效果呢？

- **逐字浮入**——react-bits 那个 `SplitText` 的形状，每片从不可见处浮上来、逐片错峰（当时那个 token 是 `--animate-nav-split`，`0.3s ease-out` 加 `backwards`）。用户看过之后说：

  > 效果还是不好，改为Rotating Text看看

- **整字翻出、从另一侧翻回**——react-bits 那个 `RotatingText` 的形状，关键帧是 `0%` 位置不动、不透明，`40%` 抬到 `-110%` 且全透明，`60%` 从 `110%` 回来且仍全透明，`100%` 回到原位。这一版用户看过之后给出了最终形状：

  > 能否改成不是从完全消失开始变化呢，而是从固定的文字位置，开始以现有效果变化，然后回到固定效果

也就是：**动的起点和终点都是文字本来的位置**，只有中途才抬起来。落到代码上是把「上方出去、下方进来」改成**原路出去、原路回来**，并去掉 `opacity` 的交接——抬起来的那半个字由遮罩裁掉，不是淡出。行程再压到半个多字高（§四）。

同一个岔口上用户还答过两件事：动效形态取**逐字浮入、悬停重放**（不是「只走一次就停」），光带**直接撤掉**（不和新的叠着）。第三版的形状是用户口述改的，没有再问。

## 一、为什么不搬上游的三个组件

三个候选形状各对着一个 react-bits 组件，**一个都没搬**，`NOTICE` 一行没动、也没有许可头：

| 组件 | 上游是什么 | 这里为什么自己写 |
|---|---|---|
| `ShinyText` | 2026 年重写成一台 rAF 引擎：canvas 逐个像素读颜色、指针位置参与、glow 层、`IntersectionObserver` 开关，412 行 | 它解决的是「底色未知、要按实际画出来的像素取色」；页头没有这个问题，底色就是 `currentColor`。取重写前那版做法，零 JavaScript、约 20 行。ADR 0026 已记 |
| `SplitText` | 靠 GSAP：`gsap` + `ScrollTrigger` + `SplitText` 插件 + `@gsap/react` | 只为页头两三个汉字引进整套 GSAP 不划算，本仓已经有 Motion；而且上游是**滚动进入时触发一次**（`once: true`），页头永远在屏上，触发点必须重定 |
| `RotatingText` | 基于 Motion：接 `texts: string[]` 与 `rotationInterval`，按 `y` 与 `opacity` 逐字进出，靠外层 `overflow: hidden` 遮住 | 形状被采用（一层遮罩 + 逐字位移 + 错峰），**适配的地方是它轮换的是另一个词、这里轮换的是同一个词**：导航标签是固定的词，不能换成别的，于是变成「同一个词出去再回来」一圈 |

最后落地这一版**没有用到 Motion**：它是 `style.css` 里一条 token 加一份关键帧，加上 `MainNavItem` 里的拆字与错峰。

## 二、改了什么

**`frontend/src/style.css`** —— 三处：

| 位置 | 内容 |
|---|---|
| `@theme` | `--animate-nav-shine` 与 `@keyframes nav-shine` 整块换成 `--animate-nav-turn: nav-turn 0.48s ease-in-out` 与 `@keyframes nav-turn`（`0%` 与 `100%` 是 `translateY(0)`，`50%` 是 `translateY(-55%)`） |
| `:root` | `--nav-shine-color` 连它那段注释整段删除——这一版不碰颜色，没有「按主题换一个显眼的颜色」这回事 |
| 文件末尾 | `@media (hover: hover) { .group:hover .nav-shine { … } }` 整块删除 |

**`frontend/src/app/MainNav.tsx`** —— 两个错峰常量（`STAGGER_MS = 30`、`STAGGER_CAP_MS = 240`）、一个按**字素**切分的 `Intl.Segmenter`、`splitLabel()`；标签包进 `.nav-words` 层，里面每个字一个 `.nav-char` `span`，挂 `group-hover:animate-nav-turn` 并在行内给 `animationDelay`。

**`frontend/src/app/AppHeader.test.tsx`** —— 原来那条钉 `.nav-shine` 的断言重写为钉 `.nav-char`：字的个数、每个都挂 `group-hover:animate-nav-turn`、延迟单调不减且相邻步长不超过 30、末值不超过 240。jsdom 不跑动画、不算样式，这里钉的是**声明**；字真的动不动是真实浏览器那一半。减动效分支不在这里测，因为 `useReducedMotion` 把第一次的读数缓存在模块级变量上，测试里再装桩已经太晚——照仓里既有做法交给真机。

四件不那么显然的事，理由都写在 `MainNavItem` 的注释里，这里只点名：

- **那层是承重的，不是装饰。** 触发器是带 `gap-1.5` 的 flex 行，字若直接做它的子元素，每个字都是一个 flex item——字母之间会开 6 像素的缝，而英文标签里的空格是一个「只有空白的匿名 item」，会被整个丢掉，「Recently played」会读成「Recentlyplayed」。
- **遮罩挂在层上，不挂在字上。** 这是它唯一能挂的地方：`inline-block` 的基线只在 `overflow` 可见时才是它最后一个行盒的基线，字自己一裁，整行会塌半个行高。层可以承担，因为触发器是 `items-center`。代价是层的最小宽度没了（flex item 只在 overflow 可见时才有自动最小尺寸），由 `min-w-max` 手工补回。
- **`aria-label` 是一处让步，值得明说。** 入口是被可访问名找到的，而命名算法会在每个非 `inline` 的元素子节点两侧各加一个空格——逐字的 `span` 会把入口读成「L i b r a r y」。属性挂在**锚点**上而不挂在层上：`aria-label` 放在 `role=generic` 的 `span` 上是禁止的，jsdom 会放过它、读屏会忽略它，那是最坏的一种绿。
- **减动效时不出现，而不是静止地出现。** 层里直接放纯文字、不拆字，所以效果是**不在**——ADR 0008 给装饰定的规矩。

## 三、行程是「看不看得见」的开关——这次真正的坑

前两次尝试都留下一段「整条标签看不见」的空窗，第三次换形状也没解决，因为**病根不在方向、也不在有没有 `opacity`，而在行程相对行盒有多大**。

把「上方出去、下方进来」改成原路出去原路回来之后，`opacity` 的交接没了，字变成一个整体在动——但 `-110%` 的行程会把整个字形清出行盒。中文标签四个字、错峰 30 毫秒，几乎是一起抬头，于是**四个字同时出框**，一趟里 `220ms` 到 `360ms` 整条看不见。用户要的「不从完全消失开始」在 `-110%` 下其实没做到，只是把消失挪到了中途。

英文标签十四画、错峰 18 毫秒，摊在 240 毫秒里，任何时刻总有一部分还在框内——同一条规则，在两种语言下的读数完全不同：

| 抬多高 | 中文「最近播放」（4 字，错峰 30ms） | 英文「Recently played」（14 字，错峰 18ms） |
|---|---|---|
| 30%（5.1px） | 最少剩 0.77，从不空 | 0.82，从不空 |
| **55%（9.4px）· 现在** | **0.47，从不空** | **0.57，从不空** |
| 85%（14.4px） | 0.11，`260ms–300ms` 整条看不见 | 0.27，从不空 |
| 110%（18.7px，改前） | 0.00，`220ms–360ms` 整条看不见 | 0.11，`340ms–380ms` 看不见 |

「最少剩多少」量的是**一层遮罩之下、整条标签还有多少文字的墨露在行内**（占不带这一层时的比例），逐点各量一次。取 `-55%`，即一个多半个字高：一道波从标签上过去，**任何时刻行内都还留着远侧的字**，标签从头到尾读得见。

## 四、实测（无头 Chrome + CDP 驱动真实页面，1280 视口，dpr 1，真实鼠标事件）

- **停住的样子就是真的跑到的样子**：两种语言各取 5 个时刻，逐字的 `opacity` 与位移差 **0.0000**。比的是引擎自报的 `currentTime`，不是墙钟——按墙钟对齐会读到约 100ms 的采样滞后，第一版就是这么对错的。
- **遮罩是承重的**：静止时加它与不加它之差 **0**（不会切到不动的文字）；`t=200ms` 时差 **220**——去掉遮罩，抬起来的字会画到标签框外面。
- **拆字对静止态的代价**：中文逐字差全 **0.00**；英文逐字成盒把整排撑宽 **3.28px**（Settings +1.67、Favorites +0.92、Recently played +0.44……）。
- **挤到 20px 宽**：有 `min-w-max` 时层保持 **96.9px**、词是完整的；去掉它，层塌成 **20px**、词被切掉。
- **指针快速划过一排**（走 **559px** / **732ms**）：划完 **0 个字**停在 `opacity<1` 或还挂着动画；0.8 秒后与静止态差 **5**（噪声级）。
- **移开再回来**：悬停 0.35 秒时与静止差 **220**（在动）；移开 0.8 秒后差 **0**、动画数 **0**；再进入是一次从头走的新动画。
- **可访问名**：真机上该入口是 `role=tab`、`name` 为「最近播放」/「Recently played」，**悬停过程中不变**。
- **引擎真的在画**：screencast 取到 **24 帧**，变动包围盒正好落在导航行（中文 `447,16–514,30`）。
- **减动效**：`prefers-reduced-motion: reduce` 下逐字 `span` 数 **0**，入口的文字仍然等于标签。
- 门禁：`npm run check` 全过（`style.css` 437 行，500 行上限内），`npm test` **85 文件 481 用例**全绿，`npm run build` 通过，编译产物里的关键帧是 `0%` → `-55%` → `to`。会话当时读到的是 **82 文件 472 用例**——此后有三个提交落在它前面，带进了 `RepositoryLink.test.tsx`、`WindowReveal.test.tsx`、`initializeTheme.test.ts` 三个文件与九条用例。两个数各自都对，写在这里免得后来者拿一个去核另一个。
- **两套主题下的颜色读数：没有，也不该有**——这一版不改字色、不填底、不加任何颜色，只动位置。ADR 0026 那组 `209` / `186` 是光带的读数，不要拿来当这一版的。

相位取样沿用了 ADR 0026 那套装置：`Page.captureScreenshot` 返回的是最后「呈现」的那一帧，只有一条动画在跑的页面按需截不到新帧，所以相位是「把动画停掉、直接把关键帧动的那条属性写到该相位」取的，动没动另由 `getAnimations()` 的时钟单独证明。这次新踩到一个装置坑：清理函数把 React 写在行内的 `animationDelay` 一并抹掉了，于是四个字齐动——必须只清「停住」加的那些属性，并把延迟还原回去。**探针必须与规则逐字节同源**，这一条 ADR 0026 也吃过。

## 五、取值与它们的代价

| 岔口 | 选项 | 用户选择 | 依据 |
|---|---|---|---|
| 换成什么形状 | 光带 / 逐字浮入 / 整字翻出再翻回 | **逐字浮入**，随后由用户口述改成「抬起落下」 | 首段那三句原话：「效果不太好」→「效果还是不好」→「不从完全消失开始」 |
| 光带留不留 | 留着 / 撤掉 | **撤掉** | 与上一条同一次问答里定的；两个效果叠着会互相盖掉 |

**下面这几个取值没有问过用户，其中两个也没有对照读数，如实记：**

- **抬多高**：`-30%` / `-55%` / `-85%` / `-110%` 四个都量过（§三 的表），取两者都不空窗的那一档。**有读数。**
- **一趟多久（`0.48s`）与缓动（`ease-in-out`）**：是照 `RotatingText` 形状定的**第一版取值，此后只改过行程，没动过这两项**；**没有做过对照实测**——没试过 `0.4s` / `0.6s` / `linear`，也就没有读数说它比别的更好。这是本篇里唯一没有量测支撑的两个数。
- **错峰（30 毫秒、240 毫秒封顶）**：同样**没有对照读数**，理由在 `MainNav.tsx` 的注释里——「收藏」两个字差 30 毫秒读起来是**一个动作**而不是两个；「Recently played」十四画若平摊 30 毫秒，最后一个要到 `0.39s` 才开始动，指针一扫过整条标签就要转掉大半秒，所以总错峰封在 240 毫秒（一趟 480 毫秒 + 240 毫秒 ≈ 720 毫秒）。

**代价如实记：**

1. **打开系统「减少动态效果」的用户永远看不到这个动效，一次也看不到**（ADR 0008 的规矩：装饰在减动效下**不出现**，而不是静止地出现）。
2. **拆字有静止态也要付的代价**：每个字各占一个 `inline-block` 盒，字与字之间的**字距调整与连字没有了**。今天的标签撞不上（没有 `fi`/`fl` 这类组合，Space Grotesk 也不调其中任何一对），但标签来自 `shared/locales`，以后加一种语言就可能带「Files」「Profile」进来。换来的好处是悬停时**不重排**，因为盒子本来就在。
3. **`aria-label` 是一处让步**：入口的名字改由属性给出，不再是它自己的文字。
4. **不是循环动画**：一趟只在指针进入时走一次，指针一直停着不会反复走——与 ADR 0026 那条 `infinite` 正好相反。

## 它推翻了什么

两条成文的约定：

**页头导航项悬停时一道光带扫过文字**（`开发指南.md` 按钮样式一节的顶部导航一条、`界面通用组件清单.md` §5.1 的 `MainNav` 行与 §7 的一行）——改为悬停时标签的字**一个接一个抬起再落回**。`界面原型.md` 与 `开发基线.md` **不回溯改稿**，偏离只记在这里（同 ADR 0024 的既例）。

**[ADR 0026](0026-页头导航项悬停时的流光.md) 记为已被本篇取代。** 它的正文一字不改（那是它当时的依据与读数），只在开头加一行指向本篇、并在它的「实施状态」补一行说明。

`NOTICE` 与 `shared/ui/tabs.tsx` 都没有因此改动：三个候选组件一个都没搬，而动效属于调用点——原语不为一处调用长出一条规则。

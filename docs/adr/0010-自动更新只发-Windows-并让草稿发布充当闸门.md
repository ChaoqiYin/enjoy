# 自动更新只发 Windows，并让草稿发布充当发布闸门

应用此前只能手动下载安装包覆盖升级。这一条补上自动更新，并记下四处被否决过的岔路：密钥与平台签名是否可互相顶替、平台差异该在编译期还是运行时表达、发布该不该先落草稿、以及安装前该拦什么。

## 为何只发 Windows 仍要一对 updater 密钥

「不发布 macOS 版」省掉的是 Apple 那一套：开发者账号、Developer ID 证书、公证，全都不需要。它省不掉 updater 自己的密钥对。两套签名管的是两件事，不能互相顶替——平台签名回答「用户能不能打开这个应用」，updater 签名回答「这个更新包是不是发布者发的」。Tauri 的 updater 强制校验后者，且不可关闭。少了对密钥就没有自动更新可言。

私钥的代价是不可逆的：已发布的客户端带着旧公钥，私钥丢了就再也签不出它们能接受的包，只能让用户手动重装。这条写进了开发指南的发布章节。

## 为何平台差异走运行时 `cfg!` 而不是编译期 `#[cfg]`

最自然的写法是把 updater 依赖放进 `[target.'cfg(windows)'.dependencies]`，再给整个模块套上 `#[cfg(windows)]`。macOS 上连编译都不编译，持续集成自然也不再检查它——而这段代码**只在 Windows 上执行**，macOS 的流水线是它唯一能被自动检查的地方。代价交换得过于昂贵。

选定：依赖放普通 `[dependencies]`，全平台编译，`is_supported()` 用 `cfg!` 返回一个运行时常量。于是 Windows 专属的路径在 macOS 的 `cargo clippy --all-targets -- -D warnings` 下照样被类型检查和 lint。项目里已有同样的手法（`src-tauri/src/media/tools.rs` 判断内置工具目录）。

代价是 macOS 上多编译一份请求栈（reqwest + rustls），首次约一到两分钟。

## 为何发布先落草稿

`releases/latest` 不解析草稿。发布先建成草稿，意味着产物可以先下载下来实际安装一次，再手动发布；端点在发布之前不会指向一个还没人验过的包。

代价是**首个版本必须手动安装**，自动更新自第二个版本起才成立。接受这条：没有更早的版本来更新第一个版本，这是链路本身的边界，不是取舍带来的损失。

## 为何安装前拦住扫描，下载却不拦

安装是一次突然退出：Windows 上 `Update::install` 会启动 NSIS 安装器然后 `std::process::exit(0)`。正在进行的扫描会随进程消失而丢掉这一轮，所以 `restart_app` 在互斥槽位被占用时硬拒（`update.blocked.scanning`）。

下载不设这道闸。它是只读网络操作，不碰数据库也不碰缩略图缓存；在下载期间禁止用户发起扫描只会制造摩擦，而且会造出「包下好了却因为扫描没结束而不能装」的中间态——用户此时既不能扫也不能装。

前端另有一层软屏蔽（扫描中禁用重启按钮并说明原因），但闸门在后端：前端的禁用只负责不邀请用户去点一个做不到的按钮。

## 验证与未做的部分

- **已在本机验证**：75 项 Rust 测试通过，其中 `update::control_tests` 覆盖两条闸门的每一条拒绝路径与优先级、下载累计（回调给的是单块长度而非累计值）、进度节流（含服务端总长为零与谎报进度）、以及重启失败时恢复状态；`update::config_tests` 按插件自己的反序列化路径解析仓库中的 `tauri.conf.json`，把「配置块缺失导致应用起不来」变成一条测试。`cargo clippy --all-targets -- -D warnings` 在 macOS 上零警告——这正是运行时 `cfg!` 方案要换到的东西。`npm exec tauri build` 仍只产出 `.app` 与 `.dmg`，既没有生成更新工件，也没有要求签名私钥，证明 Windows 专属配置没有泄漏到主配置。
- **未做**：三个命令本身需要真实端点与真实更新包，单元测试覆盖不到；Windows 实机上的端到端（收到询问、下载、重启后变成新版本）尚未进行。
- **一条从源码读出、未在实机确认的行为**：安装完成后由 NSIS 安装器把应用重新拉起。依据是 `WindowsUpdateInstallMode` 为 `Passive` 时给出 `/P` 与重启参数 `/R`，且 `restart_after_install` 默认为 `true`。若实机发现应用没有自己回来，退路是显式调用 `update.restart_after_install(true)`，再不行就改为提示用户手动打开，并同步修改文案。

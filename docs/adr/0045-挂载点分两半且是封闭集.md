# 挂载点分两半且是封闭集

用户的原话：

> 你不能陷在某一个具体的问题里面来思考这个。你应该来思考的是，比如它可以在某个地方插入自己的节点这个功能，这个功能有一些点击效果。或者他在处理一些事情之前，那么有一个回调他可以介入。

> 应该是插件可以利用比如原生js，或提供react组件的方式将组件插入到这个app提供给插件可扩展的位置

这两句把要设计的东西从「封面怎么爬」换成了「哪里有可插入的位置」。本条就是那份位置清单——它是**封闭的**，一共六个。

## 一、六个挂载点

| 挂载点 | 类别 | 归属 | 合并 |
| --- | --- | --- | --- |
| `app.page` | 界面类 | 插件界面 | 叠加 |
| `video.panel` | 界面类 | 插件界面 | 叠加 |
| `video.fields` | 数据类 | 运行体 | **依次问、取第一个非空** |
| `plugin.settings` | 数据类 | 运行体 | 叠加（一插件一组） |
| `scan.completed` | 流程类 | 运行体 | 叠加 |
| `video.actions` | 动作类 | 运行体 | 叠加 |

**「叠加」** = 每个插件的贡献都出现，顺序由用户可调的插件顺序决定。

**封闭**的意思是：这六个之外不加新的，除非改这一条。理由是每一个挂载点都要在内核的**两半**里各写一遍（派发与渲染）、在契约目录里写一遍、在作者的文档里写一遍，四处都要一起改。开放式的钩子系统会让「这个位置到底存不存在」变成一个只能读代码回答的问题。

## 二、`video.actions` 必须归运行体

这是唯一一条不看类别、只看能不能用的归属。

爬封面插件**没有插件界面**——它的触发点就是视频上的一个动作（用户右键一条视频，选「抓封面」）。这个动作若归界面那一半，一个纯运行体的插件就永远触发不了自己的动作。因此动作类挂在**运行体**上。

同理，`scan.completed` 也不能挂在界面上：扫描完成时用户可能根本不在那个页面上。

## 三、只有 `video.fields` 会冲突

界面类的挂载点各插各的，互不相干。数据类里 `plugin.settings` 是按插件分组的，也不相干。真正会撞的只有 `video.fields`：两个插件都想给同一条视频提供封面。

规则定死为**依次问、取第一个非空**。它的好处是后一个插件是**补位而不是覆盖**：甲没抓到（返回空）时乙的结果照常出现，而不是被甲那个空结果挡住。

配套两条：

- **界面必须显示每个字段是哪个插件提供的**——不然同一个字段在两个插件之间换手时，用户看不出发生了什么。
- **用户可以调整插件的先后顺序**——顺序既然决定谁说了算，它就得是用户能改的，而不是安装顺序这种一次性的偶然。

## 四、声明即认领

每个挂载点由一个条目**声明并独占渲染权**，其它插件只能往**已声明**的位置注册。注册进没有声明过的位置、或重复声明别处已声明的键，**在加载期失败**，并在消息里点名第一个声明者。

**被否决的：在运行期检测冲突并报错。** 那会把一个配置错误变成一个偶发的、依赖加载顺序的运行时症状。加载期失败是确定的、可复现的、说得出是谁的。

附带的好处是卸载只剩**一条生命周期轴**：声明者一倒，它声明的子位置连同其上的全部贡献递归塌缩。不必再为「A 卸了但 B 还挂在 A 声明的位置上」单独写一套规则。

## 五、注册即得 disposer

每个注册口**自己返回**清理函数，接进一个统一的收集器，**逆序执行、可异步等待**。Rust 侧的挂载点注册、WASM 实例、定时器走**同一个收集器**。

**被否决的：让插件在 `onDispose` 里自己清理。** 那是个空口子——**忘记是默认值**，而忘记的结果是泄漏，泄漏的症状出现在离原因很远的地方。这条把它倒过来：要泄漏得刻意绕开 API。

## 六、契约做成生成的、机器可读的目录

六个挂载点各生成一张表：`key` / `kind`（`list` | `chain`）/ `scope` / 参数形状 / 冲突规则 / 当前占用者。

**两侧的类型、门禁脚本、给插件作者的文档、最小示例插件全部读它这一处。**

**为什么非要有它**：这六个挂载点天然要在三个地方各写一遍——Rust 侧的派发、前端的渲染类型、作者的文档。三份手抄的清单里任何一份漂移了都不会有人发现（它们不参与编译、不参与测试），直到某天有人照文档写了一个挂载点却发现它不生效。这份目录是唯一能在**一次断言**里同时压住两侧的地方。

## 七、`plugin.settings` 是第六个，理由与第二节同

内核**问运行体**「用户必须填什么」，然后自己渲染、校验、保存。四种字段类型：单行文本、多行文本、开关、目录选择。

**被否决的：让插件在自己的界面里画设置。** 纯运行体的插件没有界面，那样它就没法让用户填任何东西——而爬封面插件恰好需要用户填一个网址。

## 它推翻了什么

没有推翻已落地的代码。它约束的是将来：

- 挂载点是封闭的六处，新增只能改本条。
- 注册进未声明的位置是加载期错误，不是运行期警告。
- 每个注册口必须返回 disposer 并进统一收集器。
- 两侧的挂载点说法必须与契约目录一致，由门禁强制。

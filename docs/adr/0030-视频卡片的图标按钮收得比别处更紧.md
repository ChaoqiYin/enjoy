# 视频卡片的图标按钮收得比别处更紧

用户看着视频库网格视图的一张卡片截图，要求：

> 视频卡片里的按钮图标外留白调少一些，使图标按钮更紧凑

追问之后补了两句，把范围与数值都定死了：

> 改成3px留白，并且这里的图标圆角要减小一些

范围是**只有卡片**：列表行、表格末列与详情面板那三处的同一排按钮不动。数值是**图标不变，每边留白 3 像素**，圆角跟着收。

## 一、改了什么

这一排按钮由 `VideoActions` 一处画出来，尺寸来自它在 `shared/ui/button` 里挑的那一档。原先四处都挑 `icon-sm`，现在卡片挑新加的 `icon-xs`。

| | `icon-sm`（其余三处） | `icon-xs`（卡片） |
|---|---|---|
| 按钮 | 28×28 | **20×20** |
| 圆角 | 5（`rounded-md`） | **3**（`rounded-sm`） |
| 图标 | 14×14 | 14×14（不变） |
| 每边留白 | 7 | **3** |
| 成组间距 | 5.25（`gap-1.5`） | 5.25（不变） |

`VideoActions` 因此多一个 `iconSize` 参数，默认仍是 `icon-sm` —— 另外三处不传，拿到的形状与改前逐像素相同。`VideoCard` 是唯一传 `icon-xs` 的调用点。

**图标的 14 像素不动**，是用户的原话（「图标不变」）。变的只有按钮把图标包住的那圈：14 + 3 + 3 = 20。

## 二、两个数值是怎么落到类名上的

**20 是个像素值，不是 rem 刻度。** 全仓库的按钮尺寸都走 Tailwind 的 rem 刻度（`h-8`、`size-8`），因为根字号是 14 像素，刻度与像素之间是一比一又四分之一的关系。这一档写的是 `size-[20px]`，是全仓库第一个以像素计的按钮尺寸。理由：用户要的是「14 像素图标旁边 3 像素」，而刻度上没有这一格——`size-5` 是 17.5（留白 1.75）、`size-6` 是 21（留白 3.5），两边都不落在 3 上。既然这一档的定义本来就是「相对图标的留白」，就按留白写。

**3 是 `rounded-sm`，不是写死的 3px。** `--radius: 0.5rem`（14 像素根字号下 = 7）推导出 `--radius-md: calc(7px - 2px)` = 5、`--radius-sm: calc(7px - 4px)` = 3。圆角收小的理由是量出来的：5 像素的角在 28 像素的按钮上读作「圆角」，在 20 像素的按钮上就快读成圆形了，同一枚图标在两个尺寸下不像同一个控件。`rounded-sm` 跟着 `--radius` 走，所以将来换底圆角时它一起走——这与上面那条写死的像素不是同一种取值方式，是刻意分开的：**留白是相对图标的物理量，圆角是这个界面的一档**。

## 四、代价

**四个调用点不再同形。** `VideoActions` 的立身之本写在它自己的注释里——「一套而不是四套，因为四处的差别只在装得下什么，不在能问一个视频什么」。这一轮让卡片多了一维差别：形状本身。用户的取舍是「只有卡片」，所以行、表格、详情保持 28——从这三个视图看，同一排按钮比卡片里的大一档。将来若觉得四处应该同形，把 `VideoActions` 的默认值改成 `icon-xs` 是一行，但那是另一个决定。

**点击目标小了 29%。** 28 像素已经是鼠标目标的下限附近，20 像素更依赖指针精度。宽屏网格里三枚挨着排，误点会落在相邻按钮上——相邻的是「打开目录」与「移除索引」，两者后果差别很大。**本轮没有为此加间距或热区补偿**，如实记在这里。

**圆角那一档从此多了一个尺寸依赖。** `rounded-sm` = 3 只在这个 `--radius` 下成立；哪天 `--radius` 动了，卡片按钮的角与其余按钮的角会一起动，但比例不同（一个是 5→3 的差，一个是 20 与 28 两种宽度上的同一个绝对值）。

## 它推翻了什么

- **「卡片底部与详情面板的操作共用公共 `VideoActions`……图标形态取 `size="icon-sm"`、图标 14 像素、按钮间距 `gap-1.5`」**（`本地视频统一启动器-开发基线.md` §6）——卡片那半句改为取 `icon-xs`（20 像素、3 像素圆角），详情面板那半句照旧。
- **「卡片及其他页面中的纯图标操作统一用 `outline` + `icon-sm`」**（`开发指南.md` 按钮样式一节）——加上卡片的例外。

两处都只改这一句的范围，`icon-sm` 仍是这个界面的图标按钮。

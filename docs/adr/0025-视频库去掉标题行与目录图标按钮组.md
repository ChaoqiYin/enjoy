# 视频库去掉标题行与目录图标按钮组

用户给了一张真实应用的截图，红框圈住视频库页顶部那一块——大字的页面名「视频库」加右侧两个红色实心按钮「添加目录」「扫描」——要求：

> 页面上方的这块区域直接去掉，添加目录和扫描的快捷方式做成纯图标按钮组，放到切换展示方式的按钮组左侧单独排列

红框里其实是两件成文的东西：**页面的标题行**，以及**目录操作那对 `size="lg"` 的大按钮**。两件都被推翻了，所以这一轮的重量不在改动本身（一个组件去了标题行、另一个多了个 `iconOnly` 开关），在于它推翻了什么、代价是什么。

## 一、用户在三个岔口上的选择

| 岔口 | 选项 | 用户选择 |
|---|---|---|
| 页面名怎么办 | 彻底删掉 / 留一枚 `sr-only` 的标题 | **彻底删掉** |
| 设置页那三个目录按钮 | 一起改成图标 / 不动 | **不动，只有视频库变** |
| 「扫描」的颜色 | 两枚都用 `outline` / 保留一枚红实心 | **两枚都用 `outline`** |

三条都照办了。第二条是这次能只动一个组件的关键：`DirectoryActions` 加的是开关而不是被改写，设置页一行没碰。

## 二、改了什么

**`features/library/LibraryToolbar.tsx`** 删掉整个标题行（`<h1>` 与包着 `actions` 的那个 `min-h-10` 容器），`title` 参数一并从 props 里去掉；`actions` 挪进筛选工具栏那一行，落在**竖分隔线之后、`ViewModeSwitch` 之前**。工具栏行的 `mt-4` 也删了——它量的原本是与标题行的间距。

**`features/library/DirectoryActions.tsx`** 加 `iconOnly?: boolean`，照 `VideoActions` 那一套现成范式写：

| | `iconOnly` 为假（设置页） | `iconOnly` 为真（视频库） |
|---|---|---|
| 容器 | `flex flex-wrap items-center gap-3 sm:shrink-0` | `flex shrink-0 items-center gap-1.5` |
| 变体 | `primary` | `outline` |
| 尺寸 | `lg` | `icon-sm` |
| 图标 | 18px | 14px |
| 按钮内容 | 图标 + 文字 | 只有图标 |
| `aria-label` | 不设（名字来自文字） | 与文字同值 |
| `Tooltip` | 不渲染 | 提示该动作 |

**「不提供 `Tooltip`」是靠 `Tooltip` 自己的 `disabled` 开关实现的**（`shared/Tooltip.tsx` 在 `disabled` 时直接返回 children），而不是在调用方分支——这样两种形态共用同一条渲染路径，形状的差别全部落在那张表里。

**四个调用点**：`pages/LibraryPage.tsx` 加 `iconOnly`、去掉 `title`；`pages/FavoritesPage.tsx` 与 `pages/HistoryPage.tsx` 去掉 `title`；`pages/SharePage.tsx` 去掉 `title`（它占用同一个 `actions` 槽放「开始／停止共享」，按钮本身不动，随槽一起落到工具栏行里）。

### 为什么图标组在那个位置，且不加第二条竖线

工具栏原有的那条竖线的含义是「筛选 | 其余」，插进第三类之后仍然成立，所以没有加第二条：「单独排列」由间距表达——图标组内部 `gap-1.5`（5.25px，图标按钮的成组规格），与邻近两组的 `gap-3`（10.5px）相差一倍，读起来自成一组。若看下来觉得分隔不够，加一条是单行改动。

## 三、实测（CDP 驱动真实页面，1280 视口，中文界面，两套主题读数一致）

| | 改前 | 改后 |
|---|---|---|
| 页面里的 `<h1>` | 1（视频库） | **0** |
| 工具栏行 y / 高 | y120 / 60 | **y71 / 60** |
| 工具栏行的子项 | 5 | **6**（多出图标组） |
| 搜索框宽 | 680 | **608.25** |
| 图标按钮 / 图标 | — | **28×28 / 14×14** |
| 图标组宽 | — | 61.25 |
| 组内间距 | — | **5.25** |
| 图标组 → 视图模式 | — | **10.5** |
| 排序 → 图标组 | — | 22（= 10.5 + 1px 竖线 + 10.5） |

**行高没变（60px），因为那一行的高度本来就由 `ViewModeSwitch` 的 37px 加内边距决定**；图标按钮 28px 比它矮，塞进去不动任何东西。整个页面内容因此往上提了 49px（标题行那 35px 加它的 `mt-4`），内容区多出 49px。

四个列表页（视频库／收藏／最近播放／共享）的工具栏行都在 **y71、高 60**，逐像素一致；设置页的 `<h1>` 与目录区那三个大按钮原样（`h1count=1`，且它根本不走 `LibraryToolbar`）。可访问名经 `Accessibility.getFullAXTree` 核对为「添加目录」「扫描」，悬停确实弹出同名 `Tooltip`。

**折行门槛左移了约 80 像素**：把 `actions` 容器临时 `display: none` 量到改前的几何，行从一行折成两行的视口宽度在改前是 **761–800px** 之间、改后是 **841–880px** 之间（`flex-wrap` 的工具栏行一直会在窄窗折行，这次只是提前了约 80px）。

## 四、代价

**四个列表页从此没有一级标题。** 用户选的是「彻底删掉」，这是一处真实的无障碍代价：页面名还剩两个落点——页头导航的当前项（`aria-current`）与列表区的无障碍名（`VideoPageContent.tsx` 的 `aria-label={listLabel}`）——但后者只在**非空**列表上存在，且读出来不是一个页面标题。空列表时有 `EmptyState` 自己的标题。结果是：读屏用户在非空的收藏或最近播放页里，没有一句话直接说「这是哪一页」。

**视频库这一屏不再有红实心按钮。** 用户选了「两个都用 `outline`」。原先那一对红实心是这一屏唯一的着力动作，现在整屏的强调色只剩视图模式选中段的淡色底。

**「添加目录」的可发现性下降。** 从「带文字的 `size="lg"` 大按钮」变成一枚 28 像素的图标按钮加悬停提示；「扫描」那枚的 `RefreshCw` 语义比它更直白一些。

**改动的面积比看起来大。** 删标题行是全局决定——`LibraryToolbar` 被四个页面共用，`actions` 槽还被共享页占着，所以「去掉顶部那块」实际动了四个页面组件、两处测试文件与三条成文约定。

## 它推翻了什么

两条成文的按钮／布局约定被推翻，已记进 `界面通用组件清单.md` §7：

1. **`开发指南.md` 按钮样式一节的原第 65 条**（「视频库与设置页的『添加目录』『扫描』『建缩略图』保持相同的较大规格……`LibraryToolbar` 继续统一预留标题及操作槽高度」）——被拆成两半：设置页那一半保留，视频库那一半改写。
2. **页面顶部是标题行加操作槽**（`开发指南.md` 路由与页面组合一节、`开发基线.md` 的页面内容清单）——整块删除。

**`本地视频统一启动器-界面原型.md` 不回溯改稿。** §2 的三张线框图（`:45`、`:85`、`:112`）画的是 `视频库 … [添加目录] [扫描]` 一行，`:57` 写的是「页面标题右侧是页面操作槽」。原型是设计权威，按本仓规矩把偏离记在 §7 并指向原型位置，**这是本轮最大的一处原型之外的有意偏离**，由用户点名要求。

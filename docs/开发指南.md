# 开发指南

本指南适用于所有贡献者和自动化代理。具体产品功能与软件设计参见[本地视频统一启动器开发基线](本地视频统一启动器-开发基线.md)，此处统一维护开发约束。

## 开发环境与命令

项目已配置前端和桌面开发、构建、静态检查及测试命令，具体命令见下文。环境及依赖版本遵循设计基线。

统一使用 npm 并维护锁文件；新增项目配置时，在本指南中记录经过验证的依赖安装、桌面开发、生产构建、静态检查和测试命令。引入可执行代码时，同步补充格式化和静态检查配置。

## 编码风格与命名

- TypeScript 使用两个空格缩进，Rust 使用四个空格缩进；配置自动格式化工具后统一由工具执行。
- React 组件和类型使用 PascalCase，TypeScript 函数和变量使用 camelCase，Rust 函数和模块使用 snake_case。
- 源码标识符和注释使用英文，面向用户的界面文案可使用中文；需国际化的文案按设计基线管理。

## 导入规则

- 禁止懒加载导入和动态 `import()`，包括通过 `React.lazy`、路由懒加载及其他封装间接执行的动态导入。
- 所有 `import`（含类型导入和副作用导入）必须使用静态声明，集中放在文件开头、业务声明和可执行语句之前。许可证注释及框架要求的文件级指令可位于导入之前。
- 禁止在函数、条件分支、回调或业务代码中间引入依赖，也不得通过 `require()`、动态模块加载器等方式绕过限制。
- 其他语言遵循同样原则：依赖声明置于文件或所属模块开头；Rust 的 `use` 放在所属模块顶部，不放在函数体内。
- 按外部依赖、内部模块和相对路径组织导入，类型导入明确标记。避免循环依赖，通过调整模块职责解决。

## 跨平台文件路径

- Node.js 开发脚本和构建配置统一使用 `node:path`：用 `join` 拼接路径片段，用 `resolve` 生成绝对路径，用 `dirname`、`basename`、`extname` 提取路径信息。文件路径不通过字符串拼接、分隔符替换或按 `/`、`\\` 拆分处理，也不为 macOS / Windows 编写两套拼接逻辑。
- ESM 模块位置通过 `fileURLToPath(import.meta.url)` 或 `fileURLToPath(new URL(..., import.meta.url))` 转为文件路径；依赖模块位置的路径以此为基准，再用 `node:path` 解析，避免依赖启动命令所在目录。
- 比较两个本机绝对路径时使用 `relative(base, candidate) === ''`，由 `node:path` 处理当前平台的分隔符、尾部分隔符和路径段归一化，不直接比较外部返回的原始字符串。外部输入先检查字符串类型和 `isAbsolute`；需要确认符号链接指向同一实际文件时，再用 `node:fs` 的 `realpath` 解析后比较。
- 默认使用当前平台的 `node:path` 行为；仅解析明确约定为 Windows 或 POSIX 格式的外部数据时使用 `path.win32` / `path.posix`。URL 使用 `URL` API，URL 路径、模块导入标识和工具配置中的固定路径格式遵循对应协议，不当作本机文件路径处理。
- 开发服务复用校验遵循上述规则：Vite 返回的根目录可能使用 `/`，在 Windows 上须通过 `node:path` 与本机目录比较；只接受同一项目目录且 PID 合法的服务。修改路径逻辑后，验证当前服务复用、带空格的路径及不同目录拒绝场景；跨平台运行结果须分别记录。

## 文件行数限制

- 单个文件不得超过 **500 行**，按物理行数计算，包含空行、注释和测试代码。
- 新增或修改文件均须满足限制；不得通过压缩代码、合并语句或删除必要说明规避限制。
- 接近上限时按业务职责拆分组件、服务、类型或测试模块，不按任意行数切割，也不将无关代码堆入通用工具文件。
- 文件生成流程也应遵守此限制。自动生成的依赖锁文件（`package-lock.json`、`Cargo.lock`）及 Tauri 生成的权限模式文件不受 500 行限制，必须由工具生成，不可手工压缩或拆分。源代码、测试与手写配置仍严格遵守限制。

## 架构与设计模式

- 遵循单一职责、高内聚、低耦合和依赖倒置原则，模块通过小而明确的接口协作，避免循环依赖和承担多种职责的巨型模块。
- 分离界面展示、应用流程、领域规则和基础设施访问。界面组件不直接承担数据库、文件系统或进程调用逻辑；领域规则不依赖界面框架和具体存储实现。
- 功能重合度高的部分优先抽离为公共组件进行复用。新增功能前先检查现有组件，优先复用或扩展，避免复制粘贴形成多份实现。
- 界面实现优先使用 daisyUI 现有组件，并通过组合或封装构建高阶组件，不优先从零使用 Tailwind CSS 编写组件。仅在现有组件无法满足需求时，使用 Tailwind CSS 补充布局、样式或实现必要的自定义组件。
- 重复的界面结构与交互抽为公共组件，重复的状态逻辑抽为共享 Hook，重复的业务能力抽为公共服务或模块。通过明确的参数和组合表达差异，避免堆叠条件分支形成职责混杂的万能组件。
- 复用应基于一致的业务语义和行为，不能仅因外观相似强行合并；公共能力放在各使用方共同依赖的模块中，不反向依赖具体页面。
- 根据实际变化点选择设计模式：使用适配器封装外部工具与平台接口，使用仓储封装持久化访问，存在可替换算法时使用策略模式。
- 通过构造参数或显式参数注入依赖，使核心逻辑可独立验证；避免隐藏的全局可变状态和隐式依赖查找。
- 设计模式必须解决具体的职责分离、依赖隔离或扩展问题。不要为了套用模式增加无实际用途的接口、继承层级或抽象工厂。
- 新增模块时明确职责、公开接口、依赖方向及错误处理边界；涉及产品架构变化时同步更新设计文档。

## 按钮样式

- 操作按钮默认使用 daisyUI 的 `btn btn-outline` 配合语义颜色，保留必要的尺寸和形状修饰。视频库与设置页的目录管理按钮统一复用 `DirectoryActions`，样式由组件固定管理，页面不覆盖颜色、尺寸或变体。减少无颜色修饰的默认灰色按钮。同类操作在页面、卡片和弹窗中保持一致。
- 添加、开始扫描、播放和重试使用 `btn-primary`；目录访问和清除筛选使用 `btn-info`；收藏及单视频缩略图重建使用 `btn-secondary`。目录管理区域采用下述统一主色规范。
- 移除类入口使用 `btn-error`，最终移除确认使用 `btn-error`；暂停使用 `btn-warning`，继续使用 `btn-success`。
- 关闭和取消使用 `btn-neutral`；顶部导航使用 daisyUI 的 `tabs tabs-border`，路由链接使用 `tab`，当前页增加 `tab-active text-primary`。保留导航链接语义及 `aria-current`，不使用操作按钮样式。
- 卡片及其他页面中的纯图标操作统一使用 `btn btn-outline btn-xs btn-square` 配合语义颜色，图标为 14 像素，成组间距为 `gap-1.5`；复用公共 `Tooltip`，保留无障碍名称、收藏选中态及禁用状态。视频详情中的操作复用同一 `VideoActions` 图标模式，目录条目的移除操作遵循同样规格。
- 视频库与设置页的“添加目录”“重新扫描”“重建缩略图”保持相同的较大规格：`btn btn-primary btn-soft btn-md`、18 像素图标及 `gap-3`。文字已说明用途，不提供 `Tooltip` 或原生 `title` 提示，不随卡片按钮一起缩小。`LibraryHeader` 继续统一预留标题及操作槽高度。
- 其余有文字的操作按钮使用 `btn-sm`，若附带图标则使用 14 像素图标；设置页、弹窗、错误反馈和扫描控制保持相同规则。语义颜色适配亮色和暗色主题。

- 弹窗中的文字操作按钮统一使用 `btn btn-soft btn-md`，与页面目录操作保持一致；添加与确定使用 `btn-primary`，取消与关闭使用 `btn-neutral`，删除使用 `btn-error`，扫描暂停与继续分别使用 `btn-warning`、`btn-success`。按钮组使用 `items-center gap-3`，附带图标使用 18 像素；此规则优先于上述弹窗 `btn-sm` 约定。

## 错误通知

- 所有页面、设置保存、目录操作及启动失败统一使用浮动错误通知，不将错误信息直接插入页面容器占用布局空间。
- 业务错误通过 `ErrorNotice` 翻译后交给公共 `ErrorToast`，采用 daisyUI“Alert with title and description”结构，包含错误图标、标题、说明及可用的排查编号；保留重试和关闭操作，不自动隐藏待处理的错误。
- `useNotificationHost` 将通知通过 Portal 挂到右上角 `toast toast-top toast-end` 容器，多条错误在同一容器堆叠。存在原生对话框时，宿主移入当前打开的对话框，关闭后回到页面根部，避免通知被顶层弹窗遮挡或无法操作。
- 保留 `role="alert"`、本地化及按钮无障碍名称。通知出现、关闭、切换语言或重试不得推动标题、筛选栏和视频内容；卸载时清理宿主及观察器。
- 验证页面外渲染、多错误堆叠、关闭和重试回调、对话框开启/关闭，以及现有语言切换和未知错误回退测试。

## 下拉选择框

- 按 daisyUI 官方结构将 `select` 类直接加在原生 `<select>` 上，由组件负责边框、箭头、焦点与禁用样式；不把 `select` 类放在外层标签后再对内部控件设置 `border-0` 或 `outline-none`。
- 带前置图标时，外层仅负责定位；装饰图标设置 `aria-hidden` 与 `pointer-events-none`，控件通过内边距留出图标位置。可访问名称设置在实际 `<select>` 上。
- 原生选项菜单的外观受浏览器与系统影响，不通过破坏标准控件结构强行模拟。官方参考：https://daisyui.com/components/select/。

## 路由与页面组合

- `App` 负责应用级提供者、全局顶部导航及路由配置；导航下方通过 React Router 渲染 `src/pages/` 中的独立页面。页面内容由页面组件组合，不在 `App` 内按路径条件拼装。
- 视频库、收藏、最近播放页面分别嵌入 `LibraryHeader`，通过参数适配标题、操作按钮和筛选状态；共同行为复用 `useVideoPageView`、`VideoPageContent` 和 `PageFrame`。设置页单独组合自身内容。
- `LibraryHeader` 的标题与操作插槽统一设置最小高度，无操作按钮时仍保留空插槽；桌面及窄屏下，同一窗口宽度的页面切换应保持标题区、筛选栏和视频数量的纵向位置一致。
- 共享的查询、扫描及事件订阅由应用级 `LibraryProvider` 持有；页面消费上下文，不重复调用 `useLibrary` 创建订阅。页面自身的选中项、菜单和弹窗状态随页面卸载清理。
- 新增或调整路由后，验证直接访问、导航切换、对应页面操作入口和状态保留策略；未知路径明确回到视频库。

## 测试与检查

前端采用 Vitest 与 React Testing Library，后端采用 Rust 标准测试框架，尚未设置覆盖率门槛。实现功能时添加与风险匹配的测试，并记录运行方式。前端测试使用 `*.test.ts` 或 `*.test.tsx` 命名，后端采用 Rust 标准测试模块。

依据设计文档覆盖关键行为、边界条件和异常路径；使用临时目录和小型测试样本。测试应验证对外行为，避免仅复刻实现细节。

建立开发工具链时，应加入静态导入检查、动态加载禁用检查和文件行数检查，并纳入持续集成。提交前运行已有的相关检查；尚未配置或无法执行的检查应如实说明。

## 当前后端验证命令

在仓库根目录运行：

- `cargo check --manifest-path src-tauri/Cargo.toml`：检查桌面后端编译。
- `cargo fmt --manifest-path src-tauri/Cargo.toml -- --check`：检查 Rust 格式。
- `cargo test --manifest-path src-tauri/Cargo.toml`：运行 Rust 标准测试。

当前仓储回归测试覆盖扫描后重开数据库、重复索引保留身份与收藏/播放状态、删除文件标记不可用、恢复文件、移除索引保留原文件，以及非法扫描路径。

媒体工具集成验证：`cargo test --manifest-path src-tauri/Cargo.toml -- --include-ignored`。
该命令需要本机 `PATH` 中存在 `ffmpeg` 和 `ffprobe`，会生成半秒测试视频，验证元数据、JPEG 缩略图和损坏文件错误。普通测试命令不要求安装媒体工具。

Windows x64 开发时优先使用 `resources/ffmpeg/windows-x86_64/` 中的完整 FFmpeg / FFprobe 工具对，缺少时使用 PATH；其他平台开发时继续使用 PATH。Windows 发布版固定使用安装资源目录内的工具，不依赖用户的 PATH。工具放置及许可证文件要求见[媒体工具说明](../resources/ffmpeg/windows-x86_64/README.md)。

在根目录执行 `npm exec tauri build` 生成 Windows 安装包；`tauri.windows.conf.json` 自动合并资源映射，发布构建检查 `ffmpeg.exe`、`ffprobe.exe` 和 `LICENSE.txt` 是否存在。`npm run build` 仅构建前端。二进制未纳入 Git，打包机器须事先准备。其他平台的内置工具分发尚未接入。

Windows PowerShell 中只生成 NSIS 安装包时，执行 `& .\node_modules\.bin\tauri.cmd build --bundles nsis`，输出到 `src-tauri/target/release/bundle/nsis/`。直接调用本地 CLI 可确保 `--bundles` 参数传给 Tauri。若主程序已构建成功，仅需重试打包步骤，可执行 `& .\node_modules\.bin\tauri.cmd bundle --bundles nsis`。

扫描先写入基础索引，再处理媒体字段；缩略图位于应用数据目录下的 `thumbnails` 子目录。媒体处理失败通过 `media-error` 事件返回结构化业务错误。

## 前端工具链

网页入口、源码、静态资源、Vite / Vitest / TypeScript 配置及网页验收夹具统一位于 `frontend/`。Tauri 原生工程位于同级的 `src-tauri/`。根目录保留共享 npm 工具链与统一命令，以下命令均在仓库根目录执行。

统一使用 npm 11，提交 `package-lock.json`。已验证：

- `npm install --registry=https://registry.npmmirror.com --no-audit --no-fund`：安装依赖（当前环境官方源出现 TLS 错误，使用镜像源成功）。
- `npm run build`：TypeScript 检查及 Vite 生产构建，输出到 `frontend/dist`。

已配置 `npm run dev`（Vite）、`npm run desktop`（Tauri 开发）与 `npm run format`（Prettier）；桌面运行及界面交互仍需进一步验证。前端 API 类型集中于 `frontend/src/shared/api.ts`，页面后续通过该模块调用 Rust 命令，避免自行拼装协议。

目录选择采用 Tauri 官方 `tauri-plugin-dialog`，前端使用对应插件包。主窗口权限配置位于 `src-tauri/capabilities/main.json`，允许原生打开对话框及核心事件操作；目录扫描仍由 Rust 命令执行。添加目录弹窗使用原生 HTML 对话框管理焦点，目录列表在扫描前支持去重和移除。

## 自动检查

`npm run check` 验证文件行数、JavaScript/TypeScript 导入位置、动态加载禁用、翻译键/插值参数、Rust 错误翻译覆盖和前端格式。

`cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings` 执行严格 Rust 静态检查。

上述检查已在本机通过。`.github/workflows/check.yml` 配置 macOS 持续集成，执行依赖安装、前端检查与构建、Rust 格式、测试及 Clippy；远端运行结果须以实际流水线记录为准。

前端测试使用 Vitest、jsdom 和 React Testing Library。`npm test` 执行组件交互测试，覆盖错误提示切换语言、未知错误回退、卡片双击和不可用文件播放保护；该命令已加入持续集成。组件测试不替代真实 Tauri 桌面端到端验证。


## 独立网页验收

运行 `npm run dev -- --host 127.0.0.1`，在浏览器打开 `http://127.0.0.1:5173/acceptance/web-acceptance.html`。此入口使用同一 React 页面、Tauri 官方模拟通信及固定测试数据，适合布局、筛选排序、弹层和错误文案验收；不连接真实数据库，也不替代 Rust 或系统集成测试。生产构建仍仅使用 `frontend/index.html`。

可在浏览器控制台执行 `window.enjoyAcceptance.setScan('processing')`、`setScan('paused')` 或 `setScan('cancelled')`（后两者同样通过 `window.enjoyAcceptance` 调用），发送对应扫描状态。点击播放固定返回系统打开失败业务错误，以验证本地化提示和重试入口。当前夹具只支持验收所需命令，未支持的命令会报错，不应据此判断生产后端失败。


## 标志与应用图标

原图及 1024 像素图标源图放在 `assets/brand/`，页面仅使用 `frontend/public/assets/generated/` 内裁切后的标志资源，避免原图留白影响导航尺寸。执行 `python3 scripts/generate-brand-assets.py` 生成页面标志和 1024 像素图标源图；该脚本依赖 Python Pillow，仅生成资源时需要。

再运行 `npx tauri icon assets/brand/app-icon.png --output /tmp/enjoy-brand-icons`，将生成目录中的 `32x32.png`、`128x128.png`、`128x128@2x.png`、`icon.png`、`icon.icns`、`icon.ico` 复制到 `src-tauri/icons/`。配置中的图标列表包含 macOS、Windows 和 Linux 使用的格式。运行 `npm exec tauri build -- --debug --bundles app` 验证 macOS 应用包；本次构建已确认 `Contents/Resources/icon.icns` 存在。


## VS Code 启动

在 VS Code 的“运行和调试”下拉菜单选择配置并按 F5：

- `前端开发：Vite`：执行 `npm run dev`，启动 Vite 开发网页服务，默认地址为 `http://127.0.0.1:5173/`。
- `桌面端开发：Tauri`：执行 `npm run desktop`，启动 Tauri 开发环境。Tauri 会依据 `tauri.conf.json` 的 `beforeDevCommand` 检查并启动或复用 Vite 服务，再由桌面窗口加载 `devUrl`。

这两个配置只负责启动开发脚本，不负责启动 Chrome 或打开网页验收入口。网页和桌面端可以同时运行并共享同一个 Vite 服务；需要停止共享服务时执行 `npm run dev:stop`。打包时执行 `npm exec tauri build`，页面从 `frontendDist` 指定的内置 `frontend/dist` 加载。


## 视频内容虚拟滚动

修改视频库、收藏、最近播放的布局或渲染逻辑时，必须遵守以下约束。产品范围参见[开发基线](本地视频统一启动器-开发基线.md)，滚动条的标准行为及兼容性依据参见[滚动条占位资料核对](滚动条占位-资料核对.md)。

### 滚动区域边界

- 应用采用固定视口高度，父级通过 `min-height: 0` 等约束将剩余高度交给内容区，页面根节点不产生纵向滚动条。
- 全局导航、页面标题、操作按钮、筛选工具栏及视频数量放在滚动容器外。仅下方视频网格滚动，视频数量不得随内容滚出视野。
- 设置页内容和空状态使用各自的滚动容器。局部滚动不得带动整个窗口或形成重复的纵向滚动区域。

### 虚拟渲染与测量

- 单个视频卡片统一复用 [VideoCard](../frontend/src/features/library/VideoCard.tsx)，页面不复制卡片布局或直接处理滚动范围。
- 通用虚拟集合逻辑统一复用 [useVirtualCollection](../frontend/src/shared/useVirtualCollection.ts)：接收数据、稳定标识、列数和估算行高策略，返回可见行数据、偏移、总高度、上下占位和测量接口。Hook 不依赖路由或视频领域，内部统一处理尺寸观察及缓冲行；展示组件按返回的数据渲染。
- 视频数据读取由应用级 `useLibrary` 统一执行，页面通过 `useVideoPageView` 复用筛选、排序及滚动重置标识。筛选与目录选项按数据变化缓存；各页面只传入集合标识，不重复维护分页、请求或滚动状态。
- 所有视频页面仅使用卡片网格，不提供列表视图或其切换按钮；统一复用 [VirtualVideos](../frontend/src/features/library/VirtualVideos.tsx)，使用 `@tanstack/react-virtual`，仅挂载可见行及前后各 3 行缓冲；挂载数量应随可见区域大小变化，而非随视频总量增长。缩略图随可见项挂载，保留延迟加载。
- 虚拟网格内容统一复用 [VirtualGrid](../frontend/src/shared/VirtualGrid.tsx)，列数断点和 20 像素行列间距集中维护于该模块的 `virtualGridLayout`。内容宽度达到 800 像素时每行 4 个，600、400 像素分别为 3、2 个，更窄为 1 个；页面不单独定义网格排版。
- 网格按实际可用内容宽度分列。计算宽度时扣除原生滚动条槽及容器内边距，不直接将窗口宽度或未扣除内边距的 `clientWidth` 用作内容宽度。
- 估算行高只用于初始化，实际行高必须测量。窗口尺寸、列数或语言变化后重新测量，兼容长文件名、按钮换行和缩略图状态变化，避免重叠、裁切及异常行间空白。
- 使用稳定的视频标识作为虚拟项身份；按网格行分组时使用该行首个视频的标识。通过网格总高度和虚拟行偏移确保末项可达。
- 虚拟滚动的顶部偏移只包含滚动容器内部的前置内容。视频数量已在容器外，不能再计入偏移；移动前置元素时同步更新偏移与测试。
- 切换页面、筛选条件或排序时重置内容滚动位置。滚动时关闭右键菜单；播放、收藏、详情、键盘及不可用文件保护等交互在虚拟化后仍须有效。
- 当前视频索引一次读取，用于本地筛选和排序；虚拟滚动优化的是界面节点及缩略图挂载，不代表后端分页或索引按需读取。引入分页时另行更新数据接口与设计基线。

依赖通过 `npm install @tanstack/react-virtual --registry=https://registry.npmmirror.com --no-audit --no-fund` 安装并更新锁文件。

## 滚动条占位与兼容处理

- 视频内容、空状态及设置页统一复用 [ScrollViewport](../frontend/src/shared/ScrollViewport.tsx)。将 `overflow` 与 `scrollbar-gutter: stable` 设置在实际滚动元素上；只给外层或 `body` 设置该属性不能替代局部容器配置。
- `stable` 为传统滚动条预留原生槽，但不会为 macOS 覆盖式滚动条占位，`both-edges` 也不解决覆盖式占位。不能仅凭属性声明或 `CSS.supports` 返回成功判定问题解决。
- 共享样式位于 [style.css](../frontend/src/style.css)。尾侧安全区域以 20 像素为目标，补偿内边距按 `max(0px, 20px - 原生槽宽)` 计算。原生槽宽为容器 `offsetWidth - clientWidth - 左右边框宽度`，由 `ResizeObserver` 观察尺寸变化并更新。
- 传统模式使用原生槽加差额补偿，覆盖模式补足安全留白，避免滚动条展开遮挡内容。原生槽超过 20 像素时保留完整系统槽宽，补偿为零；20 像素是应用布局策略，不是所有平台的原生滚动条宽度。
- 占位规则由共享容器统一维护，各页面不另加重复的固定右内边距。观察器卸载时必须清理，补偿更新不得造成持续的尺寸观察循环。
- 不支持 `scrollbar-gutter` 的引擎通过 `@supports not` 回退为 `overflow-y: scroll`。该回退仅解决传统滚动条槽，覆盖式模式仍需安全留白。
- 应用不得通过修改用户系统滚动条偏好解决布局问题。

## 滚动功能验证

修改上述逻辑后，运行 `npm run build`、`npm run check` 和 `npm test`。虚拟滚动回归测试使用 1,203 条视频数据，覆盖网格的有限挂载、滚动替换可见项、末项可达及筛选后位置重置。模拟布局测试不替代真实窗口布局验证。

真实窗口验收须覆盖：空内容与溢出内容切换、不同视频页面切换、窗口缩放、长文件名、传统与覆盖式滚动条、鼠标悬停展开。记录容器和内容的实际宽度，检查固定区域不移动、内容不被遮挡、卡片无重叠及异常空白、根节点不产生额外滚动。无法完成的场景须明确说明。

macOS 下先启动 `npm run dev`，再分别执行以下命令。脚本用原生 `WKWebView` 加载实际网页验收入口，断言原生槽与补偿间距之和为 20 像素，并输出内容宽度。滚动条偏好仅通过测试进程启动参数传入，不修改用户系统设置。

- `swift scripts/check-scrollbar.swift http://127.0.0.1:5173/acceptance/web-acceptance.html -AppleShowScrollBars Always`
- `swift scripts/check-scrollbar.swift http://127.0.0.1:5173/acceptance/web-acceptance.html -AppleShowScrollBars WhenScrolling`

既有本机验证中，两种模式均测得内容宽度 1,058 像素；传统模式槽宽 17 像素、补偿 3 像素，覆盖模式槽宽 0 像素、补偿 20 像素。该数值是当时窗口尺寸下的证据，不是所有窗口的固定宽度要求。脚本的 20 像素断言适用于原生槽不超过 20 像素的环境；更宽的系统槽按原生宽度验收。该检查不替代物理鼠标接入和悬停展开的人工检查。

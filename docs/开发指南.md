# 开发指南

本指南适用于所有贡献者和自动化代理。具体产品功能与软件设计参见[本地视频统一启动器开发基线](本地视频统一启动器-开发基线.md)，此处统一维护开发约束。

## 开发环境与命令

项目已配置前端和桌面开发、构建、静态检查及测试命令，具体命令见下文。环境及依赖版本遵循设计基线。

统一使用 npm 并维护锁文件；新增项目配置时，在本指南中记录经过验证的依赖安装、桌面开发、生产构建、静态检查和测试命令。引入可执行代码时，同步补充格式化和静态检查配置。

## 编码风格与命名

- TypeScript 使用两个空格缩进，Rust 使用四个空格缩进；配置自动格式化工具后统一由工具执行。
- React 组件和类型使用 PascalCase，TypeScript 函数和变量使用 camelCase，Rust 函数和模块使用 snake_case。
- 源码标识符和注释使用英文，面向用户的界面文案可使用中文；需国际化的文案按设计基线管理。
- **界面文字不以句号收尾**（中英一致）：提示、通知、错误说明、确认框都算。一条提示不是一个段落，末尾的句号只让它读起来像某段更长的话被截了一段。多句之间照常使用句号与逗号，问句保留问号——规则只管最后一个字符。唯一的例外是落地页正文（`native.shareLandingBody`）：那是一段给人读的散文，句号是它的标点；例外按名字写在 `check-translations.mjs` 里，下一次要有第二段散文就得显式加进去，而不是让它从某个模式里溜过。

## 导入规则

- 禁止懒加载导入和动态 `import()`，包括通过 `React.lazy`、路由懒加载及其他封装间接执行的动态导入。
- 所有 `import`（含类型导入和副作用导入）必须使用静态声明，集中放在文件开头、业务声明和可执行语句之前。许可证注释及框架要求的文件级指令可位于导入之前。
- 禁止在函数、条件分支、回调或业务代码中间引入依赖，也不得通过 `require()`、动态模块加载器等方式绕过限制。
- 其他语言遵循同样原则：依赖声明置于文件或所属模块开头；Rust 的 `use` 放在所属模块顶部，不放在函数体内。
- 按外部依赖、内部模块和相对路径组织导入，类型导入明确标记。避免循环依赖，通过调整模块职责解决。

## 跨平台文件路径

- Node.js 开发脚本和构建配置统一使用 `node:path`：用 `join` 拼接路径片段，用 `resolve` 生成绝对路径，用 `dirname`、`basename`、`extname` 提取路径信息。文件路径不通过字符串拼接、分隔符替换或按 `/`、`\\` 拆分处理，也不为 macOS / Windows 编写两套拼接逻辑。
- ESM 模块位置通过 `fileURLToPath(import.meta.url)` 或 `fileURLToPath(new URL(..., import.meta.url))` 转为文件路径；依赖模块位置的路径以此为基准，再用 `node:path` 解析，避免依赖启动命令所在目录。
- 比较两个本机绝对路径时使用 `relative(base, candidate) === ''`，由 `node:path` 处理当前平台的分隔符、尾部分隔符和路径段归一化，不直接比较外部返回的原始字符串。外部输入先检查字符串类型和 `isAbsolute`；需要确认符号链接指向同一实际文件时，再用 `node:fs` 的 `realpath` 解析后比较。
- 默认使用当前平台的 `node:path` 行为；仅解析明确约定为 Windows 或 POSIX 格式的外部数据时使用 `path.win32` / `path.posix`。URL 使用 `URL` API，URL 路径、模块导入标识和工具配置中的固定路径格式遵循对应协议，不当作本机文件路径处理。
- 开发服务复用校验遵循上述规则：Vite 返回的根目录可能使用 `/`，在 Windows 上须通过 `node:path` 与本机目录比较；只接受同一项目目录且 PID 合法的服务。修改路径逻辑后，验证当前服务复用、带空格的路径及不同目录拒绝场景；跨平台运行结果须分别记录。

## 文件行数限制

- 单个文件不得超过 **500 行**，按物理行数计算，包含空行、注释和测试代码。
- 新增或修改文件均须满足限制；不得通过压缩代码、合并语句或删除必要说明规避限制。
- 接近上限时按业务职责拆分组件、服务、类型或测试模块，不按任意行数切割，也不将无关代码堆入通用工具文件。
- 文件生成流程也应遵守此限制。自动生成的依赖锁文件（`package-lock.json`、`Cargo.lock`）及 Tauri 生成的权限模式文件不受 500 行限制，必须由工具生成，不可手工压缩或拆分。源代码、测试与手写配置仍严格遵守限制。

## 架构与设计模式

- 遵循单一职责、高内聚、低耦合和依赖倒置原则，模块通过小而明确的接口协作，避免循环依赖和承担多种职责的巨型模块。
- 分离界面展示、应用流程、领域规则和基础设施访问。界面组件不直接承担数据库、文件系统或进程调用逻辑；领域规则不依赖界面框架和具体存储实现。
- 功能重合度高的部分优先抽离为公共组件进行复用。新增功能前先检查现有组件，优先复用或扩展，避免复制粘贴形成多份实现。
- 界面实现优先复用 `frontend/src/shared/ui/` 下的 shadcn/ui 原语，并通过组合或封装构建高阶组件，不优先从零使用 Tailwind CSS 编写组件。仅在现有组件无法满足需求时，使用 Tailwind CSS 补充布局、样式或实现必要的自定义组件。原语清单与各自的变体、尺寸及取代的 daisyUI 组件见[界面通用组件清单](界面通用组件清单.md)。
- 重复的界面结构与交互抽为公共组件，重复的状态逻辑抽为共享 Hook，重复的业务能力抽为公共服务或模块。通过明确的参数和组合表达差异，避免堆叠条件分支形成职责混杂的万能组件。
- 复用应基于一致的业务语义和行为，不能仅因外观相似强行合并；公共能力放在各使用方共同依赖的模块中，不反向依赖具体页面。
- 根据实际变化点选择设计模式：使用适配器封装外部工具与平台接口，使用仓储封装持久化访问，存在可替换算法时使用策略模式。
- 仓储这类按种类建立的类型不把全部方法堆在定义文件里：同一类型的实现在同级按职责分散（`repository/scans.rs` 是扫描写回，`repository/videos.rs` 是一条记录，`repository/spaces.rs` 是空间），定义文件只保留类型、打开方式和共享的锁与判据。调用方按职责找文件，而不是从一个整块接口里逐条找。
- 通过构造参数或显式参数注入依赖，使核心逻辑可独立验证；避免隐藏的全局可变状态和隐式依赖查找。
- 一个行为若取决于「只有后端才知道的事实」，决定就放在后端，界面只负责把它画出来、把答案发回去：界面为一件自己掌握不了信息的事负责时，正确性会散成好几处（什么时候问、要不要拦下、谁来收尾、要什么授权），而每一处都只在运行时才知道错。关窗就是这么改的（[ADR 0015](adr/0015-关窗的决定在后端而界面只回答确认.md)）；同形的还有空间相关命令一律显式带 `spaceId`。
- 设计模式必须解决具体的职责分离、依赖隔离或扩展问题。不要为了套用模式增加无实际用途的接口、继承层级或抽象工厂。
- 新增模块时明确职责、公开接口、依赖方向及错误处理边界；涉及产品架构变化时同步更新设计文档。

## 按钮样式

- 操作按钮一律是 `shared/ui/button` 的 `Button`，语义由 `variant` 决定，只有 `primary` 是默认值，因此「什么都不说」就等于主色——它留给每个界面那一个着力的动作。视频库与设置页的目录管理按钮统一复用 `DirectoryActions`，样式由组件固定管理，页面不覆盖颜色、尺寸或变体；两处唯一的差别由组件自己的 `iconOnly` 表达（视频库取图标形态、设置页取带文字的大按钮，见本节末条），而不是两页各写一套。同类操作在页面、卡片和弹窗中保持一致。
- 每个变体都自带一层不透明的底色，看起来没填色的两个也不例外：`outline` 与 `ghost` 取 `--background`，也就是窗口点阵画在其上的那一层的颜色。这层底色的用途是挡住底下的点，而不是给这两个变体存在感——`--background` 就是页面本来的颜色，与 `--card` 只差几级，所以调用方拿到手的还是原来那个按钮，只是背后没有东西了（[ADR 0022](adr/0022-整个应用的背景用一层静态点阵.md)）。唯一的例外是 `link`：它不画形状，文字背后的点与四周的点是同一片，填上底色等于把链接变成一个按钮。
- 变体按语义选：「添加」「开始扫描」「播放」「重试」用 `primary`；「目录访问」与「清除筛选」用 `info`；「收藏」与单视频缩略图重建用 `secondary`；暂停用 `warning`，继续用 `success`。**一处例外**：目录操作的「添加」与「扫描」在视频库取图标形态，那里按图标按钮的规格用 `outline`（详见下一条），设置页的同一组操作仍是 `primary`。
- 移除类入口与最终移除确认都用 `destructive`，但重量不同：入口本身通常是一个图标按钮，形状取 `outline`（站在底色上时取 `ghost`），红色只作文字色（`text-destructive`）；**填色的 `destructive` 只给那一次真正的确认**。同一屏里出现两个一样重的红，就等于没有强调。
- 关闭与取消这一档，旧库里叫 `neutral`，新库没有这个变体，**本仓库取 `secondary`**：取消是一个有形状、有底色的按钮，只是不着重；`outline` 与 `ghost` 在浅色底上几乎不成形（两者各带一层不透明的 `--background`，只是那正是页面自己的颜色），放在一列按钮的末尾读起来不像一个可点的东西。因此 `outline` 只在需要边框定形的地方用（空间切换器的触发器、图标按钮），不作为一档语义色。
- 顶部导航使用 `shared/ui/tabs` 的 line 模式，路由链接保留链接语义及 `aria-current`，不使用操作按钮样式。**五个入口各带一个 14 像素前置图标**（与上一条的图标规格同源），图标是装饰：`aria-hidden` 与 `pointer-events-none`，**不进入入口的可访问名**——入口的名字只有那两个字，读屏与测试都按这个名字取它。其中「收藏」与「共享」刻意复用视频卡片上那两枚同义图标（`VideoActions` 的心形、`VideoBadges` 的分享），免得同一个意思有两枚图标要学；五个图标的选取、排除与代价见 [ADR 0024](adr/0024-页头导航项加前置图标.md)。选中项的横线由 `MainNav` 自己画，原语里横向那条静态下划线已经删掉：横线要在入口之间滑动，而 Radix 把选中态写在 DOM 的 `data-state` 上、触发器在 React 里读不到自己选没选中，所以只有本来就拿得到当前路由的调用方能渲染它。横线在切换时是滑过去的（`layoutId`），系统「减少动态效果」打开时直接到位。原语里纵向那档（连它那条静态下划线）**已无生产调用点**：设置页左列不再是纵向 `Tabs`，而是按需移植的 shadcn `Sidebar`（[ADR 0023](adr/0023-设置页改用-shadcn-的-sidebar-与-rubber-segment.md)），现在只有页头这条横向导航在用 `Tabs`。
- 卡片及其他页面中的纯图标操作统一用 `outline` + `icon-sm`，图标 14 像素，成组间距 `gap-1.5`；语义色同样只作文字色。**常驻的纯图标控件都给提示**——常驻可见、脸上只有一枚图标、可点击的控件，一律经公共 `Tooltip` 补一句，不再判断「这枚图标说明不了自己」（那条判据靠主观，实测漏掉了对话框与抽屉的关闭按钮这类最该有提示的控件）。无障碍名称（`aria-label`）无论如何都要有，提示**不替代**它，收藏选中态与禁用状态一并保留。视频详情中的操作复用同一 `VideoActions` 图标模式。目录条目的移除按钮也遵循这个形状，只是它的说明不是悬停提示而是就地弹出的那句问话——话已经在屏幕上了。
- 视频库与设置页的目录管理按钮是同一个组件（`DirectoryActions`）的两个形态，由页面传 `iconOnly` 选。在视频库它是**纯图标按钮组**：`outline` + `icon-sm` + 14 像素图标 + `gap-1.5`，逐条遵循上一条的图标按钮规格，动作名移进公共 `Tooltip`，而 `aria-label` 与设置页那句文字取同一个值——名字不随外形改。在设置页的「视频目录」区它仍是默认（`primary`）变体、`size="lg"`、18 像素图标及 `gap-3`：文字已经说明用途，因此不提供 `Tooltip`。「建缩略图」只在设置页出现，保持大规格。工具栏那一行由 `LibraryToolbar` 统一承载页面操作、筛选与视图模式，行高由其中最高的控件决定，不再为标题预设高度。缘由与代价见 [ADR 0025](adr/0025-视频库去掉标题行与目录图标按钮组.md)。
- 其余有文字的操作按钮用 `size="sm"`，若附带图标则使用 14 像素图标；设置页、错误反馈和扫描控制保持相同规则。
- 弹窗中的文字操作按钮统一用 `size="lg"`，与页面目录操作保持一致：添加与确定用 `primary`，取消与关闭用 `secondary`，删除用 `destructive`，扫描暂停与继续分别用 `warning`、`success`。按钮组使用 `items-center gap-3`，附带图标使用 18 像素；此规则优先于上述弹窗 `size="sm"` 约定。
- 变体名与尺寸名是其他工单要 import 的契约，已镜像到 `data-variant`／`data-size`：要钉住「用了哪一个」就断言这两个属性，不要断言 class——class 随视觉语言变，而变体名不该跟着变。

## 提示

- 悬停或聚焦触发的浮层说明一律走公共 `Tooltip`（`shared/Tooltip.tsx`，底下是 `shared/ui/tooltip` 的 Radix 实现）。它与就地弹出的 `Popover`（点击触发，目录条目与空间切换器用它）、以及与顶部那一秒的短提示（`Hint`，见「短提示」一节）是三样东西，不要混用。该给哪些控件加提示见上一节「按钮样式」的判据：常驻的纯图标控件都给提示。
- 那条判据的**边界**：「常驻」是会自己消失的东西不算——**通知（`Toast`）的关闭按钮不给提示**，它随通知一起消失，不是一直站在屏上的那类控件。判据也不覆盖下列各处，它们**保持安静**：卡片缩略图上的播放浮层（它本身就是悬停才出现的）、空间切换器的触发按钮（名字就写在脸上，且这是既有成文决定）、目录条目的移除按钮与删除空间的按钮（按下就地弹出问句，话已经在屏幕上，同属既有成文决定）。
- **原生 `title` 不得作为提示**：说明写在 `title=` 上，浏览器会画它自己那个灰框——不随主题、不随界面语言排版、出现时机由系统决定，和站内浮层并排出现一眼就是两种东西。`npm run check` 的头一环 `scripts/check-source.mjs` 遍历每个 `.tsx` 的 AST，见到 JSX 上的 `title=` 即失败，报错直接指出提示请用 `shared/Tooltip`。只有内容标题类的组件按名字放行——`EmptyState` / `SettingsSection` / `Drawer` / `SpaceDialog` / `EmptyRescanConfirmation`，它们的 `title` 是内容标题参数，不是提示。
- 提示文案与控件的无障碍名同值，**除非该元素所在的那一行已经把这个值显示在屏幕上**：那种情况下提示只取短词，而无障碍名仍保留完整值（读屏器看不见行，无法自行区分一排长得一样的按钮）。适用后半个分句的**只有两处**：添加目录弹窗里每一行的删除按钮——那一行已经写着路径，提示只说「移除」，读屏器听到的名字仍带路径；以及共享状态胶囊（`ShareStatusPill`）——屏上已经写着它的状态（「局域网在线」），而指针问的是**另一件事**：服务在**哪里**，所以提示给的是端口（`sharingOn` 那句），与无障碍名**不同值**。后一处不是「行里已经显示了那个值」，而是「指针问的与名字答的不是同一个问题」。
- 延迟分两类节奏。**控件标签**类取 **0ms**，与仓库现有全部调用点一致：视图切换的三段、播放、关闭、删除、卡片角标、共享状态胶囊——这些提示是「指针已经落在的那个控件」的名字，应当立刻应答。**补全被截断的全文**类取 **700ms**：表格的路径列、扫描与建缩略图进度条上被截断的文件名。这三处替换后触发器面积大得多（路径列是整个单元格，一张表几十行），0 延迟会让指针扫过时一路弹字；700ms 是 Radix 自己的默认值，也最接近原生 title 的手感——用户今天停在路径列上等一秒同样会看到系统灰框，换成站内浮层后交互节奏一个字没动。为什么这里不是 0，同一条说明也写在 `shared/Tooltip` 与那几处调用点的注释里。
- 挂在只读文本上的提示（路径单元格、进度条文件名、卡片上的共享角标）**不给这些元素加 `tabIndex`**：把只读元素塞进 Tab 序列是明确的对方模式。代价如实记——用键盘的用户仍拿不到被截断的全文，这一点与今天持平，本次不改善。交互类控件（按钮）在聚焦时也出提示，这是 Radix 本来的行为，不需要额外处理。

## 通知

- 失败显示在哪，由**用户此刻还在看的那个表面**决定，两种都正当：失败是关于整个库的、或者触发它的控件已经不在了（页头的按钮、启动失败、库整体读取失败）→ 浮动通知；失败是关于用户刚输入或刚选的**那个值**的（对话框里的名字、设置项里的语言与主题）→ 留在原处，和那个值放在一起，因为要改的正是它，重试也应该重放它。页面正文不插错误条这条仍然成立：所谓原地，指的是对话框或设置项内部，不是页面容器里的一条报错。
- 跑这套形状的代码是 `useCommand`：它拥有「一次命令跑一次」——跑的时候 busy，结束时把规范化后的失败连同**被尝试时的那个值**一起留下（重试要重放那个值，不是读当前值），成功之后的动作写在 action 里因为失败的 action 会在那里停下。失败去向由调用方选：交给 `onFailure` 就是浮动通知（`AddDirectories` 这样用），不交给它就渲染返回的 `failure`（两个设置项与空间对话框这样用）。三处不归它管，且各有理由：`useLibrary.run` 还拥有库的通知槽与重读，`useUpdate` 的五次拥有的是一次传输的各个阶段，都不是「一次命令」；`MaintenanceButton` 只借一个 busy 标志位，因为它的失败由动作自己上报。
- 所有通知复用公共 `Toast`，外观由类型决定。类型词表覆盖 `success`、`error`、`info`、`warning`，对应 daisyUI 原生 alert：亮色主题用实心的 `alert-{类型}`，暗色主题在其上叠 `alert-soft`。`dark` 变体在本仓库跟随 `data-theme`（见 `style.css` 的自定义变体），不是系统偏好。柔和配色用色调本身作文字色，压在亮色的近白底上只有 2.6:1 左右，故只在暗色保留。类型到配色、图标和 ARIA 角色的映射用查找表表达，组件内不按类型分支；词表可以包含暂无调用点的类型，但不为其创建组件。
- 倒计时画在通知外框自己的底边上，是一条通栏细线，不放进正文。正文里一条与内容等宽的横条读起来是「任务进度」，而通知报告的不是进度，是它自己的剩余时间；落到外框上，正文保持纯文字，收缩的线属于通知本身而不属于它的内容。这条线用外框自己的前景色（`bg-current`），因此亮色取该类型的 `-content`、暗色柔和主题取色调本身。它不是 daisyUI 的 `.progress`：`.progress` 用 `currentColor` 画填充、用同色 20% 画轨道，而实心通知的底色正是该色调；改画在底边上后连 `progress-{类型}` 也不需要了。细线靠一个 `absolute inset-0 overflow-hidden rounded-box` 的包裹层裁掉圆角，裁剪不能加在通知本体上——`overflow-hidden` 会连带吃掉关闭按钮的焦点轮廓。
- 配色类必须写成完整字面量，不得用模板拼接（如 `alert-${type}`）。Tailwind 只生成能看到字面量的工具类，拼接出来的类不会产生任何样式。
- 细线的收缩交给浏览器，不逐帧写宽度：整条线按通栏宽度绘制，用 `transform: scaleX()` 从 1 缩到 0，动画时长取剩余时间、缓动 `linear`、`fill-mode: forwards`（少了它会到期与通知消失之间弹回满宽），`@keyframes` 放在 `style.css`，只有时长与暂停随运行时变化。原先的写法是每个 tick 由 React 写一次宽度：3 秒的完成统计只走 30 步、每步约 15 像素，看到的是一级级台阶；而且每步都要等主线程，扫描刚结束时轮询、列表与缩略图正在占它，迟到的 tick 按时间戳一次性补上，台阶还会忽大忽小。`transform` 动画由合成器执行，主线程忙不影响它，也不再每步触发一次重排。暂停与计时器共用一个状态：悬停或聚焦时把 `animation-play-state` 置为 `paused`，线停在原处、移开从剩余线长处继续，与「悬停暂停、移开从剩余时间继续」是同一件事。不要因 `prefers-reduced-motion` 关掉它：这条线不是入场装饰，它表示通知还剩多久。
- `Toast` 只负责外层框架：容器、类型图标、关闭按钮、子节点插槽，以及给定时长时的倒计时与那条细线。正文（标题、说明、排查编号、重试按钮）及各自回调由调用方以子节点提供，因此通知组件不含只有部分类型成立的属性。业务错误由 `ErrorNotice` 把结构化错误翻译为子节点后交给 `Toast`。
- `error` 使用 `role="alert"`，其余类型使用 `role="status"`。错误通知不自动隐藏，保留重试和关闭操作，直到用户处置。保留本地化、按钮无障碍名称与免被读屏重复播报的处理。
- 是否自动关闭由调用方决定：传入 `autoCloseMs` 才倒计时，省略即常驻，不使用 `0` 或 `Infinity` 之类需要额外约定才能读懂的哨兵值。完成统计传 3 秒；统计含失败项时改为不传，转常驻，因为失败计数正是需要被读到、也最容易被计时器抢走的部分。判断该传什么的纯函数与「是否播报扫描完成」放在同一模块，二者同属「一次扫描完成如何对外反馈」这一职责。同一份统计里的「N 个目录当前不可访问」只参与「是否播报」，不参与时长判断：它是本次扫描范围的一项事实，统计的是仍然存在、本次却列不出内容的配置目录（整条目录已不存在的情形按其中的视频都已消失清理，不进这一项），不是要用户处置的失败，因此不延长停留时间。
- 倒计时在鼠标悬停或键盘聚焦时暂停，移开后从剩余时间继续而不是重新计时；焦点在通知内部控件之间移动不解除暂停。给定时长时显示随剩余时间收缩的细线，整条指示器必须 `aria-hidden`：暴露出来的倒计时会让读屏反复播报一个用户没有要求听的计时器，这也是不用 `<progress>` 的原因之一。指示器画在哪、怎么取色见上一条。
- 非错误通知全局只保留最新一条：新的出现时先前那条被关闭，且关闭必须真正调用它的 `onClose`。通知的可见性由其所属方持有的状态决定，只做视觉隐藏会在下次渲染时把同一条重新挂出来。错误通知豁免：既不顶掉别的通知，也不被别的通知顶掉，多条错误继续堆叠。同一状态槽位的内容被替换（连续两次扫描完成）时不得走互斥路径关闭「旧通知」——该槽位的关闭回调是无条件清空的，在写入新值之后调用它会清掉刚写入的内容。这类替换以重新挂载的形式到来（开始新操作时先清空完成统计，下一次完成再写入），通知因此从完整时长重新计时；互斥只作用于不同来源的实例。
- `useNotificationHost` 将通知通过 Portal 挂到右上角 `toast toast-top toast-end` 容器，多条错误在同一容器堆叠；非错误通知的互斥协调也在宿主一侧，宿主因而最多持有 1 条非错误通知加 N 条错误通知。宿主按**位置**注册：同一位置共用一个容器，位置与宽度写在容器上，由调用方选择用哪个位置——通知用右上角（`end`），短提示用顶部居中（`center`，见「短提示」一节）。存在原生对话框时，宿主移入当前打开的对话框，关闭后回到页面根部，避免通知被顶层弹窗遮挡或无法操作。
- 通知出现、关闭、切换语言或重试不得推动标题、筛选栏和视频内容；卸载时清理宿主及观察器。
- 视频详情复制路径的结果与通知分处两地：成功是顶部居中的短提示，失败是右上角常驻的错误通知。这不是疏忽，两者的区别见「短提示」一节。

## 短提示

- 短提示用于**动作的结果用户看不见**的情形：点击已经生效，但界面上没有任何东西因此改变，不给提示这一下就像没点。全应用目前只有一处——视频详情复制路径，剪贴板不可见，因此它是唯一的调用点。结果本身看得见的动作不需要它：播放与打开所在目录由系统窗口弹出确认，收藏由心形填充与 `aria-pressed` 确认，移除索引后卡片消失，添加目录后列表项就地出现，切换主题整页变色。判断一个新动作该不该加提示，依据是它的结果可不可见，不是它有没有被点击。
- 短提示**不是通知**，不共用通知的任何部件，也不进入「非错误通知全局只保留最新一条」那条互斥：它与正在显示的完成统计可以同时在屏，各自独立。二者的区别是**要求**而不是外观——通知是要读、要处置的信息，短提示只回答「刚才那一下生效了」。同一个动作的成功与失败因此分处两地，用户对两者的义务不同，位置不同是刻意的。
- 位置是顶部水平居中（`toast-center`，不是屏幕正中央），宽度按内容收缩（容器 `max-content`，上限 `min(20rem, 90vw)`）。居中是为了离视线近，不是为了打断；因此时长只有 1 秒，也没有倒计时细线——一条 1 秒内排空的线是闪烁而不是信息。外观用**不带色修饰**的 `alert`（底色 `base-200`、文字 `base-content`），这是 daisyUI 设计好的中性配对，亮暗两主题都成立，不需要通知那套 `dark:alert-soft` 修正。部件只有一个实心对勾图标加一句话，没有关闭按钮，也没有类型词表——这类提示只有一种语气。
- 短提示必须**静默**：整块 `aria-hidden`，不使用 `role`。它没有可供读屏用户处置的内容，播报一次「已复制」也不比剪贴板本身多给任何信息。代价明确接受：这一秒内点到它，既不会有结果也不会有播报。
- 短提示**要吞掉落在它矩形内的点击**，而不是放行给被它盖住的控件——放行会让用户点中一个自己看不见的按钮。这是定位元素的默认行为，**不要为此加 `pointer-events-none`**。由此得到一条硬约束：承载它的容器宽度必须恰好等于可见内容，顶部居中容器的 `max-content` 不能省，也不能沿用通知容器那行 `w-[min(32rem,100vw)]`，否则会在提示两侧各多吞一块看不见的空白。被吞掉的那次点击不产生任何副作用，也不关闭提示。
- 入场动画要关掉：daisyUI 给 `.toast > *` 加了 0.25 秒的 `scale` 与 `opacity` 动画，对 3 秒的通知无妨，对 1 秒的短提示要吃掉四分之一的生命，用 `animate-none` 盖掉。工具类能压住 daisyUI 组件类：后者的层嵌在 `utilities` 内部，Tailwind 工具类落在更深的层。
- 停留时长由 `Hint` 自己持有（`HINT_MS`），因为它是一条与内容无关的固定规则，不像完成统计那样要按本次扫描有没有失败项分岔。状态仍由应用级 `useLibrary` 持有、由页面框架渲染，因此复制后立刻关闭详情抽屉不会把提示一并带走——它所属的是这次复制，不是弹出它的那个组件。
- 剪贴板拿到的是界面显示的那条路径，即经 `displayPath` 处理后的形式，不是索引里存的原样字符串。两者指向同一个文件，但用户要的是眼前这一条。
- 验证宿主按位置注册（短提示与通知各占一个容器、互不干扰）、静默（无 `role`、无 `data-notice-countdown`、无按钮）、1 秒后自动关闭且只关一次、`animate-none` 生效，以及短提示出现时正在显示的完成统计**不被关闭**。
- 验证页面外渲染、多错误堆叠、关闭和重试回调、对话框开启/关闭、自动关闭与悬停/聚焦暂停、倒计时指示器的动画与静默、非错误互斥与错误豁免，以及现有语言切换和未知错误回退测试。测试倒计时须使用假定时器，并在每个用例后先卸载再恢复真实定时器；仓库未开启全局注入，`afterEach` 中的顺序不能颠倒。jsdom 不执行动画，用例只能钉住细线声明的动画（时长、缓动、`fill-mode`、暂停态）以及「时间流逝时没有任何一步被写进去」；细线真的在走、悬停真的停在原处、移开真的从剩余处继续，仍须在真实引擎里验一次。
- 驱动通知必须用 `focusin`/`focusout` 与 `mouseover`/`mouseout`：React 把 `onFocus`/`onBlur` 接在原生 `focusin`/`focusout` 上，并由 `mouseover`/`mouseout` 合成 `onMouseEnter`/`onMouseLeave`，因此 `focus`、`blur`、`mouseEnter`、`mouseLeave` 四类事件不会触发任何处理函数，测试会静默通过而什么都没测到。同理，不要在假定时器启用期间使用异步等待查询。

## 下拉选择框

- 一律使用 `shared/ui/select` 的 Radix `Select`，不用原生 `<select>`：列表要用界面自己的配色画，触发器还要承载工具栏放进来的部件。代价是弹层走 Portal——这一点反而是好处：被裁剪的页面里列表照样显示得出来。
- 触发器、内容、选项、值都是 `Select` 的组合件（`SelectTrigger` / `SelectContent` / `SelectItem` / `SelectValue`），尺寸走 `size`（`default` / `sm`）。
- 带前置图标时，装饰图标设置 `aria-hidden` 与 `pointer-events-none`，触发器通过内边距留出图标位置。可访问名称设置在实际的触发器上。
- 选项列表由本库绘制，不受浏览器与系统原生菜单影响；不为模拟外观而破坏标准控件结构。

## 路由与页面组合

- `App` 负责应用级提供者、全局顶部导航及路由配置；导航下方通过 React Router 渲染 `src/pages/` 中的独立页面。页面内容由页面组件组合，不在 `App` 内按路径条件拼装。
- 视频库、收藏、最近播放、共享页面分别嵌入 `LibraryToolbar`，通过 `actions` 及筛选参数适配页面操作与筛选状态；共同行为复用 `useVideoPageView`、`VideoPageContent` 和 `PageFrame`。设置页单独组合自身内容。
- `LibraryToolbar` 就是页面的第一行：筛选控件、页面操作（`actions`）与视图模式同在一条 `flex-wrap` 行里，页面标题不再存在——哪一页在屏幕上是导航当前项说的，页面自己做什么则由 `actions` 那一组说。四个列表页因此天然在同一窗口宽度下保持筛选栏与视频数量的纵向位置一致。
- 共享的查询、扫描及事件订阅由应用级 `LibraryProvider` 持有；页面消费窄接口，不重复调用 `useLibrary` 创建订阅。页面自身的菜单和弹窗状态随页面卸载清理。
- 消费方**不直接读整个库接口**，按职责取窄接口：`useVideos`（视频集合与会话里的上次播放标记）、`useScan`（扫描状态、是否在跑、控制扫描）、`useNotices`（错误、完成播报、复制提示）、`useSpaceCommands`（建/改名/删/切空间）、`useDirectories`（目录与两个整库维护动作）、`useVideoActions`（单条视频的六个动作）、`useBusy`（是否有命令在跑）。七者都从同一个上下文取，一文件一个。`useLibrary` 是唯一认识整份接口的地方，它按职责装配七个值，而**每一片的类型声明在交付出它的那个模块里**，返回类型由这七个类型组成。方向是这里的要点：装配少给一个键、或给错一个类型，编译就失败；按字段手抄一份清单则不会，只会静默地少发一样东西。
- 替身要造的是**那一片**的键，数量就写在它自己的类型里：`useNotices` 八条、`useScan` 三条、`useBusy` 一条。测试按模块替换（`vi.mock('./useNotices')`），所以一个替身只描述这个消费方与库的关系，不涉及其余六片。**没有强制的部分**：上下文本身仍装着整份接口，任何调用方都可以绕开切片直接 `useLibraryContext()`——「不直接读整个库接口」是约定，不是类型挡住的。要挡住得把七个切片拆成七个上下文；现在不做，因为替身本来就按模块替换，拆上下文只换来这一道约束本身。
- 新增或调整路由后，验证直接访问、导航切换、对应页面操作入口和状态保留策略；未知路径明确回到视频库。

## 测试与检查

前端采用 Vitest 与 React Testing Library，后端采用 Rust 标准测试框架，尚未设置覆盖率门槛。实现功能时添加与风险匹配的测试，并记录运行方式。前端测试使用 `*.test.ts` 或 `*.test.tsx` 命名，后端采用 Rust 标准测试模块。

依据设计文档覆盖关键行为、边界条件和异常路径；使用临时目录和小型测试样本。测试应验证对外行为，避免仅复刻实现细节。

**起真服务或本地 HTTP 服务的用例，第一件事是拿 `crate::ports::the_machine_ports()` 那把锁**：`cargo test` 一个二进制里的用例是并行跑的，而一台机器的端口是它们共用的同一件东西——两个同时向系统要空闲端口的用例可能拿到同一个号，一个刚放开端口的用例可能眼看着别人的服务占上去。这把锁是粗粒度的（一个测试范围一把锁，而不是一段端口一把），理由与它挡住的三种失败写在 `ports.rs` 里；`update` 的下载用例曾经没拿它，CI 上就出现「服务结束之后端口仍然有人应答」的假红。

测试要的是一个库而不是一个目录时，用 `fixture.library()`（`repository/fixture.rs`）：它一处决定数据库文件名与初始空间，返回的 `Library` 解构出 `repository` 与 `space`。此前每个用例各写三行把它拼出来，六十份里没有一份读出多余的信息。测试仍自己拼数据库名的只有「重开同一个库」那类用例，那里两个名字必须一致，写在同一处才看得出来。

组件测试的 provider 树逐字写在各文件里（三处嵌套各不相同），**不抽 `renderWithProviders`**：树本身只有四行，真正重复的是各文件各自的 i18n 资源、api 替身与 `showModal` 桩，而这些恰好随「这个文件在验什么」变化，抽出来只会多一层带参数的间接。

例外是替身本身跨文件一字不差的时候：共享页的两个测试文件（页面与 provider 生命周期）挂的是同一棵树、问的是同一个后台，共用的替身、后台应答与起手状态收在 `frontend/src/test/sharePage.tsx`——逐字重复两遍只会变成两份要一起改的东西。render 帮手仍然不抽，两棵树各写各的。

页面上的内容块**按内容切分并只吃自己那几个事实**（`features/share/` 下的 `ConnectionDetails`、`PasswordDetails`、`DeviceList`、`ListWarnings` 是这一形状的现有例子）：一块的入参是它要显示的值与「按下复制该做什么」的回调，不是整个共享状态。这样一块的测试只挂 i18n 一棵树，不必站起来状态、库切片与窗口；块自己的规则（地址怎么拼、密码什么时候显示、设备的时间怎么走、哪条提示什么时候出现）因此能在它旁边单独验。页面留下的只有两件事——`共享清单` 是什么（没有对应命令，是记录上的一枚标记加一次过滤），以及一次失败的复制怎么报（两个块都会复制，而提示是页面的）。撞上行数上限时先看能不能这样切：上一次共享页是因为行数上限切出去的（`SharePassword.test.tsx`），切完又把同一块脚手架抄了一遍，现在那个文件不存在了。

数据夹具（`frontend/src/test/fixtures.ts` 的 `video`、`idleScan`、`address`、`device`）与替身分开放：前者是纯数据、跟着后端结构体的类型走，谁能用谁拿；后者是 `vi` 的替身，只在需要挂起整棵树的地方出现。

建立开发工具链时，应加入静态导入检查、动态加载禁用检查和文件行数检查，并纳入持续集成。提交前运行已有的相关检查；尚未配置或无法执行的检查应如实说明。

## 日志与故障排查

运行时诊断同时写 stdout 与 `<应用数据目录>/enjoy.log`（Windows 上是 `%APPDATA%\com.enjoy.launcher\enjoy.log`，与 `enjoy.db` 同级）。日志由 `src-tauri/src/logging.rs` 打开：超过 4 MiB 时轮转为同目录的 `enjoy.log.1`，只保留一代；打不开文件不阻止启动，退回只写 stdout。`RUST_LOG` 仍可覆盖级别，默认 `info`。

界面上的错误提示只显示业务文案与一个排查编号（形如 `err_1756000000000_2`），编号背后的原文只在这份日志里——`AppError::new` 会写一行 `tracing::error!`，带 `error_id`、`code` 与 `diagnostic`。拿编号在这份日志里搜，就能看到真实原因。发布版是 Windows GUI 程序、没有控制台，这个文件因此是唯一能看到它的地方。

新增失败路径时确认它能被这个编号查到：错误走 `AppError`，把底层原因作为第二个参数传进去（`AppError::new(code, source)` 接受任何 `Display`），不要只写一个码。

## 自动检查

`npm run check` 验证文件行数、JavaScript/TypeScript 导入位置、动态加载禁用、命令名一致性、窗口权限授予、接缝两侧的形状、翻译键/插值参数/文案标点、Rust 错误翻译覆盖、版本号一致性检查、设计 token 与两份设计稿一致，以及前端格式。

命令名检查（[check-commands.mjs](../scripts/check-commands.mjs)）把三处对起来：`frontend/src` 里 `invoke('名字')` 的调用点、后端 `generate_handler!` 注册的清单、验收夹具回答的 `case` 标签。前两者要求**双向相等**——一条注册了却没人调用的命令只能从 IPC 到达，没有合法用途，报出来是要删的；夹具只要求**子集**，它是为走查需要而存在的，不是后端的全量替身。`invoke()` 的第一个参数必须是字面量，用变量绕开检查会被单独报错，否则检查的覆盖面就有了缺口。只比名字不比参数：参数形状由两侧的类型各自承担，在这里重实现 Tauri 的 camelCase 转换会是假红的来源。这三处都是裸字符串，改错了照样编译、照样构建、照样通过全部测试（调用点都在 `libraryApi` 一层被 mock 掉），只在运行时炸——理由与 `check-version.mjs` 同源。

窗口权限检查（[check-permissions.mjs](../scripts/check-permissions.mjs)）把「界面调了什么」与「能力文件授了什么」对起来，只读 `frontend/src/shared/api.ts` 一处——`check-commands.mjs` 已经保证只有它能把 Tauri 当值导入，因此读它一处就是读全部。每条调用要什么权限是 Tauri 自己的事实，写在脚本的 `needs` 表里；授了什么则读 `src-tauri/capabilities/*.json` 原文。**表里没有的调用是失败，不是跳过**：一个读不懂的写法同样报错，否则这张表就不完整。`src-tauri/gen/` 里有构建时生成的权限清单时，授权会按它展开——一个权限不再只比对「名字出现过」，而是比对它所在的集合真正携带了它；该目录不入库，因此没构建过的机器上这半边跳过并写明跳过。

这张表盖不满的部分要说清楚：**它只看得到这一层自己的调用**。Tauri 的 JS 包内部还会发 IPC——`@tauri-apps/api/window` 的 `onCloseRequested` 在没有 `preventDefault()` 时自己调 `destroy()` 就是一条，而它写在 `node_modules` 里，这里读不到。这张表现在**一项也不被用到**（界面不再碰自己的窗口），表项保留下来是为了「将来有人伸手去碰时该要什么」这件事仍写在能读到的地方，而不是让检查只覆盖当下在用的调用。

接缝形状检查（[check-seam.mjs](../scripts/check-seam.mjs)）把跨接缝的每一份形状的两处声明对起来：后端那个 `#[derive(Serialize)]` 的结构体（按它自己的 `rename_all`、逐字段 `rename` 与 `skip` 算出真正发到线上的字段名）与 `frontend/src/shared/api.ts` 里同名的接口（声明了哪些成员）。两个方向都要求相等——后端发了而界面不认识，是用户永远看不到的事实；界面读了而后端从不发，是那个时刻一定是 `undefined`。**每个导出的接口都必须在表里**，新增一份形状却忘了登记是失败而不是跳过；`rename_all` 写了一个这条检查不认识的取值也是失败，因为那样比对的约定本身就是错的。比的是名字不是类型：`Option<i64>` 与 `number | null` 之间的转换若在这里重实现一遍，换来的假红比它挡住的错误更贵。

翻译检查（[check-translations.mjs](../scripts/check-translations.mjs)）管三件事：两种语言的键集合逐字相同、同一键的插值参数相同、以及**界面文字不以句号收尾**（一段散文例外，按名字列在脚本里）。前两条是「一处漏改另一处照旧」，第三条是一条文案约定——它落在哪种检查里是有意的：文件与循环都已经在读全部文案，为它单开一个脚本只会让同一批文件被读两遍。这条规则的红绿都实测过：加一个句号立刻红，去掉立刻绿。

设计 token 检查（[check-tokens.mjs](../scripts/check-tokens.mjs)）把 `frontend/src/style.css` 里的取值与两份设计稿（`prototype-drawing/vermilion_studio` 亮、`crimson_cinema` 暗）对起来：工单点名的 `--background`／`--card`／`--primary`／`--destructive`／`--ring` 必须等于稿子里的对应色，`--success`／`--warning`／`--info` 三槽与各自的前景色在亮暗都有，暗色块确实翻转了各面与文字 token，聚焦环等于主题主色，圆角只有一处取值，并且 `@plugin`、`--page-scroll-lock`、`drawer-side`、`--video-card-shadow` 这些 daisyUI 遗留都不在。**两份设计稿自身互相矛盾**：前置 front-matter 块给的是 Material 3 的浅色调主色，正文末尾的编译块才是按钮上那个红——检查以编译块为准。没有这份检查，一个改错十六进制的 token 照样能构建、能渲染、能通过全部测试，只在视觉走查时才看得出来。

`cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings` 执行严格 Rust 静态检查。

上述检查已在本机通过。`.github/workflows/check.yml` 配置 macOS 持续集成，执行依赖安装、前端检查与构建、Rust 格式、测试及 Clippy；远端运行结果须以实际流水线记录为准。

前端测试使用 Vitest、jsdom 和 React Testing Library。`npm test` 执行组件交互测试，覆盖错误提示切换语言、未知错误回退、单击卡片打开详情而不播放、卡片键盘手势与按钮操作互不串扰，以及播放按钮只随媒体任务运行状态禁用；该命令已加入持续集成。`shared/useCommand.test.ts` 覆盖「一次命令跑一次」的四条规则：跑的时候 busy、跑完不论成败都不 busy；失败与它被尝试时的值一起留下；失败被替换或主动关闭后不再存在；给了 `onFailure` 就交出去、自己不留——以及 action 在失败处停下，await 之后那一步不执行。组件测试不替代真实 Tauri 桌面端到端验证。


## 发布

自动更新仅面向 Windows 发布。发布由标签触发：改 `package.json`、`tauri.conf.json` 和 `Cargo.toml` 三处版本号（`npm run check` 强制它们一致），提交后打 `vX.Y.Z` 标签并推送。`.github/workflows/release.yml` 在 `windows-latest` 上构建 NSIS 安装包、签名并生成 `latest.json`，创建为**草稿** release；核对产物后再手动发布，`releases/latest` 从那时起才指向它。因此首个版本必须手动安装，自动更新自第二个版本起生效。

构建机需要两个仓库 secret：`TAURI_SIGNING_PRIVATE_KEY` 放私钥内容，`TAURI_SIGNING_PRIVATE_KEY_PASSWORD` 放它的口令。私钥只生成一次——`npm exec tauri signer generate -- -w ~/.tauri/enjoy.key`——公钥内容写入主配置的 `plugins.updater.pubkey`。**私钥丢失后，已发布的客户端永远无法再收到更新**：它们带着旧公钥，签不出能被接受的新包。私钥须离线备份并排除在版本库之外。

内置媒体工具不入库，流水线从仓库 `ffmpeg-tools` 标签的发布附件取 `ffmpeg.exe` 与 `ffprobe.exe`。该标签的附件需先手工上传一次，之后每次发布复用同一对，发布产物因此可复现。

## 独立网页验收

运行 `npm run dev -- --host 127.0.0.1`，在浏览器打开 `http://127.0.0.1:5173/acceptance/web-acceptance.html`。此入口使用同一 React 页面、Tauri 官方模拟通信及固定测试数据，适合页面框架、弹层和错误文案验收；不连接真实数据库，也不替代 Rust 或系统集成测试。生产构建仍仅使用 `frontend/index.html`。

该入口会把夹具里那 36 条视频渲染进真实网格，因此依赖真实数据的走查（筛选、排序、卡片与详情）也可以在这里做。此前记录的「视频列表不加载」（#23）在 2026-09-26 已不成立，但恢复原因未追溯——打开后列表若是空的、停在「正在读取视频库…」，那就是老毛病回来了，此时它又不能作为验证手段。它走桩通信，验的是界面行为，后端与系统集成仍由 Rust 测试和桌面端承担。

可在浏览器控制台执行 `window.enjoyAcceptance.setScan('processing')`、`setScan('paused')` 或 `setScan('cancelled')`（后两者同样通过 `window.enjoyAcceptance` 调用），发送对应扫描状态。`window.enjoyAcceptance.setUpdate('available'|'ready'|'none'|'unsupported')` 覆盖检查结果能渲染的四种形状，须先点一次「检查更新」。

更新的下载流程也可以在这里走：夹具的 `install_update` 把命令的 promise 挂住并推一条进度，直到 `control_update` 按暂停或取消把它兑现——真实下载只在结束时作答，不这样做的话，一段只在传输运行时才出现的暂停与取消按钮根本走不到。因此点「下载」会停在进度上，此时可按「暂停下载」看到暂停态与「继续下载」，按「取消下载」则清空。第二次「下载」开的是新的一次传输而不是接着上一次的断点，这一点与后端不同。

点击播放固定返回系统打开失败业务错误，以验证本地化提示和重试入口。当前夹具只支持验收所需命令（[check-commands.mjs](../scripts/check-commands.mjs) 会把「未进夹具」的命令列出来，不视为错误）。走到夹具没有答案的命令时，应用照旧报一条通知，但**页面底部会同时出现一条横幅、点名是哪条命令**——横幅说的是「夹具没有实现它」，不是「应用失败了」。这条区分是给走查者的：把夹具的缺口读成应用的缺陷是这条入口最贵的一种误判，issue #46 就是这么来的（夹具的缩略图全是空，于是卡片几何那条分支根本走不到）。扫描的暂停、继续与取消已经进了夹具，它们只改相位，不重实现后端的槽位与闸门语义。

## 视频列表布局与渲染

修改视频库、收藏、最近播放、共享的布局或渲染逻辑时，必须遵守以下约束。列表的条数、筛选、排序与分页见[后端分页决策](adr/0016-后端分页承担筛选排序与分页.md)，三态视图见[列表三态视图决策](adr/0017-列表三态视图与废除虚拟滚动.md)，滚动条的标准行为及兼容性依据参见[滚动条占位资料核对](滚动条占位-资料核对.md)。

### 滚动区域边界

- 应用采用固定视口高度，父级通过 `min-height: 0` 等约束将剩余高度交给内容区，页面根节点不产生纵向滚动条。
- 全局导航、页面操作按钮、筛选工具栏及视频数量放在滚动容器外。仅下方视频列表滚动，视频数量不得随内容滚出视野。
- 设置页内容和空状态使用各自的滚动容器。局部滚动不得带动整个窗口或形成重复的纵向滚动区域。

### 列表渲染

- 列表一次只取一页。筛选、排序与分页都由后端执行（[ADR 0016](adr/0016-后端分页承担筛选排序与分页.md)），每页 24 条（`features/library/listing.ts` 的 `PAGE_SIZE`），页面不持有全量数据，也不在本地筛选。
- **不引入虚拟滚动**。一页只有 24 条，浏览器自己排布即可。`@tanstack/react-virtual` 及其估算行高、缓冲行与配套几何纪律已整体废除（[ADR 0017](adr/0017-列表三态视图与废除虚拟滚动.md)），依赖也已从 `package.json` 移除，不要再为「挂载节点数」做优化。
- 三态视图（网格 / 列表 / 表格）由 `features/library/VideoBoard.tsx` 按 `viewMode` 分派，形态词表与默认值在 `features/library/listing.ts`（`ViewMode`、`DEFAULT_VIEW_MODE`），按页面记忆在 `features/library/libraryView.ts` 的 `viewModes`。单个视频卡片统一复用 [VideoCard](../frontend/src/features/library/VideoCard.tsx)，页面不复制卡片布局。
- 视频卡片的盒子集中在 [videoCardBox](../frontend/src/features/library/videoCardBox.ts)：只剩图片区的比例类名（`pictureClass`）与起始边悬停余量（`hoverRoom`、`hoverRoomStyle`）这些浏览器算不出来的量；行高估算随虚拟滚动一并删除。
- 视频数据读取由应用级的库接口统一执行（页面经 `useVideos`，`useVideoPageView` 在其上组装查询），页面通过 `useVideoPageView` 复用筛选、排序、视图模式与滚动重置标识，不重复维护请求状态。
- 切换页面、筛选条件或排序时重置内容滚动位置。滚动时关闭右键菜单；播放、收藏、详情及键盘等交互在三态下都须有效。缩略图随列表项挂载，保留延迟加载。
- 网格按实际可用内容宽度分列：`VideoBoard` 的网格用 `repeat(auto-fill, minmax(min(240px,100%),1fr))`，列数由浏览器按**网格自身的宽度**算定——页面内边距与滚动条预留都已从那个宽度里扣掉，因此不直接将窗口宽度或未扣除内边距的 `clientWidth` 用作内容宽度。240 像素是下限而非定宽，列宽吃掉余量；用 `auto-fill` 而非 `auto-fit`，否则末页不满一行时卡片会被拉宽、尺寸与满页不一致；`min(…,100%)` 是窗口可被拖到 240 像素以内的护栏。内容列不再有宽度上限（`PageFrame` 的 `max-w-7xl` 已去掉），窗口变宽即继续加列。取舍与各尺寸实测见 [ADR 0019](adr/0019-视频网格按内容宽度分列.md)。
- 表格视图的文件名列有最小宽度（`VideoTable.tsx` 的 `min-w-[14rem]`）。八列里只有它与路径列会截断，其余是 `whitespace-nowrap`、按内容取宽；不给它下限时浏览器把它压到最小内容宽度（本机实测仅 90 像素，比时长、编码、大小各列都窄），而余量被别的列按比例吃掉。窗口窄于表格的最小宽度时由 `Table` 外层的 `overflow-x-auto` 横向滚动；拖拽调列宽**不做**，没有可复用的开关（`shared/ui/table` 是纯样式化的 `<table>`，`radix-ui` 不含 resizable table）。

## 滚动条占位与兼容处理

- 视频内容、空状态及设置页统一复用 [ScrollViewport](../frontend/src/shared/ScrollViewport.tsx)。将 `overflow` 与 `scrollbar-gutter: stable` 设置在实际滚动元素上；只给外层或 `body` 设置该属性不能替代局部容器配置。
- `stable` 为传统滚动条预留原生槽，但不会为 macOS 覆盖式滚动条占位，`both-edges` 也不解决覆盖式占位。不能仅凭属性声明或 `CSS.supports` 返回成功判定问题解决。
- 共享样式位于 [style.css](../frontend/src/style.css)。尾侧安全区域以 20 像素为目标，补偿内边距按 `max(0px, 20px - 原生槽宽)` 计算。原生槽宽为容器 `offsetWidth - clientWidth - 左右边框宽度`，由 `ResizeObserver` 观察尺寸变化并更新。
- 传统模式使用原生槽加差额补偿，覆盖模式补足安全留白，避免滚动条展开遮挡内容。原生槽超过 20 像素时保留完整系统槽宽，补偿为零；20 像素是应用布局策略，不是所有平台的原生滚动条宽度。
- 占位规则由共享容器统一维护，各页面不另加重复的固定右内边距。观察器卸载时必须清理，补偿更新不得造成持续的尺寸观察循环。
- 不支持 `scrollbar-gutter` 的引擎通过 `@supports not` 回退为 `overflow-y: scroll`。该回退仅解决传统滚动条槽，覆盖式模式仍需安全留白。
- 应用不得通过修改用户系统滚动条偏好解决布局问题。

## 滚动功能验证

修改上述逻辑后，运行 `npm run build`、`npm run check` 和 `npm test`。后端筛选、排序与分页由 `repository/listing_tests.rs` 覆盖，前端三态视图、视图模式记忆与分页控件由 `features/library/VideoBoard.test.tsx`、`features/library/libraryView.test.ts` 与 `shared/ui/pagination.test.tsx` 覆盖。模拟布局测试不替代真实窗口布局验证。

真实窗口验收须覆盖：空内容与溢出内容切换、不同视频页面切换、窗口缩放、长文件名、传统与覆盖式滚动条、鼠标悬停展开。记录容器和内容的实际宽度，检查固定区域不移动、内容不被遮挡、卡片无重叠及异常空白、根节点不产生额外滚动。无法完成的场景须明确说明。

macOS 下先启动 `npm run dev`，再分别执行以下命令。脚本用原生 `WKWebView` 加载实际网页验收入口，断言原生槽与补偿间距之和为 20 像素，并输出内容宽度。滚动条偏好仅通过测试进程启动参数传入，不修改用户系统设置。

- `swift scripts/check-scrollbar.swift http://127.0.0.1:5173/acceptance/web-acceptance.html -AppleShowScrollBars Always`
- `swift scripts/check-scrollbar.swift http://127.0.0.1:5173/acceptance/web-acceptance.html -AppleShowScrollBars WhenScrolling`

既有本机验证中，两种模式均测得内容宽度 1,058 像素；传统模式槽宽 17 像素、补偿 3 像素，覆盖模式槽宽 0 像素、补偿 20 像素。该数值是当时窗口尺寸下的证据，不是所有窗口的固定宽度要求。脚本的 20 像素断言适用于原生槽不超过 20 像素的环境；更宽的系统槽按原生宽度验收。该检查不替代物理鼠标接入和悬停展开的人工检查。**内容宽度那一项此后不再是一个固定数**：内容列的宽度上限已去掉（[ADR 0019](adr/0019-视频网格按内容宽度分列.md)），内容宽度随窗口变化，原记录的 1,058 像素正是那道上限留下的痕迹。该脚本真正验证的是原生槽与补偿之和为 20 像素，这一条与窗口宽度无关，未受本次改动影响。

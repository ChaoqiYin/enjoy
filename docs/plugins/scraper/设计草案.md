# 刮削插件设计草案（草案）

> 本草案聚焦领域与行为，目的是达成共享理解。首版不写实现代码；细节待第三轮进一步敲定。

## 概述

「刮削」插件是第一个真实的运行体插件（Rust→wasm32），功能是对影片进行元数据与封面刮削。因刮削是异步网络请求，宿主需维护**任务队列**管理。

## 术语（参照 CONTEXT.md）

- 刮削、刮削任务、任务队列、刮削源、刮削结果、自动刮削、刮削标记（见 CONTEXT.md）。
- 宿主-运行体接口遵循现有插件框架约定（ADR 0043/0044）。

## 挂载点选用（首版）

首版注册以下挂载点：

1. `video.actions`：手动单条触发「刮削」。符合现有语义，复用该挂载点。
2. `plugin.settings`：插件自身配置（站点列表、单任务内重试上限等）。
3. `scan.completed`：接收扫描完成通知，由宿主判断是否自动入队。

暂缓 `video.panel`：纯运行体插件首版不强行配界面，结果已通过 `video.fields` 持久呈现。

## 触发方式

- **手动**：用户在视频右键菜单触发 `video.actions`。**不受**「刮削标记」约束（允许强制重刮）。
- **自动**：`scan.completed` 通知到来时，宿主对媒体处理完成的视频做资格判定（见下文）。由**应用级开关**控制，默认关闭。

## 任务队列模型

- **所有权**：任务队列由**宿主（Rust）**维护。每插件一条串行队列，插件间并行。
- **全局并发**：宿主全局同时进行的 `video.actions` 调用上限首版 **2**（仅统计进行中的 `video.actions` 调用）。
- **状态机**：`pending → running → completed | failed | cancelled`。
- **调度策略**：FIFO（无优先级）。
- **重试**：重试策略由**运行体（WASM）**决定，宿主不维护重试计数。运行体在一次任务执行中自行处理重试循环。
- **去重**：按 `(插件id, video.id)` 去重。同一视频在 `pending` 或 `running` 时**拒绝**再次入队；`completed`、`failed`、`cancelled` 状态允许再次入队。
- **持久化**：首版**仅内存**。重启后 `pending/running` 丢弃；已落库的刮削结果与标记不丢。自动入队在下次 `scan.completed` 时补足。

## 宿主-运行体接口（最小约定）

- **触发方式**：通过复用 `video.actions` 把任务交给运行体。宿主为该动作类调用设置**单独预算 120 秒**（默认 5 秒不适用），常量建议为 `SCRAPER_ACTION_DEADLINE_SECS = 120`，仅在 `video.actions` 派发时使用。`VideoActionsResult` 形状为：`{ outcome: "done"|"failed"|"cancelled", error?: string }`。
- **超时与取消**：宿主负责计时和取消。取消走中断（epoch trap），不强制要求运行体定期检查取消标志。
- **结果回流**：任务 `done` 后，宿主**再问一次**该插件的 `video.fields`（带当前空间、视频上下文及链参数），按「依次问、取第一个非空」合并并由内核写入库。action 本身**不**直接携带字段数据。**写入标记时机**：等宿主「再问 video.fields」拿到返回并确认结果已写入 `video_fields` 表后，再写入 `scraper.scrapedAt`。
- **封面**：若 `video.fields` 返回 `cover` 为 http(s) 地址，内核沿用现有封面下载逻辑写入 `$APPDATA/covers/` 并替换为本地路径。

## 自动刮削资格与刮削标记

- **应用级开关**：`扫描后自动刮削`（默认关闭），归宿主/应用设置页「刮削」小节。
- **判定条件**：`scan.completed` 收到后，对媒体处理完成的视频检查 `video_fields` 是否存在保留键 `scraper.scrapedAt`。若无，或其记录的**文件身份**（`normPath`、`size`、`mtime`，身份键形式 `${size}:${mtime}:${normPath}`）与当前身份不符 → 自动入队。
- **标记写入**：任务成功且结果已写入后，宿主顺带写入 `scraper.scrapedAt`。值格式为结构化 JSON：`{"vid": video.id, "path": normPath, "size": video.size, "mtime": video.modified_at, "ts": now_unix_seconds}`（UTC 秒级）。标记不进白名单，前端隐藏。
- **例外**：手动触发不检查标记；失败/取消不写标记。

## 字段映射

首版最小白名单（具体键名）：

- `cover`（封面，最终路径由内核处理）
- `title`
- `originalTitle`
- `plot`
- `director`
- `actors`
- `genre`
- `studio`
- `premiereDate`
- `series`

多值键（`actors`、`genre`）以 **JSON 字符串数组** 格式存入 `video_fields`（例：`["张三","李四"]`）。前端尝试 `JSON.parse`，解析失败时回退单值显示。

白名单外的键一律以 `<插件id>.<原始键名>` 前缀化存储、原样显示。保留键 `scraper.*` 前端隐藏不显示。

## 设置项结构与校验

**宿主/应用级（设置页「刮削」小节）：**

1. `自动刮削（扫描后）` 开关，默认 `false`
2. `任务超时（秒）`，默认 `120`

**plugin.settings（插件自身）：**

1. `sites`（textarea），一行一个刮削源站点。校验：过滤空行和首尾空格，至少要有 1 行非空，否则保存时报错「至少要配置一个刮削源」。
2. `retryCap`（text），单任务内重试上限（运行体自律）。校验：必须是 1-10 的整数，默认 3；超出范围报错。

## 失败通知与进度

v1 仅做：

- **手动触发失败**：一次错误通知（沿用现有通知体系）。
- **扫描后自动批量结束**：汇总通知（成功 n / 失败 m，失败明细写入日志）。

不做进行中状态行，不预留 `video.panel` 事件。刮削结果通过 `video.fields` 已可直接呈现。

## 验收要点

- 手动触发可强制重刮，不受标记限制。
- 文件身份变化（normPath/size/mtime 任一变化）后自动会重新刮削。
- 超时/取消不写新字段、不更新标记。
- 标记写入时机为「video.fields 结果已写入后」。
- 封面最终落入 `$APPDATA/covers/`。
- 白名单外键正确前缀化，`scraper.*` 不在详情中显示。
- 全局同时进行的 `video.actions` 调用上限 2，仅统计进行中的 `video.actions` 调用。

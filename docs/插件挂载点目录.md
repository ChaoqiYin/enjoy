# 插件挂载点目录

**这份文件是生成的，不要手改。** 事实来源是 `shared/plugins/mount-points.json`，改完跑 `npm run generate:plugins`；`npm run check` 会拦住「改了目录却忘了重新生成」。

挂载点是**封闭的六处**，插件只能往它们上面加料——不能删、不能改、不能拦。为什么是这六处、以及每一处归哪一半，见 [ADR 0045](adr/0045-挂载点分两半且是封闭集.md)。

| 挂载点 | 类别 | 形态 | 归属 | 空间 | 冲突规则 | 占用者 |
| --- | --- | --- | --- | --- | --- | --- |
| `app.page` | 界面类 | `list` | 插件界面 | 整窗 | 叠加 | 无 |
| `video.panel` | 界面类 | `list` | 插件界面 | 一条视频 | 叠加 | 无 |
| `video.fields` | 数据类 | `chain` | 运行体 | 一条视频 | 依次问、取第一个非空 | 无 |
| `plugin.settings` | 数据类 | `list` | 运行体 | 插件自己 | 叠加 | 无 |
| `scan.completed` | 流程类 | `list` | 运行体 | 一次扫描 | 叠加 | 无 |
| `video.actions` | 动作类 | `list` | 运行体 | 一条视频 | 叠加 | 无 |

- **类别**：界面类（`interface`）、数据类（`data`）、流程类（`flow`）、动作类（`action`）——插件加的是界面、数据、流程钩子还是一条动作。
- **形态**：`list` 是每个插件的贡献各自出现，`chain` 是按插件顺序依次问、把答案合并成一份。
- **归属**：这一处归插件的哪一半——`interface` 是插件界面，`body` 是运行体。动作类与流程类必归运行体，否则没有插件界面的插件永远触发不了自己。
- **空间**：这一处挂在哪里，也就决定了它跟着哪个空间走。
- **冲突规则**：`overlay` 是每个插件的贡献都出现，顺序由用户可调的插件顺序决定；`first-non-empty` 是按插件顺序依次问、取第一个非空的结果，因此后一个插件是补位而不是覆盖。
- **参数**：每一处都带本次调用所在的**空间**，链式那一处还带链上已经问到的字段值**及其来源插件**——后一个插件据此补位，不必重复劳动。字段的来源只在参数这一侧出现：结果是插件交回来的数据，来源由内核写库时补上。
- **占用者**：声明并占用这一处的插件 id（声明即认领）。空表示目前无人声明。

## 每一处

### `app.page`

插件往顶部导航加一个自己的页面，做一件与视频库无关的事

- 类别：界面类（`interface`）
- 形态：`list`（叠加）
- 归属：插件界面（`interface`）
- 空间：整窗（`app`）
- 冲突规则：`overlay`（叠加）
- 交给插件的参数：`space: SpaceRef`
- 插件交回来的结果：无

### `video.panel`

插件往视频详情面板里加一块自己的区域，查看某条视频时能看到它算出来的东西

- 类别：界面类（`interface`）
- 形态：`list`（叠加）
- 归属：插件界面（`interface`）
- 空间：一条视频（`video`）
- 冲突规则：`overlay`（叠加）
- 交给插件的参数：`space: SpaceRef`、`video: VideoRef`
- 插件交回来的结果：无

### `video.fields`

内核问插件要这条视频的具名字段。两个插件提供同一个字段时依次问、取第一个非空，因此后一个插件是补位而不是覆盖。参数带上链上已经问到的字段值及其来源插件，据此补位而不必重复劳动

- 类别：数据类（`data`）
- 形态：`chain`（串问）
- 归属：运行体（`body`）
- 空间：一条视频（`video`）
- 冲突规则：`first-non-empty`（依次问、取第一个非空）
- 交给插件的参数：`space: SpaceRef`、`video: VideoRef`、`fields: SourcedFieldValue[]`
- 插件交回来的结果：`fields: FieldValue[]`

### `plugin.settings`

内核问插件「用户必须填什么」，然后自己渲染、校验、保存；用户填好的值随每一次提问交给插件，纯运行体的插件因此也能让用户填东西

- 类别：数据类（`data`）
- 形态：`list`（叠加）
- 归属：运行体（`body`）
- 空间：插件自己（`plugin`）
- 冲突规则：`overlay`（叠加）
- 交给插件的参数：`space: SpaceRef`、`values: SettingValue[]`
- 插件交回来的结果：`fields: SettingField[]`

### `scan.completed`

一次扫描完成，内核把刚入库的视频交给插件。这是通知，插件此刻要做的事落在它自己的数据目录里

- 类别：流程类（`flow`）
- 形态：`list`（叠加）
- 归属：运行体（`body`）
- 空间：一次扫描（`scan`）
- 冲突规则：`overlay`（叠加）
- 交给插件的参数：`space: SpaceRef`、`videos: VideoRef[]`
- 插件交回来的结果：无

### `video.actions`

插件往视频的右键菜单和详情里加一个自己的动作。归运行体是必须的：没有插件界面的插件只有这一条路能触发自己

- 类别：动作类（`action`）
- 形态：`list`（叠加）
- 归属：运行体（`body`）
- 空间：一条视频（`video`）
- 冲突规则：`overlay`（叠加）
- 交给插件的参数：`space: SpaceRef`、`video: VideoRef`
- 插件交回来的结果：无

## 参数形状

这些形状两侧各有一份类型，都由本目录生成。

### `SpaceRef`

本次调用所在的空间。插件自己的数据目录是全局的，但它看到的数据始终属于某个空间

| 成员 | 类型 | 说明 |
| --- | --- | --- |
| `id` | `number` | 空间 id；内核命令一律显式带它 |

### `VideoRef`

本次调用的视频，也是插件能看到的关于它的全部

| 成员 | 类型 | 说明 |
| --- | --- | --- |
| `id` | `number` | 视频在主库里的 id |
| `path` | `string` | 视频文件的绝对路径 |

### `FieldValue`

一条具名字段的值，插件交回来的那一侧。内核写库时补上来源插件，插件自报的身份不作数，因此这个形状不带来源

| 成员 | 类型 | 说明 |
| --- | --- | --- |
| `key` | `string` | 字段名，比如 cover |
| `value` | `string` | 字段值；封面是一个路径，图片由内核写进 covers/ |

### `SourcedFieldValue`

链上已经问到的字段值，带上是哪个插件给的。与结果那一侧的 FieldValue 是两个形状：来源只有内核说得准，因此只在这一侧出现

| 成员 | 类型 | 说明 |
| --- | --- | --- |
| `key` | `string` | 字段名 |
| `value` | `string` | 字段值 |
| `sourcePlugin` | `string` | 这条值由哪个插件给出 |

### `SettingField`

内核替插件画的一个设置项，插件只声明它要什么，不画控件

| 成员 | 类型 | 说明 |
| --- | --- | --- |
| `key` | `string` | 设置项的名字 |
| `kind` | `SettingFieldKind` | 要哪一种控件 |
| `label` | `string` | 显示给用户的标题 |
| `required` | `boolean` | 用户必须填才能用这个插件 |

### `SettingValue`

用户填好的一项设置，内核把它交回给要它的那个插件。值一律是字符串，不管那一项当时是哪种控件：值是什么意思只有插件说得清，内核只负责画那四种控件

| 成员 | 类型 | 说明 |
| --- | --- | --- |
| `key` | `string` | 设置项的名字，与 SettingField.key 是同一个 |
| `value` | `string` | 用户填的值 |

### `SettingFieldKind`

内核画得出的四种设置项

`text`、`textarea`、`toggle`、`directory`

## 字段键封闭集

插件在 `video.fields` 上能交回的字段键是**封闭的十三个**，事实来源同样是 `shared/plugins/mount-points.json` 的 `fieldKeys`，本文件这一节也由它生成。内核在写库前只认这十三个：**集合外的键被丢弃并记一行日志，不会进 `video_fields`**，交一个集合外的键等于什么都没说。

`cover`、`title`、`number`、`actors`、`genres`、`studio`、`label`、`series`、`director`、`releaseDate`、`duration`、`rating`、`plot`

- **值一律是字符串**；演员、类型这类多值用 `, ` 连接，v1 不拆成标签。
- **`cover` 是内核唯一认识的键**：值是一个网址，内核把它下载成路径再写进库（`plugins/cover.rs`）。
- **界面按 `field.<键>` 画标签**，翻译在 `shared/locales/{zh-CN,en}/common.json` 的 `field.*` 一组里；那一组缺一个键时界面退回显示键名本身。
